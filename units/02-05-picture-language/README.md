## 1. 问题：不要在每次组合时重写整幅图

若图像只是绝对坐标数组，把两幅图并排放置需要遍历修改每个点；再旋转整体，还得再改一次。SICP 改变接口：**painter 不是已经画完的图片，而是一个接受 frame 的过程**。它知道怎样把自己的图画进那个框架。

教材 painter 调用 `draw-line` 产生绘图效果。本单元把这一层改为返回同一批绘图命令：

```text
painter : frame → 按顺序排列的绝对坐标线段列表
segment : 起点向量 . 终点向量
```

这是对教材**线段 painter 子语言**的无头解释：把返回的每条 `(start . end)` 交给一个画线过程，就会在指定 frame 中画出同一批线。组合时用 `append` 合并命令，而不是用副作用在屏幕上连续画线。我们保留了 painter 的过程接口、仿射映射、递归组合和绘制顺序；不实现照片 painter、像素颜色、填充或 GUI。返回数据不是拿线段数量假装图形实现，端点确实经过全部变换。

## 2. frame 是原点加两条边，不一定是矩形

```text
F = (O, E1, E2)
M_F(x,y) = O + x E1 + y E2

O+E2 ───────── O+E1+E2
  ╲                 ╲
   O ─────────────── O+E1
```

局部图形用单位正方形坐标 `[0,1]×[0,1]`，y 向上。`E1,E2` 是位移向量，不是边的绝对终点。相对屏幕 y 向下的坐标系统，若未来接显示后端，需要在最终边界处理方向，不能悄悄颠倒本单元 `below` 的含义。

例：`O=(2,3)`、`E1=(4,1)`、`E2=(1,2)`：

```text
M(0,0) = (2,3)
M(1,1) = (7,6)
M(1/2,1/2) = (2,3)+(2,1/2)+(1/2,1) = (9/2,9/2)
```

`segments->painter` 对每条线的两个端点各做一次这个映射，因此对斜框也成立。它不要求知道原图是人像还是菱形。

## 3. 变换 painter，实际是在变换传给它的 frame

`transform-painter` 接受 painter 和单位框中的三个点：新原点 `o`、第一边终点 `c1`、第二边终点 `c2`。返回的新 painter 收到外层 `F` 后：

```text
新原点 = M_F(o)
新边1  = M_F(c1) - M_F(o)
新边2  = M_F(c2) - M_F(o)
用这个新 frame 调用原 painter
```

减掉新原点不能省略，否则平移会错误地混入边向量。变换不拆原 painter 的内部线段，因此原语和复合图形都能被同样处理。

| 操作 | 新局部原点、边1终点、边2终点 |
| --- | --- |
| 垂直翻转 | `(0,1), (1,1), (0,0)` |
| 水平翻转 | `(1,0), (0,0), (1,1)` |
| 逆时针转 90° | `(1,0), (1,1), (0,0)` |

`beside(p,q)` 将 p 放到左半框、q 放到右半框；`below(p,q)` 将 p 放到下半框、q 放到上半框。它们都返回新 painter，而不是立即要求一个全局画布。这就是组合封闭性：原语与组合结果可互换使用。实现上这些返回过程又是词法闭包；**结构封闭性**与**捕获定义环境**依然是两个不同事实。

## 4. 习题 2.44：向上递归分裂

**题意概述**：仿照 `right-split` 写 `up-split`，交换 `below` 与 `beside` 的角色。

```scheme
(define (up-split p n)
  (if (= n 0)
      p
      (let ((smaller (up-split p (- n 1))))
        (below p (beside smaller smaller)))))
```

文件额外检查 `n` 是非负精确整数，负深度不会无限递归。注意不能只交换画面中的左右位置：需要交换**两个组合操作的角色**。

```text
up-split(p,1)         up-split(p,2)
┌──────┬──────┐       ┌──────┬──────┐
│  p   │  p   │       │ up,1 │ up,1 │
├──────┴──────┤       ├──────┴──────┤
│     p      │       │     p      │
└────────────┘       └────────────┘
```

以 X painter 第一条对角线 `(0,0)→(1,1)` 为例，在 `up-split(X,1)` 中，下半幅映成 `(0,0)→(1,1/2)`；左上幅映成 `(0,1/2)→(1/2,1)`；右上幅映成 `(1/2,1/2)→(1,1)`。文件对实际端点而不仅是数量作断言。

原图出现次数满足 `C(0)=1`、`C(n)=1+2C(n-1)`，所以 `C(n)=2^(n+1)-1`。X 有 2 条线，深度 2 就有 14 条。`smaller` 在构造时只算一次，但绘制时必须在两个不同 frame 各调用一次，不能因为过程值相同就删掉一幅图。

文件同时给出教材的 `right-split`、`corner-split`、`square-limit`：最后一个用四个方向不同的角落图构造整幅图。它们只是 painter 组合，不关心线段表示；深度 1 的 `square-limit(X,1)` 实际生成 48 条线。

## 5. 习题 2.49：四个原语的完整构造

**题意概述**：用 `segments->painter` 构造边框、X、菱形、wave。

### (a) 边框

依次连接 `(0,0)→(1,0)→(1,1)→(0,1)→(0,0)`，共四条线。由于两个边向量可不垂直，这会画出指定 frame 的平行四边形，而不仅是固定轴向正方形。

### (b) X

两条线：`(0,0)→(1,1)`，以及 `(0,1)→(1,0)`。它们连接对角顶点。

### (c) 菱形

连接四边中点：`(1/2,0)→(1,1/2)→(1/2,1)→(0,1/2)→(1/2,0)`，共四条线。这里“菱形”描述单位框中的原图；一般仿射变换不保持长度，斜框中的结果未必是四边等长的欧氏菱形，但正是题目要求的 painter 变换。

### (d) wave

教材图 2.10 没有指定唯一数值坐标。文件参照[原图][wave-image]画出张臂、双腿和头部轮廓，使用以下五条**开放**折线；每行相邻两点成一条线，不跨行连线：

```text
(0,.85) → (.15,.60) → (.30,.65) → (.40,.65) → (.35,.85) → (.40,1)
(.60,1) → (.65,.85) → (.60,.65) → (.75,.65) → (1,.35)
(1,.15) → (.60,.45) → (.75,0)
(.60,0) → (.50,.30) → (.40,0)
(.25,0) → (.35,.50) → (.30,.60) → (.15,.40) → (0,.65)
```

合计 `5+4+2+2+4=17` 条线，代码用精确分数表示这些坐标。这是教材草图的近似描线，不宣称逐像素复制；原图中的虚线 frame 不是 wave 内容，因而没有给 wave 加边框。辅助过程 `polyline` 只负责把点序列变成连续线段，所有四种原语最终都调用相同的 `segments->painter`。

## 6. 分层设计的收益与成本

```text
向量/线段/frame
→ frame 坐标映射
→ 基础 painter
→ transform / beside / below
→ up-split / corner-split / square-limit
```

每层用适合它的词汇工作。改 wave 的轮廓不必改 `corner-split`；改输出后端不必改递归布局。高阶过程还可以接收“变换 painter 的过程”，例如把四个方向变换参数化后再排列四幅图；这与第一章过程组合是同一种能力，不需要新的宏或解释器。

代价也很具体：本实现最终物化全部线段，深度增大时输出指数增长；`append` 还会复制部分列表。它适合有限教学图形，不是交互渲染引擎。几何测试能证明坐标和组合规律，不能替代艺术审美判断。
