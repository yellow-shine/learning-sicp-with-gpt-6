## 1. 一种胶水，三种解释层次

`cons` 接受任意两个值。结果仍是一个值，还能传给 `cons`，所以不必为“数组的数组”“树的树”分别引入新语法。

- **pair**：由 `car`、`cdr` 两部分构成；`(cons 1 2)` 显示为 `(1 . 2)`。
- **正规列表（proper list）**：`cdr` 链最终到达空表的 pair 链；`(list 1 2)` 是 `(cons 1 (cons 2 '()))`。
- **树**：对嵌套组合的一种解释。pair 的任一部分都可以继续是 pair；原子是叶子，空表在本单元不算叶子。

```text
(list 1 2 3)
  ┌─────┬─────┐    ┌─────┬─────┐    ┌─────┬─────┐
  │  1  │  ───┼───→│  2  │  ───┼───→│  3  │  /  │
  └─────┴─────┘    └─────┴─────┘    └─────┴─────┘
                                               空表
```

每个列表节点的 `car` 是一项，而不是整个余下序列；`cdr` 才是尾表。`car` 空表是错误，不是某种“零值”。

对于 `((1 2) 3 4)`，外层长度是 3，叶子数是 4：

```text
外层首节点 [ • | • ] → [3 | •] → [4 | /]
             ↓
           [1 | •] → [2 | /]

树视图： 根
        / | \
     (1 2) 3 4
      / \
     1   2
```

树视图隐藏了列表用于链接兄弟项的 pair；盒指针图则把所有 pair 都画出来。这两种图回答不同问题，不应把图上的节点数混为一谈。

## 2. “封闭性质”不等于“词法闭包”

教材的 **closure property（组合的封闭性质）**：一种组合操作的结果，可以继续作为同种操作的输入。pair 能包住 pair，painter 能组合成 painter，这让层次构造没有人为的层数上限。

**lexical closure（词法闭包）**：过程值连同它所需的定义环境；例如 `(lambda (m) (m x y))` 保留 `x,y` 的绑定。

二者不是同义词，也不存在“列表必须用闭包实现才有封闭性质”的推论。02.01 用词法闭包实现 pair，是一种表示方案；本单元用原生 pair 同样具有组合封闭性质。Go 的函数闭包知识不能替代这里的结构性定义。

## 3. 习题 2.17：返回最后一个 pair，不是最后一个元素

**题意概述**：对一个非空列表，返回只包含末项的列表，例如 `(23 72 149 34)` 得 `(34)`。

```scheme
(define (last-pair items)
  (cond ((not (pair? items)) (error "nonempty proper list required"))
        ((null? (cdr items)) items)
        (else (last-pair (cdr items)))))
```

执行轨迹：

```text
last-pair (23 72 149 34)
→ last-pair (72 149 34)
→ last-pair (149 34)
→ last-pair (34)
→ 返回这个现成的 (34)，不是数 34，也不是复制出的新列表
```

所以 `(eq? (last-pair xs) tail)` 可以为真：返回的是原列表尾部的同一个 pair。没有赋值时，共享不影响值的推理；第三章允许修改 pair 后，这种共享就有可观察后果。

对长度 `n` 的非空正规列表，时间 Θ(n)、控制空间 Θ(1)：递归调用在尾位置。这里不分配答案列表。空输入和点尾列表 `(1 . 2)` 不符合约定，文件显式报错。含环结构不在此单元的输入域，不能期待它终止。

## 4. 习题 2.28：fringe 返回从左到右的叶子

**题意概述**：树用嵌套列表表示，将所有叶子按从左到右的顺序取出。教材样例 `x=((1 2) (3 4))` 得 `(1 2 3 4)`，`(list x x)` 得重复的八个叶子。

最直接的递归关系是：

```text
fringe(空表) = 空表
fringe(原子) = 只包含这个原子的列表
fringe(pair) = append(fringe(car), fringe(cdr))
```

例如：

```text
fringe ((1 2) (3 4))
→ append(fringe (1 2), fringe ((3 4)))
→ append((1 2), (3 4))
→ (1 2 3 4)
```

这个答案正确，但每次 `append` 都复制左边的结果；左侧含大量叶子的偏斜树会反复复制，最坏达平方量级。文件采用同一递归含义的尾表版本，不建中间结果再复制：

```scheme
(define (fringe tree)
  (define (walk t tail)
    (cond ((null? t) tail)
          ((not (pair? t)) (cons t tail))
          (else (walk (car t) (walk (cdr t) tail)))))
  (walk tree '()))
```

不变量是 `walk(t, tail)` 返回“`t` 的叶子，后接 `tail`”。归纳证明：空树直接返回尾表；原子只需 `cons` 一次；pair 先把右部分的叶子放到尾表前，再把左部分放到它们前。因此**计算右侧在先，但最终输出仍从左到右**：

```text
walk(((1 2) (3 4)), ())
右侧建立 (3 4)
左侧 walk((1 2), (3 4))
  先 cons 2 到 (3 4) → (2 3 4)
  再 cons 1          → (1 2 3 4)
```

这不是带副作用的“访问日志顺序”。若要在遇到叶子时打印，打印顺序会从右到左；本过程是纯粹构建结果，没有这种副作用。

对无环 pair 树，以展开后的节点出现次数 `N`、叶子数 `L`、pair 树高度 `h` 计，时间 Θ(N)、结果空间 Θ(L)、控制空间 O(h)。共享子树按每次出现分别展开：`(list x x)` 不能因两部分指向同一对象而丢掉一份叶子。对共享图，这个 N 可能远大于实际分配节点数；本过程不是图去重遍历。

## 5. 运行与常见误解

```sh

```

输出 `02.03: all checks passed`。测试包含末项、单项、空输入报错、点尾报错、两次共享子树、嵌套空表、叶子计数，以及 `fringe` 对原子和 `(1 . 2)` 的自然扩展。`last-pair` 要求正规列表，而 `fringe` 按 pair 树递归，两个过程的输入约定不同。

- `cons` 不等于 `append`：前者把整个第一参数作为一项，后者接起两个序列。

- 引号得到数据：`'(1 2)` 是列表；直接求值 `(1 2)` 会试图把 1 当过程。

**已回答回顾**：层次结构来自组合封闭性；尾部选择可能返回共享对象；树遍历必须分别处理空表、原子、pair。02.04 把这些递归样式提炼为序列接口，使业务代码不再每次手动追踪 `car/cdr`。
