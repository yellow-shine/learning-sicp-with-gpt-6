## 1. 问题：程序为什么能理解另一段程序？

第三章用环境图解释闭包，现在把画图动作变成可执行算法。输入不是字符串，而是 reader 已读出的符号、数和列表。例如宿主表达式：

```scheme
(mc-eval '(+ 1 (* 2 3)) (setup))
```

外面的 `mc-eval`、`quote`、`setup` 由 **宿主 `#lang sicp`** 执行；引号里的 `(+ 1 (* 2 3))` 是 **对象语言程序数据**，由我们写的求值器执行。宿主 `+` 不会理解列表 `(* 2 3)`，求值器必须先把它变成 6。

这不是“调用内建 eval 就完成解释器”。本章没有使用宿主 eval。宿主负责 pair、算术、函数调用、内存管理；本程序负责对象语言的语法分类、绑定、闭包、特殊形式和组合式求值。底层调用栈仍借自宿主，第五章再揭开它。

## 2. 两条互相递归的规则

```text
mc-eval(表达式, 环境)
  ├─ 数/字符串/布尔量 → 自身
  ├─ 符号 → lookup
  ├─ quote / if / lambda / begin / define / set! → 各自规则
  ├─ and / or / let / cond → 语法变换 → mc-eval
  └─ 普通组合式 → 求操作符和操作数 → mc-apply
                                             ├─ primitive → 宿主 apply
                                             └─ compound → 扩展闭包环境
                                                            → 求过程体 → mc-eval
```

特殊形式必须在普通组合式之前识别，否则 `(define x 3)` 会被当成调用名为 define 的过程，甚至先查找尚未定义的 x。`if` 只执行一个分支；`lambda` 构造过程，不执行过程体；`quote` 返回数据，不递归解释数据内部的符号。

对象语言只把 `#f` 当假，0 与空表都是真；这是 `truth?` 明确规定的，而不是假定任何宿主的真假约定都适用。教材把 true/false 作为全局变量；此处保留这两个绑定，并额外接受布尔字面量。缺少 else 的 if 在假分支返回 `#f`，define/set! 返回 `ok`，都是本教学实现的明确约定。

### 环境不是名字到值的全局字典

`evaluator.rkt` 的环境是一条框架链；框架有可变头结点，内部是 `(名字 . 值)` 单元的关联表。

- `lookup` 从最近框架向外找，未绑定就报错。
- `define!` 只更新/增加当前框架的绑定。
- `assign!` 沿链找到既有单元，修改该单元；不能悄悄创建新名字。
- `extend` 为参数分配新单元，检查参数个数及重复参数。
- 闭包保存的是环境的引用，不是框架内容的深拷贝，因此后续赋值能被共享闭包观察。

与 Go 的类比是“闭包捕获可共享的变量位置”，但这里还显式实现了环境链查找，不是直接用宿主同名变量偷渡绑定。

## 3. 一次定义与调用的完整轨迹

对象程序：

```scheme
(define (make-adder x) (lambda (y) (+ x y)))
(let ((add5 (make-adder 5)))
  (let ((x 100)) (add5 3)))
```

1. define 的过程简写被 `def-value` 变成 lambda。
2. lambda 产生 `compound` 对象：参数 `(x)`、过程体、全局环境 G。
3. `(make-adder 5)` 扩展 **make-adder 保存的 G**，得到 E1：`x=5 → G`。
4. 执行内部 lambda，产生 add5，它保存 E1。
5. 调用点虽然有 `x=100`，应用 add5 时仍扩展 **add5 保存的 E1**：

```text
调用点：   x=100 → add5=<闭包> → G
                         │
add5 闭包环境：           └── E1: x=5 → G
add5 本次调用： E2: y=3 ──────┘
求 (+ x y)：x 从 E1 得 5，y 从 E2 得 3 → 8
```

若错误地扩展调用者环境，就成为动态作用域，本例会得到 103。自检直接检验 8，并用两个 inc 调用检验同一变量单元被共享，结果 `(1 2)`。

## 4. 习题 4.1：让顺序属于对象语言，而不是宿主偶然性

**题意概述**：教材的 `cons` 两个参数若按不同顺序求值，`list-of-values` 的效果顺序也随之改变。分别实现不依赖宿主参数顺序的左到右和右到左版本。

左到右先用一个只有一个初始化式的 let 固定 first，随后递归；右到左先固定递归得到的 rest，再算 first：

```scheme
;; 左到右的递归分支
(let ((first (evaluator (car expressions) env)))
  (cons first (values-left (cdr expressions) env evaluator)))

;; 右到左的递归分支
(let ((rest (values-right (cdr expressions) env evaluator)))
  (let ((first (evaluator (car expressions) env)))
    (cons first rest)))
```

`cons` 最终仍按**源位置**组织参数，不是把参数表 reverse。把 n 初始化为 0，两个操作数均为 `(begin (set! n (+ n 1)) n)`：

| 版本 | 第一个源位置的值 | 第二个源位置的值 | 返回参数表 |
| --- | --- | --- | --- |
| 左到右 | 1 | 2 | `(1 2)` |
| 右到左 | 2 | 1 | `(2 1)` |

两个版本最后 n 都是 2，但传给过程的参数不一样。本求值器普通应用固定先求操作符，再从左到右求操作数；这是教学语言的选择，不是宣称第二版 Scheme 规定所有普通调用都如此。

## 5. 习题 4.4：短路不等于返回布尔值

**题意概述**：实现 and/or 的左到右短路规则，可以直接增加特殊形式，也可以变换为已有形式。本题选择后一条完整路线。

### and 的派生形式

- 空 `(and)` → `#t`。
- 单项 `(and e)` → e，保留 e 的原值。
- 多项 `(and e rest...)` → `(if e (and rest...) #f)`，递归展开 rest。

`(and 1 2)` 得 2，`(and #f (/ 1 0))` 得 `#f` 而不除零。

### or 要保存第一次求出的真值

- 空 `(or)` → `#f`。
- 单项 → 原表达式。
- 多项概念上变成：

```scheme
((lambda (fresh)
   (if fresh fresh <其余 or 的变换>))
 e)
```

普通应用会且只会算一次 e。不能变成 `(if e e ...)`，因为 e 可能修改计数器，重算会改变结果。也不能始终使用普通名字 `temp`，否则用户的自由变量可能被意外捕获。`or->if` 通过宿主 `gensym` 产生不可与用户 reader 符号重名的临时名字。

这里使用宿主 fresh-symbol 工具不等于使用宿主宏系统来代替求值器：实际创建的是对象语言 lambda/if 数据，再交给 `mc-eval`。

自检涵盖空式、0、空表、非布尔真值、未选中的除零、计数器只加一次及临时名字不捕获用户名字。

## 6. 表示选择与边界

- 环境关联表查找随框架大小与深度线性增长，优点是机制可见；第五章的词法地址会减少运行时按名字搜索。
- `cond` 支持测试加动作以及最后的 else；不包含 `=>`、只有测试而无动作的子句。let 支持普通 let，不含 named let。固定参数 lambda 不含 dotted/rest 参数。
- 这不是完整 Scheme：没有宏系统、call/cc、对象语言模块或通用 I/O。对象程序使用受控、合法的 S 表达式；没有网络接口，也不宣称可以安全运行不可信代码。运行期未绑定名、错误参数个数、非过程调用等会报错。
- 共享核心已接入 04.02 的 `scan-out-defines`，并拒绝读取 `*unassigned*`；本单元例子不依赖内部定义，这个扩展下一节完整说明。
- 不直接把对象过程交给宿主 map/apply：对象复合过程是带标签的数据，不是宿主可调用闭包。只有明确标记的 primitive 才能桥接宿主 apply。
