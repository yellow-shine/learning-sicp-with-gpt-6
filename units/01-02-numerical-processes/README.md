## 1. 从“是什么”到“如何得到”

“平方根是满足 `y ≥ 0` 且 `y² = x` 的数”说明答案的性质，却没有说明计算步骤。牛顿法提供一种可执行知识：从正猜测 `y` 出发，用 `y` 与 `x/y` 的平均值作为下一次猜测。

```text
sqrt-relative(x)
 ├─ improve(guess)：提出更好的猜测
 ├─ relatively-close?(old,next)：决定是否停止
 └─ iter(guess,remaining)：组织重复计算
```

对 `x=2`：

| 旧猜测 y | x/y | 新猜测 (y+x/y)/2 |
| --- | --- | --- |
| 1 | 2 | 1.5 |
| 1.5 | 1.3333333333 | 1.4166666667 |
| 1.4166666667 | 1.4117647059 | 1.4142156863 |
| 1.4142156863 | 1.4142114385 | 1.4142135624 |

为什么这不是碰运气？令真正的根为 `r>0`，则精确算术下

```text
new - r = (y + r²/y)/2 - r = (y-r)²/(2y) ≥ 0。
```

一次更新后猜测不小于根；若 `y>r`，下一次又小于 `y`。靠近根后，误差近似被平方，所以局部收敛很快。但“数学序列收敛”不等于“浮点程序终止”，这正是 1.7 的问题。

代码对正常输入从 `1.0` 开始，明确使用不精确实数；若一直用精确分数，分母可能迅速长大，并不会自动产生浮点近似。实现中的求平均写成 `y/2+(x/y)/2`，减少直接相加的溢出风险。

## 2. 习题 1.7：误差应该相对谁？

**题意概述**：解释原书的绝对平方残差测试为什么不适合极小、极大数；举例；改用相邻猜测的相对变化判断停止，并比较效果。

原条件是：

```scheme
(< (abs (- (* guess guess) x)) 0.001)
```

它限制的是**平方的绝对误差**，不是根的相对误差。

### 极小数：还离答案很远，却已经通过

取 `x=1e-12`，真实根是 `1e-6`。从 1 开始，前面几步近似不断减半：

```text
1 → 0.5 → 0.25 → 0.125 → 0.0625 → 0.03125
```

最后的平方约为 `0.0009765625`，与 `1e-12` 相差小于 `0.001`，因此原测试接受约 `0.03125`。结果却是真实根的约 31250 倍。即使把常量改小，也只是把失效范围推向更小的输入，没有解决尺度问题。

### 极大数：表示精度使要求无法满足

本环境用 `x=1e100` 可实际观察到：猜测停在约 `1e50`，但平方残差约为 `1.94e84`。这里不是根差了 `1e84`，而是**平方的差**如此大；在这一尺度，浮点数相邻可表示值的间隔本就远大于 `0.001`。

下一次更新可能舍入回同一个猜测，条件却仍为假：原算法永远重复。不是每个大数都失败，例如有些平方正好舍入到 `x`；失败与数值和浮点实现有关，不能只看十进制位数。

`legacy-sqrt-observe` 保留原条件，但加上“猜测不再变化/步数耗尽”的**观察出口**，返回 `(状态 猜测 更新次数 平方残差)`。`stalled` 表示诊断到原算法无法继续，不把它谎称为满足原条件。

### 解法：相邻猜测的相对变化

本单元使用以下判断，`ε=1e-12`：

```text
old = next，或者
|next-old| / max(|old|,|next|) ≤ ε。
```

先检查相等，再检查尺度是否大于零，避免 `0/0`。与直接乘 `ε×scale` 相比，除以尺度也避免阈值在极小数处下溢。核心循环是：

```scheme
(let ((next (improve guess)))
  (if (relatively-close? guess next)
      next
      (iter next (- remaining 1))))
```

在完整代码中，非有限值与步数用尽都显式报错。步数上限是故障保护，不是“达到上限就假装收敛”。对 `x=0` 直接返回 0：若只用纯相对判据，`y → y/2` 的相对变化始终为 1/2，直到浮点下溢；没有必要等待这个偶然事件。负数的**实平方根**无定义，代码拒绝，不偷偷改成复数接口。

自检验证 `1e-300 → 1e-150`、`1e300 → 1e150` 及零、普通数、精确分数。相对判据明显改善了尺度适应性，但不是任意数值算法的误差证明：更新停滞可能来自舍入，也可能来自坏的更新函数。平方根这里有前面的收敛分析；通用迭代还要看函数本身。输入范围是能够转为非零有限浮点值的有限实数（零除外），不是任意精度数值库。

## 3. 习题 1.8：把同一组织方式用于立方根

**题意概述**：利用教材给出的立方根改进公式，编写类似平方根的过程。

设 `g(y)=y³-x`，它的导数是 `3y²`。牛顿更新得到：

```text
y_new = y - (y³-x)/(3y²) = (2y+x/y²)/3。
```

这就是题目公式，代码将 `improve` 改为：

```scheme
(+ (* (/ 2.0 3.0) guess)
   (/ (/ (/ x guess) guess) 3.0))
```

代数上相同，但不先形成 `guess²` 或 `2*guess`，以减少中间溢出。停止策略与 1.7 相同；零直接返回，负数用 `-1.0` 起步，保持猜测与被开方数同号，避免把迭代带到除零点。

以 `x=8` 为例：

```text
1 → 10/3 ≈ 3.333333
  → (2×3.333333+8/3.333333²)/3 ≈ 2.462222
  → 2.081341 → 2.003137 → 2.000005 → 2。
```

`x=-8` 从 -1 开始沿相反数序列趋近 -2。对正 `x` 与正 `y`，若真根为 `r`，新误差为 `(y-r)²(2y+r)/(3y²)`，同样在第一次更新后不低于根，并随后下降；负数由符号对称性得到相同结论。

这说明可复用的不是某一个公式，而是“猜测—改进—判断”的组织方式。01.06 会把它真正提取成接收过程参数的通用过程。

## 4. 黑盒不是“什么都不用知道”

黑盒抽象让调用者只依赖**契约**：例如 `sqrt-relative` 接收非负有限实数，返回近似实平方根；调用者不必知道猜测变量叫什么。它不能隐藏输入域、误差含义或可能失败的条件。

内部 `improve`、`iter` 都定义在 `sqrt-relative` 内，因此别的求根过程也能用这些名字，不污染外层。`improve` 中的 `guess` 是自身形参绑定的名字；`x` 相对这个内部过程是自由变量，由定义位置外层的 `sqrt-relative` 绑定。它不是从调用者碰巧同名的 `x` 获取值：这是**词法作用域**。

```scheme
(define (sqrt-relative input)
  (define x (checked-inexact input))
  (define (improve guess) ... x ...)
  ...)
```

形参可以一致改名而不改变意义，但必须避免捕获原来的自由变量；把 `guess` 改成 `abs` 后若体内调用 `(abs ...)`，就可能把原来指向绝对值过程的名字遮蔽成数字。作用域是绑定在源码中的可见区域，不等同于“过程运行了多久”。

还有两个常见误会：

- 教材用于说明替换性的“用 exp/log 算平方”只在合适的输入域与数学模型下等价；浮点误差、零与负数会暴露接口差异，不能无条件替换。
- 不可把条件控制与普通的值选择过程混同，下面补齐 01.01 留下的例子。

### 习题 1.6：new-if 为什么不能替代 if？

**题意概述**：Alyssa 用由 cond 定义的普通过程 new-if 替换平方根循环中的 if，说明运行结果。

```scheme
(define (new-if predicate then-clause else-clause)
  (cond (predicate then-clause)
        (else else-clause)))

(define (sqrt-iter guess x)
  (new-if (good-enough? guess x)
          guess
          (sqrt-iter (improve guess x) x)))
```

普通调用进入 new-if 的过程体之前，必须先算三个参数。即使 `good-enough?` 已经返回真，第三个参数仍需要调用下一次 sqrt-iter；它又要先求下一次递归参数：

```text
sqrt-iter(g,x)
→ 等待 new-if 的参数：good-enough?(g,x)、g、sqrt-iter(g1,x)
→ 后者又等待 new-if 的参数：good-enough?(g1,x)、g1、sqrt-iter(g2,x)
→ …
```

所以在算术仍能继续的情况下永远进不到能返回结果的 new-if 过程体，不正常终止；具体实现还可能最终耗尽资源。cond 在 **new-if 内部**的短路帮不上忙，因为过早求值发生在**进入过程体之前**。`(new-if (= 2 3) 0 5)` 能得到 5 只说明已经算好的值可以选择，不说明它能控制分支表达式是否求值。

自检不运行这个无限版本，而是断言 `(new-if #t 0 (/ 1 0))` 会抛除零错误，对照 `(if #t 0 (/ 1 0))` 安全返回 0。两者有限、可重复地证明参数求值与特殊形式选择的区别。
