## 从变量赋值到结构修改

`set!` 改名字所在的绑定；`set-car!` / `set-cdr!` 改某个 pair 的槽，不管它有几个名字。`cons` 创建新 pair，`set-cdr!` 则改变旧 pair。`#lang sicp` 的 pair 可变；不能将代码直接搬到默认 pair 不可变的 `#lang racket` 而不适配。

```text
shared → [a | •] → [b | /]
graph  → [• | •]
          │   └────────→ shared
          └────────────→ shared
```

`(set-car! (car graph) 'changed)` 之后，`(car (cdr graph))` 也得到 `changed`。两个槽指向同一节点，不是两份内容恰好相同的数据。树形递归依赖“子树不回到祖先”；共享图还可能重复计算，环则可能让递归根本到不了空表。

## 3.13：首尾相接以后 last-pair 没有答案

**题意**：把有限非空列表最后一个 pair 的 cdr 指向列表自身，画 `(a b c)` 的结果，并解释再找尾 pair 会怎样。

```scheme
(define (make-cycle x)
  (set-cdr! (last-pair x) x)
  x)
```

```text
z ─→ A:[a | •] ─→ B:[b | •] ─→ C:[c | •]
      ↑                                │
      └────────────────────────────────┘
```

创建时 `last-pair` 还能找到 C，因为原本 C.cdr 是空表。修改后沿 cdr 走的节点序列是 A,B,C,A,B,C,…，没有任何节点的 cdr 为空，所以 `(last-pair z)` 不终止。它是尾递归，不能把“不终止”武断说成“必然栈溢出”。

代码只检查 `(eq? z (cdddr z))` 并取七个 car 得 `(a b c a b c a)`；不调用循环版本的 `last-pair`，也不把环交给不确定是否支持图打印的普通打印器。`last-pair`/`make-cycle` 的约定是非空、正常有限列表输入；不是一般图算法。

## 队列：表示多两个指针，换来常数时间

队列自身是 `(front-ptr . rear-ptr)`，元素链是普通单向列表。

- 空队列当且仅当 front 为空。
- 非空时 rear 指向元素链的最后一个 pair，其 cdr 为空。
- 入队分配一个节点；空队列同时设置 front/rear，否则链接旧 rear 再移动 rear。
- 出队移动 front；空队列取头或删除报错。

每次入队、出队、取头都是 Θ(1)。若只保存列表头，每次尾部插入通常要 Θ(n) 搜索。

## 3.21：打印的是表示，不是抽象内容

**题意**：教材队列为什么看起来重复打印最后一项，删除完又留下 b？实现正确的 `print-queue`。

```text
插 a：q → [• | •]，两个指针都指向 A:[a | /]
插 b：q.front → A:[a | •] → B:[b | /] ← q.rear
删 a：q.front ───────────→ B         ← q.rear
删 b：q.front → ()                    q.rear → B
```

普通打印器从 q.car 和 q.cdr 分别打印引用内容，不展示它们的共享身份：

| 动作 | 原始 q 的列表记法 | 抽象内容 |
| --- | --- | --- |
| 插 a | `((a) a)` | `(a)` |
| 插 b | `((a b) b)` | `(a b)` |
| 删一次 | `((b) b)` | `(b)` |
| 再删一次 | `(() b)` | `()` |

例如 q 的 car 为 `(a b)`，cdr 为 `(b)`，于是整个 pair 按列表记法打印成 `((a b) b)`。不是插了两个 b。教材删除过程没有清 rear，故最后还指向 B；但判空只看 front，这不破坏队列操作。再次入队时会重置两个指针。残留 rear 会延长最后一个节点的存活，工程实现可在变空时顺手清掉；本题为复现现象保留教材行为。

解答是只打印抽象序列：`(define (print-queue q) (display (car q)) (newline))`。打印 Θ(n)，并不影响队列操作 Θ(1) 的结论。`queue-items` 暴露内部链仅供教学断言；生产接口不应让调用者随意破坏结构。

## 表：从共享 pair 到可变关联

本单元 `make-table` 把记录链藏进闭包；记录是 `(key . value)`。查找用 `assoc`（结构相等的键），更新已存在记录用 `set-cdr!`，新键则插入记录。

```text
records → [(math +) . 10] → [other . 7]
insert! '(math +) 20：改旧记录 value 槽，不新增重名记录
lookup 一个新建但 equal? 的 '(math +) → 20
```

线性表查找/更新 Θ(n)，新键插入的分配本身 Θ(1)。二维表可让第一层键的值成为子表；第二章的数据导向操作表就是这个思想。记忆化表可以缓存“参数→结果”，但只有纯过程或正确包含状态的缓存键才安全。此处用 `#f` 表示未找到，因此不能区分“存着 #f”和“键缺失”；调用者若需要这种区别，应返回带存在标记的记录，本单元没有扩大接口。
