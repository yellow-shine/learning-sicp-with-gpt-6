## 不再让调用时刻承担全部“时间”

带状态账户把“现在的余额”存进槽；流可以存成 `100,90,70,65,…`。第 n 项是模型的第 n 个状态，宿主程序今天算到第3项、明天才算第4项，不改变这些项的数学含义。流让计算需求的顺序和被模拟世界的时间轴分开。

这种解耦既适合时间历史，也适合“第 n 次近似”“x 的 n 次方系数”“第 n 个候选对”。它们的索引不一定都代表秒，不应把各种流都称作实时系统。

## 先表达近似序列，再选择何时停止

`sqrt-stream` 从猜测1.0出发，把牛顿改进映射到自己的猜测流；`stream-limit` 单独比较相邻项，差小于正 tolerance 时返回后者。

```text
sqrt(2) 猜测：1 → 1.5 → 1.416666… → 1.414215… → 1.41421356…
流生成器：负责下一次更好猜测
消费者：负责要多少精度
```

停止条件仍是数值算法的条件，不因包装成流就自动正确。这里限制平方根示例为正数；相邻差很小并非对任意序列都证明接近真解，错误 tolerance 被拒绝。

`partial-sums` 将 `1,-1/3,1/5,-1/7,…` 变成逐项和，乘4得到 π 近似。教材 Euler 变换利用连续三项：

```text
T_n = S_(n+2) - (S_(n+2)-S_(n+1))² /
                    (S_n - 2S_(n+1) + S_(n+2))
```

它试图消掉主要误差项；可以反复变换构成 tableau，再取每行第一项作为进一步加速流。代码实现一次变换，在相同原始前缀预算下比较第5个变换值与第7个原值，对这个 π 序列确实更精确；不声称任意序列都加速。分母0显式报错，不能默默除零。

## 3.60：级数乘法是卷积，不是逐项相乘

**题意**：把幂级数表示成系数流，完成乘法，并验证 `sin²x+cos²x=1`。

流 `a0,a1,a2,…` 表示 `A(x)=a0+a1*x+a2*x²+…`。尾流自身表示 `A1(x)=a1+a2*x+…`，所以 `A=a0+x*A1`；尾里的第一个系数重新位于常数项位置，这个移位很重要。

令 `B=b0+x*B1`，则：

```text
A*B = a0*B + x*A1*B
    = a0*b0 + x*(a0*B1 + A1*B)
```

对应解答：

```scheme
(define (mul-series a b)
  (cons-stream (* (stream-car a) (stream-car b))
               (add-streams
                (scale-stream (stream-cdr b) (stream-car a))
                (mul-series (stream-cdr a) b))))
```

每次只先给常数项，递归放在延迟尾中。一般第 n 项是 `Σ(i=0…n) ai*b(n-i)`，即卷积。若仅逐项相乘，会漏掉交叉项；若递归直接拿两个尾而不补移位，会把次数放错。

例：`(1+2x)(3+4x)` 得系数 `(3,10,8,0,…)`，其中10来自 `1*4+2*3`。这里 `mul-series` 约定输入为无限系数流，有限多项式先用无限零尾补齐，不能把有限流被截短误当成正确多项式乘法。

### 构造 sine、cosine 并核验

积分把系数 `a0,a1,…` 变成 `a0/1,a1/2,…`，这段流表示积分结果的**非恒定部分**，要由调用者补常数项。

```scheme
(define cosine-series
  (cons-stream 1 (scale-stream (integrate-series sine-series) -1)))
(define sine-series
  (cons-stream 0 (integrate-series cosine-series)))
```

根据 `sin'=cos, cos'=-sin`，得到：

```text
sin: 0, 1, 0, -1/6, 0, 1/120, …
cos: 1, 0, -1/2, 0, 1/24, 0, …
```

二次项相加是 `1 + 2*(-1/2)=0`；四次项相加是 `2*(-1/6) + ((-1/2)²+2*(1/24)) = -1/3+1/3=0`。常数项1。更一般地，形式微分有 `(sin²+cos²)'=2sin*cos-2cos*sin=0`，且常数项1，所以这个恒等式对所有系数成立。代码用精确有理数核验前12项 `(1,0,…,0)`，这是对实现的有限自检，不用有限测试冒充无限证明。

`exp-series=cons-stream 1 (integrate-series exp-series)` 同样来自导数等于自身。这里先做**形式幂级数**运算；给 x 代值时是否收敛、截断误差多大，是另一个分析问题。

## 公平枚举：不要被无限第一行困住

想枚举所有正整数对 `i≤j`，若先输出 `(1,1),(1,2),(1,3),…` 再处理第二行，第二行永远轮不到。`interleave` 每出一项就交换两个输入的位置，`pairs` 将第一行剩余部分和剩余子三角形交错。

前八项实际为：

```text
(1,1), (1,2), (2,2), (1,3), (2,3), (1,4), (3,3), (1,5)
```

每个固定层次会在有限轮换后得到服务，所以任一固定合法对最终可达；但深层可能等待很久。普通 append 不公平；公平也不等于按权重递增或固定延迟。代码只取有限前缀，不显示整个无限枚举。构造递归子三角形在 `cons-stream` 尾内，避免还没产第一对就无限递归。

## 信号处理：采样、平滑与过零分层

信号流每项是某个采样时刻的值。`smooth` 对相邻两个采样取平均，`zero-crossings` 再比较符号；零按非负处理。分离两层后，换平滑策略不用改检测器。

```text
输入       2, 4, -2, -4, 2, 4
相邻平均   3, 1, -3, -1, 3
过零输出   0, 0, -1,  0, 1    （之前的值取0）
```

- -1 表示从非负到负，1 表示从负到非负，0 表示无穿越。
- 长度 N 的有限输入产生 N-1 个相邻平均；没有凭空补最后一个采样。
- 采样可能漏掉两个采样点之间的变化；平滑会削弱噪声，也可能影响检测时间。这是离散信号模型，不是连续物理传感器的完整替代。

## 3.77：延迟反馈输入，还要延迟递归的输入尾

**题意**：将显式递归积分器改成接收 delayed-integrand，使它能用于 `dy/dt=f(y)` 的反馈求解。

离散积分采用显式 Euler 递推：

```text
y_0 = initial-value
y_(n+1) = y_n + dt * integrand_n
```

N 个导数采样产生 N+1 个积分值，包括初值。真正的解答是：

```scheme
(define (integral delayed-integrand initial-value dt)
  (cons-stream
   initial-value
   (let ((integrand (force delayed-integrand)))
     (if (stream-null? integrand)
         the-empty-stream
         (integral (delay (stream-cdr integrand))
                   (+ initial-value (* dt (stream-car integrand)))
                   dt)))))
```

这里有三处不能移错：

1. 初值立即可返回，不需要知道导数流。
2. `force delayed-integrand` 在 `cons-stream` 的**尾**里，要求第二个积分值时才读导数。
3. 递归调用仍传 `(delay (stream-cdr integrand))`，不把还不需要的下一个导数尾提前求值。

### 宿主初始化与教材记法要分开

教材写 `define y (integral (delay dy) ...)`，接着 `define dy (stream-map f y)`。这个意图要求先初始化 y，再用其首项构造 dy。本环境的 R5RS 式内部定义不能当作保证逐个赋值的 `letrec*`：直接照搬在本次 Racket 实跑中出现 `y: undefined; cannot use before initialization`。

所以可运行版显式分配两处绑定，再按必要顺序赋值：

```scheme
(define (solve f y0 dt)
  (let ((y #f) (dy #f))
    (set! y (integral (delay dy) y0 dt))
    (set! dy (stream-map f y))
    y))
```

`#f` 只是构造期间尚未填入的绑定值，不会作为导数使用：创建 y 时尾未强迫；创建 dy 时 y 首项已经可用；函数返回后两者都初始化完成。这两次局部赋值用于接上递归图，之后数值历史由流方程决定，不把余额式状态更新藏进每次采样。

### 实际反馈追踪：f(y)=y，y0=1，dt=1/10

```text
构造 y：头1，尾等待 dy
构造 dy：头 f(1)=1，尾等待 y 的尾
要求 y1：读 dy0=1，得 1+1/10=11/10；暂不强迫 dy 的尾
要求 y2：此时 y1 已存在，dy1=f(y1)=11/10，得121/100
继续：1331/1000，14641/10000，…
```

若递归参数写成已经求好的 `(stream-cdr integrand)`，正在生成 y1 时就要生成 dy1，而 dy1 又要求尚在生成的 y1；形成“强迫正在强迫的 promise”的环。仅给最外面加一次 delay 不够。代码的精确反馈前缀检查会在这个错误下失败，而不是只测试无反馈的有限输入。

当 dt=0.001，取索引1000对应 t=1，实际输出 `2.716923932235896`。递推精确模型是 `(1.001)^1000`，不是真正的 e；与 `e≈2.718281828` 的差来自离散化及少量浮点舍入。减小 dt 通常减小 Euler 的离散误差，但稳定性取决于方程与步长，流包装不保证稳定。

## 用输入历史替代可变对象

`stream-withdraw` 接受初余额与提款流，产生包含初值的余额历史：`100` 加输入 `(10,20,5)` 得 `(100,90,70,65)`。这是确定函数；两个消费者读同一纯流，不会像调用同一取款闭包那样额外扣款。这里按教材简化转移直接相减，不包含银行透支政策。

随机生成器也可接收请求流：`generate` 推进种子，`(reset 1)` 重置，并在本示例中输出重置后的状态。种子1的请求 `generate,generate,reset1,generate` 得 `6,15,1,6`。使用03.01同一小型确定转移，明确不用于安全或高质量统计；确定的输入请求使实验可重现。蒙特卡洛也可以把试验结果映成布尔流，再把累计成功数/总数映成估计流，消费者决定需要多少样本。

交互用户仍感到“系统有状态”，因为用户在时间中逐项输入并观察。纯函数没有消灭世界的时间，只把历史显式化。若两个用户共享账户，必须决定两条请求流如何合并；真正并发到达的选择可能不确定，无法凭纯流接口自动免除同步问题。流也不是分布式流平台的背压、容错和投递语义的完整模型。
