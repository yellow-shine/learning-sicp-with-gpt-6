## 1. 把“求解方法”也变成可操作的值

01.05 把 term、next 传给求和过程；本单元更进一步：给一个过程，生成另一个过程。最终我们可以分别描述：

```text
待解决的方程 → 转换成迭代函数 → 选择迭代引擎 → 近似解。
```

这些层次分别变化。改变目标函数不必重写引擎，改变改进方法也不必重写终止循环。但接口还必须说明收敛条件；一个“接受任意函数”的参数列表不代表数学上能解决任意函数。

## 2. 两种一般方法：二分找零点与寻找不动点

### 二分法保持的是一个区间

若 f 在 `[a,b]` 连续且两端异号，介值定理保证其中至少有一个零点。取中点 m，保留仍然异号的一半区间；若 `f(m)=0` 直接结束。

例：`f(x)=x²-2`，区间 `[1,2]`：

```text
[1,2]       中点 1.5，f>0 → [1,1.5]
[1,1.5]     中点 1.25，f<0 → [1.25,1.5]
[1.25,1.5]  中点 1.375，f<0 → [1.375,1.5]
...
```

每步将宽度减半，初宽 L、目标宽度 T 且 `L>T` 时，步骤 Θ(log(L/T))；中点到被保留区间中的零点距离至多半个区间宽度。实现额外接受端点恰好为零、端点顺序颠倒的情况；无异号且无端点根时报错。

异号不自动保证连续：例如带跳跃的符号函数可异号却无零点。程序检查不了任意传入过程的连续性，这是调用者的数学前提。同号也不证明没有根，如 `x²` 在 `[-1,1]` 两端同正；只是二分保证不适用。

### 不动点保持的是一个猜测

r 是 f 的不动点意味着 `f(r)=r`。从猜测 `x0` 产生：

```text
x1=f(x0), x2=f(x1), x3=f(x2), …
```

例如 `cos` 从 1 开始：`1 → 0.5403 → 0.8576 → 0.6543 → … → 0.739085…`。

可微情形下，根附近的 `|f'(r)|<1` 提供局部吸引的充分线索；严格的收缩映射论证还要有邻域内统一的收缩界以及迭代留在该区域等前提。仅仅把方程写成 `x=f(x)`，不能推出从任意初值收敛。`f(x)=1+x` 发散；`f(x)=-x` 从 1 起在 ±1 间震荡。

## 3. 习题 1.35：黄金比例的不动点

**题意概述**：证明黄金比例是 `x↦1+1/x` 的不动点，并实际用 fixed-point 求它。

黄金比例 φ 是方程 `φ²=φ+1` 的正根，因此 φ 非零，等式两边除以 φ 得到 `φ=1+1/φ`。反过来若 `x=1+1/x`，乘 x 得 `x²-x-1=0`，两个根是 `(1±√5)/2`。我们要的是正根 `(1+√5)/2`。

```scheme
(fixed-point (lambda (x) (+ 1 (/ 1 x))) 1.0)
```

轨迹前几步：

```text
1 → 2 → 1.5 → 1.6666667 → 1.6 → 1.625
  → 1.6153846 → 1.6190476 → … → 1.61803398875。
```

从 1 起，第一次到 2，第二次到 1.5；此后区间 `[1.5,2]` 映到 `[1.5,5/3]`，仍在自身内，而且导数绝对值 `1/x²≤4/9<1`，所以这里的迭代有收缩保证，不只是数值观察。正根处导数约 -0.382，负号解释为什么从两侧交替逼近。负根处导数绝对值约 2.618，不能指望一般初值稳定逼近它；零初值会除零。

代码真正运行迭代，黄金比例公式只作为独立参考断言，同时验证 `φ²≈φ+1`，没有把公式当作所谓迭代实现。

## 4. 平均阻尼：修改过程，而不是修改引擎

求平方根可写成 `y=x/y`。直接迭代 `y↦x/y` 一般不收敛：

```text
以 x=2 从 1 开始：1 → 2 → 1 → 2 → …
x/(x/y)=y，除非已经在根上，否则两步回到原值。
```

把每次更新和旧猜测平均：

```scheme
(define (average-damp f)
  (lambda (x) (+ (/ x 2.0) (/ (f x) 2.0))))
```

`average-damp` 输入一个过程 f，**返回**另一个过程，返回时尚未求某个数的 f 值：

```text
(average-damp square)  → 一个过程 h，其中 h(x)=(x+x²)/2
(h 10)                → 55
```

`h` 的函数体使用定义时捕获的 f；即使外层 `average-damp` 已返回，它仍能使用这个绑定。这是词法闭包的初次实际用途，不是把过程体里的 f 文本机械替换成某个全局名字。

```scheme
(fixed-point (average-damp (lambda (y) (/ 2 y))) 1.0)
```

现在轨迹就是 01.02 的牛顿平方根轨迹。平均阻尼不改变不动点，因为 `y=(y+f(y))/2` 等价于 `y=f(y)`，却改变导数为 `(1+f'(y))/2`。原平方根变换在根处导数 -1，平均后为 0，所以局部收敛显著改善；若原导数大于 1，平均后仍大于 1，不能把阻尼当作万能收敛器。

过程组合也能直接返回过程：

```scheme
(define (compose f g)
  (lambda (x) (f (g x))))

((compose square inc) 6) ; square(inc(6))=49
```

先 g 后 f；`compose` 不是把两个数值结果相加，也不是马上调用 f、g。过程可命名、传参、返回、放进数据结构，就是本章所谓“一等地位”。

## 5. 牛顿变换：从零点问题生成不动点问题

若要解 `g(x)=0`，在当前 x 处用切线近似：

```text
g(x+Δ) ≈ g(x)+g'(x)Δ。
令右边为零，Δ=-g(x)/g'(x)，
所以 N_g(x)=x-g(x)/g'(x)。
```

N_g 的不动点（且导数分母合法）就是 g 的零点。教材用有限差分近似导数，代码保持这一教学实现：

```scheme
(define dx 1e-5)
(define (deriv g)
  (lambda (x) (/ (- (g (+ x dx)) (g x)) dx)))
```

`deriv` 是“过程→过程”，不是求某一点导数的最终数值；`((deriv cube) 5)` 才产生约 75.00015，真导数为 75。这是**数值求导**，不同于第二章的符号求导。

`newton-transform` 返回执行 `x-g(x)/g'(x)` 的过程，`newtons-method` 再把它交给 fixed-point。完整代码在生成变换时建立导数过程，以免每一步重复生成；斜率为零且函数非零时报错，当前已是零点则保留它。

```text
g(y)=y²-2
    ↓ newton-transform
y ↦ y-(y²-2)/(2y) = (y+2/y)/2   （精确导数时）
    ↓ fixed-point，从 1 开始
√2 的近似值。
```

可以把两种方法统一写成：

```scheme
(define (fixed-point-of-transform g transform guess)
  (fixed-point (transform g) guess))
```

平方根的一种 g 是 `y↦x/y`，transform 为 average-damp；另一种 g 是 `y↦y²-x`，transform 为 newton-transform。二者的**输入函数含义不同**，不能只交换 transform 而不检查 g。

代价与限制：牛顿法通常在简单根附近、初值足够好时二次收敛，但也能跳离根、遇到零导数或循环；固定 dx 的有限差分有截断误差，dx 太小又有相消误差，大尺度时 `x+dx` 甚至等于 x。这里只在中等尺度例子展示通用数值求导，不声称比 01.02 的专用稳定更新更适合极端输入。

## 6. 习题 1.46：提取 iterative-improve

**题意概述**：把“判断当前猜测是否足够好，否则改进再继续”提取成接受两个过程的 iterative-improve；它返回接受初始猜测的过程。再用它重写平方根和不动点。

### 通用引擎

教材接口的 `good-enough?` 接受**当前猜测一个参数**，本解保留这个约定：

```scheme
(define (iterative-improve good-enough? improve)
  (lambda (first-guess)
    (define (iter guess)
      (if (good-enough? guess)
          guess
          (iter (improve guess))))
    (iter first-guess)))
```

实际文件再加有限实数验证和 4096 次改进上限。若初猜已满足条件，不应调用 improve，自检用一个会报错的 improve 验证这一点；若循环不收敛，明确抛错，而不是挂起或假装返回答案。

这个引擎不知道平方根、不动点或导数，只知道两个参数过程各自的职责。它是尾递归组织，迭代 k 步时控制空间 Θ(1)，成本是 k 次判断加不超过 k 次改进的实际成本，不是所有函数都能写成固定的 Θ(log n)。

### 平方根答案

对非零、非负、可表示的有限实数 x，使用

```text
improve(y)=y/2+(x/y)/2
good-enough?(y)=相对接近(y,improve(y))。
```

然后调用 `((iterative-improve good-enough? improve) 1.0)`。`x=0` 直接返回 0，负数拒绝。采用与 01.02 一致的纯相对判据，避免 tiny x 被固定绝对容差草率接受；对 `1e-300` 和 `1e300` 也做实际自检。此接口返回满足判断的当前猜测；它与下一猜测已相对接近，都能满足本例误差要求。

### 不动点答案

用 `improve=f`，用 `good-enough?(y)=close?(y,f(y))`；先由 iterative-improve 得到合格的当前猜测，再返回 `f(current)`，保持原书 fixed-point 返回 next 的习惯。

通用 `close?` 使用混合阈值：

```text
|a-b| ≤ 1e-12 × max(1,|a|,|b|)。
```

尺度大于 1 时主要是相对容差，小于 1 时是绝对容差，使趋近零的序列也能停止。但它不保证极小非零答案的相对精度，所以专用平方根不能盲目复用这个判据。

为忠实保留题目“一元判断、先判断再改进”的接口，未收敛步骤的 f 通常算两次：判断中一次，更新中一次；最后判断通过后再算一次 f 作为返回值。这里假定 f 纯且确定，故值语义一致，代价是重复求值。若 f 昂贵，可让迭代状态显式保存 `(current,next)` 再使用同一个引擎；本单元不引入缓存状态或另一套接口来掩盖这个取舍。

相邻值接近通常检查的是迭代残差，不是“离真解距离小于相同容差”的自动证明。若有收缩常数 q<1，才可推得相应的距离界，例如 `|x-r|≤|f(x)-x|/(1-q)`；q 很接近 1 时差别显著。程序的步数保护也只保证及时失败，不能替代收敛证明。
