## 1. 程序可以处理“名字本身”

```scheme
(define x 10)
(list x 3)        ; (10 3)：先求值 x
(list 'x 3)       ; (x 3)：保留符号 x
'(+ x 3)          ; 一个列表，不调用 +，也不查 x 的数值
```

`'e` 是 `(quote e)` 的 reader 缩写。它不是字符串；`'x` 是符号，`"x"` 才是字符串。`eq?` 适合比较符号，比较复合表达式结构用 `equal?`，不能把它们和数值 `=` 混用。

一个值得展开的例子：

```text
''x = (quote (quote x))
其值是列表 (quote x)
(car ''x) → quote
```

引用之后的 `(+ x 3)` 是**描述加法的语法树**。我们的求导器处理这棵树，输出另一棵树；它不运行任意 Scheme 源码，也不调用宿主 `eval`。Lisp 的表示让“程序式样的数据”很自然，但运行中的过程值不是源代码列表的同义词。

## 2. 核心算法与表示接口分开

对变量 x 求导，基础规则是：

```text
D(c) = 0
D(v) = 1（v=x），否则 0
D(u+v) = D(u)+D(v)
D(uv)  = u D(v)+D(u) v
```

每条复合规则都把问题缩小到子表达式。它只需知道“是不是和/积”“左右部分是什么”“怎样构造和/积”，不必知道操作符在列表第一个还是第二个位置。

文件用一个小的 `make-differentiator` 工厂把规则共享给三个表示版本。它接收 `view` 与构造器，返回 `deriv`；`view` 是把教材的谓词和左右选择器合在一起，返回 `(operator left right)`。因此 `view` 第一项决定 `sum?`/`product?`，第二、三项分别提供 `addend`/`augend` 或 `multiplier`/`multiplicand`，不是绕开抽象接口另写三套规则。

构造器还做局部化简：`0+a=a`、`a+0=a`、`0a=0`、`1a=a`，两个数字可直接计算。化简只发生在构造处，不散布在求导规则里。

例如：

```text
D((* x y), x)
→ make-sum(make-product(x, D(y)), make-product(D(x), y))
→ make-sum(make-product(x, 0), make-product(1, y))
→ make-sum(0, y)
→ y
```

输出 `(+ x x)` 不自动变成 `(* 2 x)`。这是局部代数简化，不是完整计算机代数系统；等价的树可能长得不同。

## 3. 习题 2.56：加入幂和链式法则

**题意概述**：用 `**` 表示幂，增加幂的识别/选择/构造与求导分支，并简化 0 次、1 次幂。

前缀表示为 `(** base exponent)`：

```scheme
(define (exponentiation? e)
  (and (pair? e) (eq? (car e) '**)))
(define base cadr)
(define exponent caddr)
```

构造器遇到指数 0 返回 1、指数 1 返回底数；其他情形返回幂表达式，或在底数/指数均为数字时计算数值。按题目要求，`(** 0 0)` 在这个形式代数约定下也被简化为 1；这不是给所有分析学中的极限不定式定值。

求导分支也必须先处理数字零指数，直接返回 0：`D(0^0)=D(1)=0`。不能先构造一般公式 `0 × 0^(-1) × D(0)` 再期待乘零化简；Scheme 会先求过程参数，尚未进入乘积构造器就因计算 `0^(-1)` 报错。自检明确覆盖 `(deriv '(** 0 0) 'x)`，而不只检查符号底数 `x^0`。

规则是：

```text
D(u^n) = n × u^(n-1) × D(u)，n 与求导变量无关
```

文件用 `constant-exponent?` 检查指数对当前变量是常量，支持数字、符号 n 和不依赖当前变量的合法表达式；`n-1` 用和构造器表达为 `(+ n -1)`，不能直接对符号调用宿主 `-`。

```text
D((x+1)^3)
→ 3 × (x+1)^2 × D(x+1)
→ 3 × (x+1)^2 × (1+0)
→ (* 3 (** (+ x 1) 2))

D(x^n,x) → (* n (** x (+ n -1)))
```

乘上 `D(u)` 不能省：若底数是 `(* 2 x)`，这个因子就是 2。若输入 `(** x x)`，指数依赖 x，文件明确拒绝；一般变指数公式需要 `ln` 和除法，属于另一条规则而不是把常指数公式硬套上去。实数分数/负指数还有定义域约束；输出是规则适用域内的形式导数，不是对任意点都有定义的保证。

## 4. 习题 2.58(a)：完全括号化的二元中缀

**题意概述**：支持 `(x + (3 * (x + (y + 2))))`，`+`、`*` 总是二元。

这时每个复合表达式仍是三项列表，只是操作符在第二项。完整表示接口可写成：

```text
sum?(e)     = e 是三项列表且 cadr(e) 是 +
product?(e) = e 是三项列表且 cadr(e) 是 *
left(e)     = car(e)
right(e)    = caddr(e)
make-sum(a,b)     = 局部简化，否则 (list a '+ b)
make-product(a,b) = 局部简化，否则 (list a '* b)
```

文件的 `binary-infix-view` 返回 `(cadr(e), car(e), caddr(e))`，`deriv-infix-a` 使用中缀构造器，规则引擎不变：

```text
D(x + (3 * (x + (y + 2))))
= 1 + [3 × (1 + (0+0)) + 0 × (x+(y+2))]
= 4
```

若没有正确的构造器，输入虽然是中缀，输出却会混入前缀；所以“只改操作符位置的识别”不是完整解答。此版本拒绝 `(x + x + 1)`，因为它不满足二元全括号协议。

## 5. 习题 2.58(b)：乘法优先，括号只在必要处保留

**题意概述**：处理 `(x + 3 * (x + y + 2))` 这种通常数学写法。

输入已经由 Scheme reader 读成列表，不是需要自行分词的字符串。内部列表就是显式括号分组。核心是找出当前表达式的**最低优先级、最外层运算**：

1. 检查当前列表按“操作数、操作符、操作数……”交替排列且非空。
2. 只扫描当前列表的顶层元素，不深入子列表寻找分隔符。
3. 顶层有 `+` 就在第一个 `+` 分开；没有 `+` 再找 `*`。
4. 分隔符两侧若只有一项，就取出该项；多项则保留为一个中缀子表达式。
5. 若整个列表只含一项，作为额外括号分组，递归处理里面的表达式。

“先找加号”不是让加法先求值，而是把加法识别成语法树的根，乘法留在子树中先结合。

```text
输入 (x + 3 * (x + y + 2))
顶层列表：x，+，3，*，一个子列表
根是 +
  左：x
  右：(3 * (x + y + 2))
        根是 *
          左：3
          右：(x + y + 2)
                根是 +，左 x，右 (y + 2)
```

依次应用同一组导数规则，仍得 4。另一个避免“样例刚好都是常量”的检验：

```text
D(x * x + x * 3, x)
→ D(x*x) + D(x*3)
→ (x+x) + 3
输出：((x + x) + 3)
```

全括号输出本身也是合法的“可省略多余括号”中缀表达式。因此构造器仍用二元中缀列表是正确的；不必为了外观最短再写 pretty printer。连续 `+` 或 `*` 选择第一个分隔符会右结合，这对这里的形式和/积按结合律等价；它不是对浮点逐位结果或减法/除法结合性的承诺。

该表示只包含题目要求的 `+`、`*` 和分组，不把减法、除法、一元负号和中缀幂的优先级悄悄混入。负数字如 `-2` 已经是 reader 的一个数值 token，可以作操作数。`(x +)`、`(x - 2)` 会报错。

### 时间与扩展边界

扫描顶层分隔符用线性时间，长而偏斜的平坦表达式在递归选择时可能反复扫描后缀，最坏平方时间。它是题目的最小可运行表示层；大型表达式可先解析为固定 AST，再让选择器常量时间访问，但此处不为教学样例额外建立完整 parser 框架。求导产生的新表达式也可能增长，不能只数原始节点就概括全部成本。
