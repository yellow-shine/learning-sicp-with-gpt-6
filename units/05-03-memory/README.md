# 05.03 向量存储与复制式回收：地址会变，身份不应变

## 1. 两个向量就是一片 pair 存储

令指针 p_i 表示第 i 个 pair。`the-cars[i]` 是它的 car，`the-cdrs[i]` 是它的 cdr。选取是向量读取，赋值是向量写入，`cons(a,d)` 在 free 处写两格，再令 free 加一。

必须区别 `n1`（数值 1）与 `p1`（地址 1）。脚本用 `(p . 1)` 表示后者，普通数、符号和空表直接作为原子。p 标签是这套教学堆保留的元数据，不允许把任意宿主 `(p . i)` 当普通原子存进去。

地址是表示细节；上层 append 控制器只见 `cons/car/cdr/set-cdr!` 操作表，因此可以不改控制器而换存储方式。这正是第二章数据抽象屏障落实到机器的例子。

## 2. 5.20：共享 pair 的盒指针图与向量图

**题意**：从 free=p1 开始执行 `x=(cons 1 2)`、`y=(list x x)`，画结构和向量，并给出 x、y、free。

```text
          ┌───────────────┐
x ───────→│ car=1 | cdr=2 │  p1
          └───────▲───────┘
                  │        两条边都指向同一个 p1
           ┌──────┴──────┐
y ───→ [ p1 | ● ] ───→ [ p1 | () ]
          p3               p2
```

分配次序显式选为：先 x，再 y 的尾 pair，最后 y 的头 pair。于是：

| 索引 | the-cars | the-cdrs |
| --- | --- | --- |
| 1 | n1 | n2 |
| 2 | p1 | 空表 |
| 3 | p1 | p2 |

**x=p1，y=p3，free=p4**。只有三个 pair，不是四个：`list` 为两个元素分配两个脊柱格子，不复制元素对象 x。y 的两个 car 在身份上相同，不只是内容相等。

若实现以头到尾次序分配 list 脊柱，y 可为 p2、其尾为 p3，free 仍为 p4，图同构。Scheme 并不规定 `list` 的内部格子分配顺序；这里采用与从右向左嵌套 cons 对应的布局，并在代码里明确顺序，避免把地址编号误当语言语义。

## 3. 5.22：非破坏性 append 的机器

**题意**：为第三章的 `append` 和 `append!` 分别设计控制器，假设 pair 操作可作机器原语。两份完整控制器均在脚本中，并且实际接到上述向量堆运行。

非破坏性版本的递推是：x 为空返回 y，否则 `cons(car(x), append(cdr(x),y))`。用 x、y、head、val、continue：

```text
append-loop:
  x为空？是 → val←y → goto continue
  否 → save continue；head←car(x)；save head
       x←cdr(x)；continue←after-append；goto append-loop

after-append:
  restore head；restore continue
  val←cons(head,val)；goto continue
```

对于 x=(a b)、y=(c d)：下降时保存 a、b；基例 val 指向原 y；返回时先分配 `(b . y)`，再分配 `(a . 新尾)`。复制的是 x 的脊柱，不是 x 的元素，也不是 y。时间 Θ(|x|)，新分配 |x| 个 pair，最大栈深 2|x|；x 的别名不变，结果尾部与 y 共享。

若要不使用栈，也可以反转后累积，但会增加遍历或分配；本题保持教材递归过程的直接机器化，不为避免栈而改算法。

## 4. 5.22：破坏性 append! 的机器

`append!-controller` 先把原 x 保存到 val，用 x 沿 cdr 链找最后一格，令其 cdr 指向 y，然后返回 val。只需要 x、y、next、val 和空表测试/选取/写入通路，不用栈。

```text
val←原x
loop: next←cdr(x)
      next为空？否 → x←next → loop
                是 → set-cdr!(x,y) → done
```

对于 x=(a b)，`alias=x`：拼接后 alias 也读到 `(a b c d)`，因为不是复制 x，而是修改原来 b 所在格子的 cdr。时间 Θ(|x|)，额外空间 Θ(1)，新分配 0 个 pair。两种版本都共享 y；非破坏性不等于“结果没有任何共享”。

教材通过 last-pair 实现的 append! 要求 x 非空。本实现额外定义 `append!([],y)=y`，并明确这是空输入扩展，不声称修改了空表。脚本检查空/空、空/非空、非空/空和普通情况。输入域是有限 proper list；如果 x 有环，遍历不会结束。如果 y 已指向 x 的内部，拼接可能造环，这是破坏性操作的真实别名风险，不是 GC 能消除的逻辑错误。

## 5. Stop-and-copy：可达性代替“未来还会不会用”

无法一般地判断一个对象以后是否还会被使用，但可以保守地保留**从根可达**的一切。根必须包括存着指针的寄存器、全局环境、闭包、栈等。只登记全局变量会把仍在栈上的值误当垃圾。

教材把内存分成 from-space 和 to-space。停下用户计算后：

1. 把根指向的 pair 搬到新空间，在旧 car 写 broken heart，旧 cdr 写新地址。
2. 新空间 `[起点,scan)` 已扫描，`[scan,free)` 已复制但子指针尚未全部修正，free 后未使用。
3. 扫描一个新 pair 的 car、cdr。原子直接返回；旧指针若已被标记就使用转发地址，否则复制并设置转发。
4. scan 向前走，直到 scan=free；交换新旧空间角色，再继续分配。

**先设置转发再继续扫描**保证同一对象只复制一次，也使环不会造成无限递归。教材预先分配并复用两个半空间，复制与扫描成本是 Θ(存活 pair 数 + 根数)，不遍历不可达垃圾；代价是预留另一半空间、暂停时间，以及必须完整更新根。压缩后存活对象连续，有利于局部性，但地址会改变。

本脚本为直观展示新旧空间，每次 `collect` 都用 `make-vector` 新建并填充两个容量为 capacity+1 的向量，另有 Θ(capacity) 初始化成本。因此本实现一次回收的总成本为 Θ(capacity + 存活 pair 数 + 根数)，即使根集为空，也不会跳过容量大小的初始化。若要获得教材的纯存活量回收成本，应预先分配并循环复用两个半空间；这里不把教材的遍历界误当成当前脚本的全部成本。

## 6. 手工追踪教材算法：搬迁 5.20 的共享图

这里使用教材 §5.3.2 的 scan/free/转发规则，输入图选用刚完成的 5.20，并非声称教材图 5.15 指定了这些数字地址。只以 y 为根，新空间也从 1 开始：

| 动作 | scan | free（下一空位） | 新空间/转发变化 |
| --- | ---: | ---: | --- |
| 搬旧 p3（y）到新 p1 | 1 | 2 | 旧3→新1；新1 暂为 (旧1 . 旧2) |
| 扫新1 的 car，搬旧1 到新2 | 1 | 3 | 旧1→新2；新2=(1 . 2)；新1.car=新2 |
| 扫新1 的 cdr，搬旧2 到新3 | 1 | 4 | 旧2→新3；新3 暂为 (旧1 . 空) |
| 扫新2：两边都是原子 | 2 | 4 | 不分配 |
| 扫新3.car：旧1 已有 broken heart | 3 | 4 | 直接写新2，不再复制 |
| scan 前移到4 | 4 | 4 | 完成，根改为新1 |

新1.car 和新3.car 都是新2，共享关系不变。如果忘记转发，旧1 会复制两次，修改一份后另一份不变，程序语义就坏了。

脚本还加入一个不可达 pair、一个自环，并把 y、x、自环作为**多个根**。实际搬迁顺序为旧3→新1、旧1→新2、旧5→新3、旧2→新4；free=5，垃圾没有被搬走。第二次回收仍保持环，原子根不分配，空可达集回收全部 pair。

## 7. 运行与边界

```sh
racket units/05-03-memory/solutions.rkt
```

输出 5.20 的两个向量、有限转发表和 `05.03: all checks passed`。断言检查分配地址、共享、别名、两种 append 的分配数和尾部身份、回收后的环与多根关系、重复回收、堆满与非法指针错误。

这是可执行的教学堆，不是 Racket 的 GC 替代品：模拟 pair 位于向量，表示标签和辅助表仍由宿主内存管理。GC 算法用宿主循环显式实现 relocation 和 scan，而 append 两种算法由机器指令执行；没有把宿主 `append` 作为待测算法。为了让根集责任可见，堆满时抛错，调用者显式 `collect` 并接收更新后的根，不自动猜测宿主局部变量里的指针。不要保留回收前的外部地址继续使用；本教学表示不提供跨回收代数的悬空指针检测。

**已回答回顾**：回收依据是可达性，不是引用计数，所以可达环保留、不可达环可回收；对象身份靠转发关系保留，而不是固定地址；非破坏性 append 复制 x 脊柱，append! 改原脊柱。下一单元把环境和过程对象交给显式控制求值器，但为隔离控制机制，它继续使用宿主 pair，不把这套演示堆强接入整个运行时。
