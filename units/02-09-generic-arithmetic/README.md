## 1. 问题：统一接口不代表所有数都压成一种表示

客户希望写 `(add a b)`，而不是先分辨 a、b 是有理数还是复数。但如果简单把一切都转成浮点数，会丢失精确性和代数结构。通用算术让外层只依赖操作名，再把实际工作交给对应类型包。

```text
add / sub / mul / div / =zero?
                ↓ 操作表按参数标签分派
scheme-number      rational            complex            polynomial
宿主实数           分子/分母            内层表示标签         变量/项表
                                           ↓                 ↓ 系数再次通用分派
                                     rectangular / polar    标量或多项式
```

本实现保留显式标签，包括普通数：

```text
(scheme-number . 2)
(rational . (1 . 2))
(complex . (rectangular . (3 . 4)))
(polynomial . (x . ((2 <系数>) (0 <系数>))))
```

这与习题 2.78 的“让原生数字不再显式带标签”是不同选择；2.78 不在代表题中，不混用两套协议。

为避免宿主已经支持复数而绕过教学分派，这里的 `scheme-number` 明确限制为**有限宿主实数**，仍可包含精确整数、精确分数、非精确实数。复数必须经 `make-complex`。`rational` 要求精确整数分子、非零精确整数分母，规范化符号和 GCD；和 02.01 一样，不接受 `1.0` 假冒精确分子。

## 2. 方法调用只剥掉当前一层标签

```scheme
(define (add x y) (apply-generic 'add x y))
(define (=zero? x) (apply-generic '=zero? x))
```

操作表有如 `(add,(rational rational))` 的条目。找到方法后才 `map contents`，所以有理数加法收到两个裸 `(numer . denom)`，结果由构造器重新加标签；谓词返回布尔值，不给 `#t/#f` 再包装成“数”。

复数多了一层内部表示：

```text
magnitude(complex(rectangular(3,4)))
→ 按 (magnitude,(complex)) 找方法
→ 去 complex 标签，传 rectangular(3,4)
→ complex 方法调用通用 magnitude
→ 按 (magnitude,(rectangular)) 找方法
→ 去 rectangular 标签，传裸 (3,4)
→ sqrt(3²+4²)=5
```

两次分派分别解决“这是哪类数”和“这类数的哪种表示”，不是重复劳动。不能一开始把所有标签都去掉，否则复数包就无法区分直角/极坐标。

本单元复数加减乘除采用直角坐标公式（乘积为 `(ac-bd)+(ad+bc)i`），但选择实/虚部仍经 02.08 的内层分派，因此可处理两种内层表示。选择直角结果能让精确实/虚输入的示例保持精确，避免无必要的三角函数往返；不改变多重表示机制。

## 3. 混合类型：先找精确签名，再尝试转换

若 `(add,(scheme-number complex))` 没有专用方法，就尝试把普通数看成虚部为零的复数。

```text
add(scheme-number(2), complex(3,4))
→ 未找到精确签名方法
→ get-coercion(scheme-number,complex)
→ scheme-number(2) 转成 complex(2,0)
→ add(complex(2,0),complex(3,4))
→ 找到 complex 加法 → complex(5,4)
```

转换过程接收**完整带标签值**；算术方法接收**去掉一层标签的内容**。混淆这两个调用协议很容易把 `car` 用在错误层。

实际安装的方向为：

| 来源 → 目标 | 转换 |
| --- | --- |
| rational → scheme-number | 精确计算分子/分母，保留宿主精确商 |
| scheme-number → complex | 实部为该值、虚部 0 |
| rational → complex | 直接以精确商作实部，虚部 0 |

二元分派在没有直接方法时先尝试把第一个参数转成第二种类型，没有这种转换再反向尝试。若转换后同类型仍无方法，立即失败，不盲目搜索另一条路。安装包必须保证声明的转换确实产生目标标签；这里的有限可信安装表满足这个条件，不是允许外部任意注入转换过程的插件系统。

## 4. 习题 2.81：自转换不会创造缺失的方法

### (a) 安装 Louis 的 identity 转换后会怎样？

**题意概述**：Louis 给每种类型加入转换到自身的过程。若方法不存在会怎样？特别是只给普通数安装 `exp`，却对两个复数求 `exp`。

教材旧版在查不到方法时仍尝试强制转换：

```text
apply-generic(exp, complex z1, complex z2)
→ get(exp,(complex complex)) = #f
→ complex→complex 存在，返回原 z1
→ apply-generic(exp, complex z1, complex z2)
→ 同一个状态无限重复
```

自转换改变不了类型签名，因而无法让一个不存在的条目出现。这里的错误是**不终止**，不是一定栈溢出；尾调用可使它不断循环而不增长控制栈。

对两个 scheme-number：若操作是已安装的 `exp`，首次查表就成功，如 `2^3=8`，不会进入转换；若操作在该类型上缺失，同样陷入 identity 重试循环。是否循环取决于“对应方法是否存在”，不是仅取决于参数类型。

### (b) Louis 的判断正确吗？

不正确。没有自转换条目时，旧版对相同类型且方法缺失的参数，会发现两个方向都没有转换，正确报“无方法”。同类型不需要先转成自身，直接按同类型签名查方法已经完成了该做的工作。改进是阻止无进展的转换重试，不是补一批 identity 方法。

### (c) 修正 apply-generic

完整实现在文件开头，关键控制顺序为：

```text
1. 先查 (op, 全部参数标签)；找到就应用。
2. 没找到且恰有两个参数、标签不同时，才查两个转换方向。
3. 同标签或没有转换，直接报错。
```

同标签检查必须放在**方法查找之后**，否则 `(add rational rational)` 这样的合法调用会被拒绝。

自检故意安装 Louis 的两个 identity 转换，再调用复数 `exp` 和普通数未知操作；修正版都有限报错并被捕获断言。它不真的启动无限循环来“验证”旧版，而用上面的状态重复推导说明旧版的问题。

## 5. 类型塔：有用的全局结构，但不是语言现实的自动写真

教材提出的塔是：

```text
complex
   ↑ real → complex：补零虚部
real
   ↑ rational → real：解释为实数
rational
   ↑ integer → rational：n/1
integer
```

每层提供 `raise` 向上一层；混合参数先逐步提升较低层，直到标签相同，再查方法。还可以在当前层缺少操作时向上查找，从而让整数继承复数的实部等操作。因为等级严格上升且塔有限，提升有进展，不会发生自转换那种原地循环。

**提升与下降不对称**：任意实数都能补零虚部看成复数，但不能把任意复数丢掉虚部仍称为等值转换。若要 `drop` 简化结果，可先 `project` 到下一层，再 raise 回去，只有与原值相等时才继续下降。例如 `6+0i` 可降，`6+2i` 不可降。

需要特别区分数学包含关系与机器表示：

- 数学有理数是实数子集，但有限精度浮点数不能精确保存所有有理数。若 `raise` 到 real 就调用浮点转换，`1/3` 会发生信息损失。
- 本文件的 `scheme-number` 本身已包含宿主精确分数，不是教材四层塔中的纯 integer 或纯 real 类型。因此**实际代码实现的是上节三条直接转换，不是假称已经实现完整 raise/drop 类型塔**。
- 本分派只做二元、一条直接转换；不会自动寻找“两个类型都能转到的第三类型”，不会搜索多步路径，也不会替三个及更多参数规划公共类型。
- 同类型缺方法立即报错，是 2.81 的直接转换方案；若实现塔中“同类型但可向上继承操作”，需要另设有进展的提升逻辑，不能把这一 guard 不加区分搬过去。
- 一般类型图可能有多重父类型、转换环和多个候选公共类型；需优先级与歧义政策。类型塔只是每层至多一个上级的特例。

这些不是靠多加一条 `cond` 就能无原则解决的问题。自动转换越广，精确性、终止性与“用户到底想要哪个操作”的决定越重要。

## 6. 多项式：系数也可以是通用数据

一个 x 的稀疏多项式由变量和降序项表构成：

```text
p(x) = (1/2)x² + 1
变量：x
项表：((2 rational(1,2)) (0 rational(1,1)))
每项 = (order coefficient)
```

构造器要求变量是符号、阶数是非负精确整数且严格递减、系数支持通用零判断。显式零系数可以保留，以便验证零判断不是只看表空不空。重复阶数会被拒绝，不让两个同阶系数的抵消暗中破坏“逐项判断”的条件。

系数必须与当前变量无关。例如可以是 y 的多项式，但不能把仍以 x 为变量的多项式直接塞进 x 的系数。代码做保守的结构检查：递归系数中若再次出现主变量，就拒绝；即使嵌套的同名多项式恰好为零，也不试图借代数化简特判放行。

### 加法：有序项表归并

- 当前较高阶项直接接到结果前面。
- 同阶项通过通用 `add` 合并系数。
- 新系数若通用 `=zero?` 成立，就不加入这项。

这与 02.07 有序集合的归并有相同的结构，只是相等键不再简单去重，而要计算系数和。

### 乘法：分配律与项表加法

每个第一表项乘上第二表所有项，阶数用普通 `+` 相加，系数用通用 `mul` 相乘，再把各行部分积归并相加：

```text
((1/2)x²+1)²
第一行：(1/4)x⁴+(1/2)x²
第二行：(1/2)x²+1
归并 → (1/4)x⁴+x²+1
```

阶数是表示元数据，不需要通用数值标签；系数才是需要扩展的数据。这一条依赖边界决定了包能否接受复数、有理数或多项式系数。

### 数据导向递归

令 `xy` 是 x 的一次项，其系数是 y 的一次多项式。计算 `xy×xy`：

```text
mul(polynomial x, polynomial x)
→ 合并外层阶数 1+1=2
→ mul(系数 polynomial y, 系数 polynomial y)
   → 合并内层阶数 1+1=2
   → mul(scheme-number 1, scheme-number 1) → scheme-number 1
→ 外层结果：x²，其系数为 y²
```

没有专门写“二维多项式乘法”函数，递归层数由系数的标签决定。文件有这个完整计算的结构断言，不是只拿零多项式演示递归。

## 7. 习题 2.87：把多项式 =zero? 安装到通用系统

**题意概述**：让 `adjoin-term` 能处理系数本身为多项式的情况，安装多项式零判断。

在阶数互不重复的表示约定下，多项式为零，当且仅当所有系数为零；空项表自然是真：

```scheme
(define (zero-terms? terms)
  (or (null? terms)
      (and (=zero? (coeff (car terms)))
           (zero-terms? (cdr terms)))))

(put '=zero? '(polynomial)
     (lambda (p) (zero-terms? (cdr p))))
```

方法收到去掉标签的 `(variable . terms)`，所以它用 `cdr p` 得到项表。关键不是把 `zero-terms?` 起个“generic”的名字，而是系数检查调用真正查表的 `=zero?`。

```text
zero-y = y 的项表 ((3 rational(0,7)))
zero-x = x 的项表 ((5 zero-y))

=zero?(zero-x)
→ polynomial 方法 → 系数 zero-y 再走 =zero?
→ polynomial 方法 → 系数 rational(0,1) 再走 =zero?
→ rational 方法检查分子 = 0 → #t
→ 内层所有系数为零 → #t
→ 外层所有系数为零 → #t
```

于是 `(adjoin-term (make-term 7 zero-y) '())` 正确返回空表。若写成宿主 `(= coefficient 0)`，会把带标签的 pair 当数比较而报错；若只判断项表空不空，会误判显式零项。

不能通过“代入 x=0 看值是不是零”判断多项式恒零：`x²` 在 0 为零但不是零多项式。零判断也不是浮点近似阈值比较，擅自把很小非零系数删掉会改变代数值；本包采用各标量包的精确数值等零语义。

## 8. 表示与范围的真实限制

- 稠密多项式可只存系数序列，如 `(1 0 3)` 表示 `x²+3`；稀疏表示保存 `(order,coeff)`，适合 `x^100+1`。文件选择稀疏表，未实现 2.90 的两套项表通用分派。
- 多项式加法线性归并项表，但系数 `add` 本身可能很贵；乘法至少进行 mn 次系数乘法，另有部分积合并成本。不能把“系数一次操作”无条件当常量时间。
- 只安装同主变量多项式的 `add`、`mul` 与 `=zero?`。不同主变量相加明确失败；数字与多项式也没有自动“常数多项式嵌入”，因为必须先决定变量上下文。递归系数操作在双方类型存在方法或已安装转换时成立，并非任意嵌套表达式都能自动归一化。
- x 的多项式套 y 的系数，与 y 的多项式套 x 的系数可能代数等价，却不是天然的一上一下关系。统一变量顺序并展开重排可以规范化，但可能膨胀；这正是类型塔不适合所有符号代数的例子。
- 多项式减法、长除法、GCD 和有理函数约分不是本单元选题。其接口仍可沿同样路线扩展：长除法用首项消去递归产生商与余数；有理函数的分母不能是零多项式，约分依赖多项式 GCD，不能直接复用只接受整数的有理数构造器。

**已回答的本章总结**：

1. **谁能知道有理数的 pair 布局？** 构造/选择层；算术层只依赖分子分母接口。
2. **谁能知道求导表达式采用中缀？** 表示谓词、选择器和构造器；乘积法则本身不应改变。
3. **通用多项式为什么能递归处理系数？** 系数运算回到同一通用分派接口，标签决定调用标量还是多项式包。
4. **强制转换为什么需要限制？** 没有进展会循环，丢失信息会破坏等值，过多候选会产生歧义。
