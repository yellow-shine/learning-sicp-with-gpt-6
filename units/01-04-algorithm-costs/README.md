## 1. 不仅少保存工作，还要少做工作

把线性求幂改成尾递归，只把控制空间从 Θ(n) 降到 Θ(1)，乘法仍做 n 次。真正减少步骤需要利用数学结构：`b^(2k)=(b^k)²`。例如 `b^8` 可按 `b² → b⁴ → b⁸`，三次乘法完成。

教材的递归快速幂在偶数分支只递归一次，再平方返回值；若写成两个相同的递归调用相乘，计算树会重复，失去对数步骤的好处。递归快速幂时间 Θ(log n)、控制空间 Θ(log n)；下一题把状态也压缩。

## 2. 习题 1.16：用不变量设计迭代快速幂

**题意概述**：用连续平方设计对数步数的迭代求幂，利用额外状态 `a` 保持 `a*b^n` 不变。

初始状态 `(a,b,n)=(1,B,N)`，目标值为 `B^N`：

| 条件 | 新状态 | 不变量验证 |
| --- | --- | --- |
| n=0 | 返回 a | a·b⁰=a |
| n 为正偶数 | (a,b²,n/2) | a·(b²)^(n/2)=a·bⁿ |
| n 为奇数 | (a·b,b,n-1) | (a·b)·b^(n-1)=a·bⁿ |

```scheme
(define (iter a b n)
  (cond ((= n 0) a)
        ((even? n) (iter a (* b b) (/ n 2)))
        (else (iter (* a b) b (- n 1)))))
```

算 `2^10`：

```text
(1,2,10) → (1,4,5) → (4,4,4)
         → (4,16,2) → (4,256,1) → (1024,256,0) → 1024。
```

正奇数减一后成为偶数，所以下一步至少能减半；每两步最多只剩一半量级。时间 Θ(log n)，常量个数值状态；若计入 `n=0` 可写 Θ(log(n+1)+1)。对这份具体实现，`n>0` 的乘法次数是 `floor(log₂ n)+popcount(n)`，因为每个非最高位产生一次平方、每个 1 位产生一次乘入累积器。例如 `n=1000` 有 9 次平方、6 次乘入，共 15 次；教材另一种实现提到的 14 次不能不加区别地搬过来。

指数域为精确非负整数，底数允许整数、分数、负数等数值；`n=0` 返回乘法单位元 1，包括算法约定的 `0^0=1`，不是在裁定所有数学上下文中的 `0^0`。负指数不在本题算法域，显式拒绝。

## 3. Euclid：保持共同除数不变

写 `a=q*b+r`。若 d 同时整除 a、b，就整除 `a-q*b=r`；反过来，整除 b、r 也就整除 a。因此：

```text
gcd(a,b)=gcd(b,remainder(a,b))。
```

正数输入的第二个参数严格减小，最终变零；`gcd(a,0)=a`。教材的尾递归 GCD 在应用序下只保留两个参数，额外控制空间 Θ(1)。最坏余数步数是 Θ(log min(a,b))（正输入、略去常数小值）；连续 Fibonacci 数接近最坏情况。某些输入一步就结束，所以不能宣称**每一对**输入都花 Θ(log min(a,b)) 步。`gcd(0,0)=0` 是程序约定，数学上的“最大正公约数”在此并不存在。

## 4. 习题 1.20：同一源码，为什么会是 4 次或 18 次？

**题意概述**：按应用序与教材正则序代换规则分析 `(gcd 206 40)`，明确实际执行的 `remainder` 次数。`if` 仍只求谓词与选中的分支。

### 应用序：先算好余数再传参

```text
gcd(206,40)
→ gcd(40,6)   ; remainder(206,40)，第 1 次
→ gcd(6,4)    ; remainder(40,6)，第 2 次
→ gcd(4,2)    ; remainder(6,4)，第 3 次
→ gcd(2,0)    ; remainder(4,2)，第 4 次
→ 2。
```

条件测试拿到的已经是数值。共 **4 次**余数运算。

### 正则序：表达式被复制，不是值被缓存

为了不写满一页括号，下面的 `R1…R4` 是**表达式缩写，不是会记住数值的变量**：

```text
R1 = rem(206,40)                  值 6
R2 = rem(40,R1)                   值 4
R3 = rem(R1,R2)                   值 2
R4 = rem(R2,R3)                   值 0

gcd(206,40)
→ gcd(40,R1)
→ gcd(R1,R2)
→ gcd(R2,R3)
→ gcd(R3,R4)
→ R3。
```

在每次进入 `gcd` 时，`(= b 0)` 必须得到 b 的数值，但测试不会把参数表达式全局替换成这个数值。之后展开下一次调用仍会携带原表达式；这里没有按需共享。

令 C(R) 为单独归约一次表达式 R 的余数次数，常量的 C 为零：

```text
C(R1) = 1
C(R2) = 1+C(R1) = 2
C(R3) = 1+C(R1)+C(R2) = 4
C(R4) = 1+C(R2)+C(R3) = 7。
```

例如 `R3=rem(rem(206,40), rem(40,rem(206,40)))`，外层 1 次、左边 1 次、右边 2 次，共 4 次。

| 当前调用参数 | 为条件求 b 的成本 | 条件结果 |
| --- | --- | --- |
| 206,40 | 0 | 假 |
| 40,R1 | 1 | 假 |
| R1,R2 | 2 | 假 |
| R2,R3 | 4 | 假 |
| R3,R4 | 7 | 真 |

条件总共 `0+1+2+4+7=14` 次。真分支返回 a，即 R3；为取得最终数值又计算 4 次，所以总共 **18 次**。常见的 14 次错误来自漏算最终返回值；4 次答案则相当于偷偷给表达式加了共享。

可运行题解中，应用序直接调用 GCD；正则序的参数用**不缓存的零参数过程**表示，每次需要都调用它，以局部计数器统计真正执行的余数。断言得到 `(答案 次数)=(2 4)` 与 `(2 18)`。这是针对本题需求位置的可执行佐证，不是把宿主 Scheme 改成正则序，也不是完整求值器。`set!` 只用于计量；带状态语义第三章再系统解释。

## 5. 习题 1.22：找出素数，然后诚实地测时间

**题意概述**：写指定区间内的连续奇数素性搜索，找出分别大于 1000、10000、100000、1000000 的前三个素数；记录测试时间，讨论是否支持 Θ(√n) 预测。

### 试除机制和边界

若 `n=d*q` 是合数，不可能 d、q 都大于 √n。因此从 2 试到 `d²>n` 即可；要用 `>`，因为 `d²=n` 时 d 仍可能是除数。程序保留教材的 `2,3,4,…` 试除顺序，不把优化后的奇数除数算法与本题计时混在一起。

`prime?` 在 `n<2` 或输入不是精确整数时返回假；否则查找最小除数。对素数 n，余数运算次数恰为 `floor(√n)-1`，时间 Θ(√n)；合数可能早停，例如偶数只需要一次。因此它是最坏界，不是每个候选都需要这么多次。

`search-for-primes` 的上下界都包含在内，仅枚举奇数（按题意，2 不在此搜索接口内，但 `prime? 2` 为真）。文件用足够窄的四个区间实际扫描，断言结果恰好如下；绝非直接返回这个表：

| 严格大于 | 前三个素数 | 各素数的余数次数 |
| --- | --- | --- |
| 1000 | 1009、1013、1019 | 30、30、30 |
| 10000 | 10007、10009、10037 | 99、99、99 |
| 100000 | 100003、100019、100043 | 315、315、315 |
| 1000000 | 1000003、1000033、1000037 | 999、999、999 |

从下界到第三个素数的每个奇数都检查过，所以这证明它们是前三个，不只是随手找到三个素数。

### 一次实际运行的记录

`timed-prime-test` 测量素性计算后才打印，不把输出时间算进去。相比教材，失败候选不打印以保持日志短。`#lang sicp` 的 `runtime` 用微秒单位，但计时分辨率与系统噪声使一次调用常显示 0；这不表示零成本。另做每个素数 200 次的短批量测量，报告每次均值，减少时钟量化影响。

同一量级三项均值约为 `0.118、0.448、1.402、3.833 µs`，相邻比约 `3.79、3.13、2.73`。操作数比为 `3.30、3.18、3.17`，逐渐接近 √10≈3.162。计时大体支持随 √n 增长，但微小计时不精确支持每一档固定倍率；循环、计时和记录计数有固定开销，运行时/JIT、调度、缓存也会影响数据。

**完整回答比较问题**：10000 对 1000 的观测倍率略大，100000 对 10000 接近预测，1000000 对 100000 略小；这与“足够大时主要时间近似随步骤数增长”的模型相容，不是其证明。不能把某次微秒比值硬编码为测试断言；本单元只断言结果和确定性操作次数，时间只报告。

## 6. Fermat：更少步骤换来的不是同一种保证

Fermat 小定理：素数 n 对每个 `1≤a<n` 有 `a^n mod n=a`。`expmod` 用平方求幂，而且每次乘法后取模，不先算出巨大 `a^n`。一次测试需要 Θ(log n) 次模算术；递归版本空间 Θ(log n)，t 轮时间 O(t log n)。

随机选 a，不满足等式可**确定是合数**；满足只说明没有在这一轮找到反例。`561=3×11×17` 是 Carmichael 数，所有合法 a 都通过这条 Fermat 检验；程序实际枚举 1–560 验证，同时试除认出 561 为合数。不能声称重复 Fermat 任意多轮就能对所有合数把错误率压到任意小，更不能移用 Miller–Rabin 的误判上界。零轮“通过”仅表示没发现反例，不是已证明素数。

“概率测试的假阳性上界”通常指给定合数时随机基底导致误接收的概率，也不是没有先验条件的“通过后为素数的概率”。

最后，Θ(log n) 是**模运算次数**。n 的输入长度约为 `L=log₂ n` 位，试除 Θ(√n) 对 L 是指数级；模幂的乘法、取余也不是对任意长整数的常量时间。这一成本模型层次要和 01.03 的大整数说明一致。
