## 1. 要解决的问题

你会用 Go 写函数，但“函数调用会先算参数”平时常常是默认常识。SICP 要把这类默认常识变成**明确的规则**。

本单元不是训练你记括号，而是回答：

> 给定一段程序，不靠运行，你能根据规则解释它将做什么吗？

先看两个表达式，暂时不要执行第二个：

```scheme
(if (= 0 0) 0 (/ 1 0))

(define (choose x y)
  (if (= x 0) 0 y))
(choose 0 (/ 1 0))
```

它们看似都“在 x 为 0 时返回 0”，但一个返回 0，另一个会在调用过程体之前除零。整节课就是要把这个差别讲透。

## 2. 最少的语法，明确的规则

### 2.1 基本元素、组合与抽象

SICP 从三种能力观察一种语言：

| 能力 | Scheme 例子 | 作用 |
| --- | --- | --- |
| 基本元素 | `3`、`+`、`*` | 数值和已有操作 |
| 组合手段 | `(+ 3 (* 2 4))` | 用简单表达式组成复杂表达式 |
| 抽象手段 | `(define (square x) (* x x))` | 给计算模式命名，之后不必每次展开细节 |

普通调用写作：

```scheme
(操作符 操作数1 操作数2 ...)
```

例如 Go 的 `square(3)` 在这里写成 `(square 3)`。没有逗号，括号也不是可有可无的分组符：`(square)` 表示零参数调用，`square` 才是取得过程值。

```scheme
(+ 2 3 4)            ; 9：+ 接受多个参数
(* (+ 2 3) (- 7 4))  ; 15：组合式可以嵌套
(/ 1 2)              ; 1/2：精确有理数，不是 Go 的整数除法结果 0
```

`;` 后是注释。本课程代码文件的第一行 `#lang sicp` 告诉 Racket 采用哪种语言，不是教材中的求值表达式。

### 2.2 普通组合式怎样求值

对一个**普通过程调用**：

1. 求值操作符表达式和操作数表达式。
2. 操作符位置的结果必须是可调用的过程。
3. 把这个过程应用到已经得到的参数值。

例如：

```text
(* (+ 2 3) (- 7 4))
→ (* 5 3)
→ 15
```

这里用一条轨迹展示计算依赖，不是在规定所有 Scheme 实现都从左到右算参数。SICP 所用 Scheme 的普通调用不提供统一的左右顺序保证；**参数先于过程体求值**和**参数之间谁先求值**是两个问题。本单元的算术题不依赖左右顺序。

### 2.3 命名与过程定义

```scheme
(define a 3)
(define b (+ a 1))

(define (square x)
  (* x x))
```

- `a` 关联到 3；定义 `b` 时算出 4，再把 `b` 关联到 4。它不是保存着一个会随时重算的电子表格公式。
- 定义 `square` 时建立一个过程；**不是当场执行 `(* x x)`**。
- `x` 是形式参数，调用 `(square 5)` 时实际参数值是 5。
- 环境负责关联名字和值。完整的环境图和带状态闭包留到第三章。

`define` 是特殊形式，不能按普通调用规则先把所有位置都求出值；否则第一次定义 `a` 时，求值器反而要先找到尚不存在的 `a`。

### 2.4 代换模型：一种推理工具

```scheme
(define (sum-of-squares x y)
  (+ (square x) (square y)))
```

对于本单元的纯过程，可以先算参数，再在过程体中用参数值替换对应形参：

```text
(sum-of-squares (+ 1 2) 4)
→ (sum-of-squares 3 4)
→ (+ (square 3) (square 4))
→ (+ (* 3 3) (* 4 4))
→ (+ 9 16)
→ 25
```

每一步有两种不同动作：**求值一个子表达式**，或**展开一个复合过程的应用**。

代换模型不是声称解释器真的编辑源码字符串。它是当前适用的计算模型；替换必须尊重绑定关系，不能把同名但属于别的绑定的变量一起替换。加入赋值和共享状态后，我们会使用环境模型。

### 2.5 条件不是普通调用

```scheme
(if 谓词表达式
    为真时的表达式
    为假时的表达式)
```

`if` 先求谓词，随后**只求一个分支**：

```scheme
(if (= 0 0) 0 (/ 1 0)) ; 0：除零表达式没有被求值
```

`cond` 从上向下检查条件，执行第一个成立的分支；`else` 放在最后作为兜底：

```scheme
(cond ((> x 0) x)
      ((= x 0) 0)
      (else (- x)))
```

`and`、`or` 也有短路规则；`not` 则是普通过程。Scheme 只有 `#f` 表示假，`0` 不是假，空列表也不是假；本单元通常用返回 `#t` / `#f` 的比较过程作谓词。

对应 Go 时可以这样记：普通函数调用会先算参数，但 `if`、`&&`、`||` 有各自的控制规则。Scheme 的 `if` 还是一个会产生值的表达式，Go 的 `if` 是语句。**括号形式统一，不意味着求值规则统一。**

## 3. 代表题：从结果回到规则

以下题号对应 [教材原文][source]。题意用中文概述，完整代码集中在 [solutions.rkt](solutions.rkt)，不需要逐段复制拼装。

### 习题 1.1：逐个表达式预测结果

**题意**：依次求值下面的表达式；后面的表达式可以使用前面建立的定义。

| 表达式 | 结果 / 效果 | 为什么 |
| --- | --- | --- |
| `10` | `10` | 数字自身就是值 |
| `(+ 5 3 4)` | `12` | 三数相加 |
| `(- 9 1)` | `8` | 普通过程应用 |
| `(/ 6 2)` | `3` | 精确除法 |
| `(+ (* 2 4) (- 4 6))` | `6` | `8 + (-2)` |
| `(define a 3)` | 建立 `a = 3` | 定义，不是计算答案 3 的普通调用 |
| `(define b (+ a 1))` | 建立 `b = 4` | 定义时使用已有的 `a` |
| `(+ a b (* a b))` | `19` | `3 + 4 + 12` |
| `(= a b)` | `#f` | 3 不等于 4 |
| `(if (and (> b a) (< b (* a b))) b a)` | `4` | `4 > 3` 且 `4 < 12`，选择 `b` |
| `(cond ((= a 4) 6) ((= b 4) (+ 6 7 a)) (else 25))` | `16` | 第二个条件成立，`6 + 7 + 3` |
| `(+ 2 (if (> b a) b a))` | `6` | 先取得条件表达式的值 4 |
| `(* (cond ((> a b) a) ((< a b) b) (else -1)) (+ a 1))` | `16` | `cond` 得 4，另一个因子为 4 |

教材不规定 `define` 必须打印哪个值。这里的 Racket 环境通常不会为定义打印普通计算结果；不要把 REPL 的显示约定当作语言计算规则。

**提炼**：算术部分很简单，关键是分清“表达式产生值”和“定义建立名字关联”，以及嵌套条件如何参与更大的组合式。

### 习题 1.3：三个数中较大的两个数的平方和

**题意**：接受三个数，返回其中较大两个数的平方和。

关键不是列举六种排列，而是换个问题：**找出一个最小的数，只用另外两个数计算。**

```scheme
(define (square x)
  (* x x))

(define (sum-of-squares x y)
  (+ (square x) (square y)))

(define (sum-square-largest-two x y z)
  (cond ((and (<= x y) (<= x z)) (sum-of-squares y z))
        ((and (<= y x) (<= y z)) (sum-of-squares x z))
        (else (sum-of-squares x y))))
```

推导例子：

```text
(sum-square-largest-two 3 1 2)
x = 3 不是最小值
 y = 1 满足 1 <= 3 且 1 <= 2
→ (sum-of-squares 3 2)
→ (+ 9 4)
→ 13
```

为什么完整：

- 如果 `x` 是最小值，第一个分支排除它。
- 否则若 `y` 是最小值，第二个分支排除它。
- 前两个都不是最小值时，排除 `z`。
- 使用 `<=` 处理相等值；最小值并列时排除任意一个，剩余平方和不变。

这里假定输入是能按大小比较的普通实数；复数和 NaN 不在题目训练范围。不额外为教学过程设计外部输入接口。

| 输入 | 选中的数 | 结果 |
| --- | --- | --- |
| `3, 1, 2` | `3, 2` | `13` |
| `2, 2, 1` | `2, 2` | `8` |
| `1, 1, 2` | `1, 2` | `5` |
| `2, 2, 2` | `2, 2` | `8` |
| `-3, -2, -1` | `-2, -1` | `5` |

注意最后一行：先按**数本身**的大小选，不是先平方再取最大的两个平方。

这个过程只做固定次数的比较和算术。在本章按每次数值操作单位成本计算的模型下，时间和额外空间都是 Θ(1)；任意精度数的位运算成本不在这个简化模型内。

也可以算“三个平方和减去最小数的平方”，但上面的写法更直接表达选择过程，也不引入一次不必要的大数平方与相减。无需排序，也无需先学习列表。

### 习题 1.4：操作符位置也可以是表达式

**题意**：说明以下过程的行为：

```scheme
(define (a-plus-abs-b a b)
  ((if (> b 0) + -) a b))
```

不要把两层括号读成“奇怪语法”。外层仍是普通调用，只是操作符需要先通过内层 `if` 得到：

```text
(a-plus-abs-b 10 -3)
→ ((if (> -3 0) + -) 10 -3)
→ (- 10 -3)
→ 13
```

- `b > 0`：`if` 返回加法过程，计算 `a + b`。
- `b <= 0`：`if` 返回减法过程，计算 `a - b`。
- 因此两种情况都得到 `a + |b|`；`b = 0` 时走减法，结果仍为 `a`。

内层写 `+` 或 `-` 是**取得过程值**，不是马上执行加减。外层才把这个值应用到 `a`、`b`。

Go 里可以把两个签名相同的函数作为值，经过条件选择后调用；但 Go 的内建 `+`、`-` 运算符不能直接当成函数值传递。这是类比的边界。

**提炼**：求值规则不要求操作符位置必须是一个固定名字，只要求它最终得到一个过程。这为后续高阶过程铺路。

### 习题 1.5：应用序和正则序为什么会得到不同命运

**题意**：给定下面两个过程，用 `(test 0 (p))` 区分求值策略。

```scheme
(define (p) (p))

(define (test x y)
  (if (= x 0) 0 y))
```

`p` 的过程体再次调用 `p`，没有终止分支。**定义它不会循环，调用它才会。**

#### 应用序：先求参数值，再应用过程

```text
(test 0 (p))
需要先得到 0 和 (p) 的值
(p) → (p) → (p) → ...
始终无法把参数值交给 test 的过程体
```

因此在当前 `#lang sicp` 中，这个调用不终止。即使过程体根本不需要 `y`，也不能跳过调用前对第二个参数的求值。是否先算第一个参数不影响这个结论。

不要把结果描述成“必然栈溢出”：Scheme 的尾调用机制允许 `(p)` 不断调用而不持续增加控制栈；本题关键是**没有结果**，不是某种特定报错。

#### 正则序：先展开，随后归约需要的表达式

按本节教材的正则序代换规则推演，并保留 `if` 的条件选择规则：

```text
(test 0 (p))
→ (if (= 0 0) 0 (p))
→ (if #t 0 (p))
→ 0
```

`(p)` 落在未选中的分支中，从未需要计算。

这是**另一套求值规则下的推演**，不是声称当前 Racket 可以直接运行同一调用并得到 0。第四章再实现具有延迟求值行为的解释器。

#### 延迟不等于自动缓存

先记住三层区别，暂不实现它们：

- 本节的正则序模型强调先展开、再归约。
- 按名调用延迟参数，每次需要时可能重新计算；与正则序相关，但不要把不同语义定义无条件视为相同。
- 按需调用在延迟基础上共享并记住求值结果，避免重复计算。

“没有立刻计算”本身没有说明是否缓存。带副作用时，这种差别会影响可观察行为。

#### 用不会挂起的例子观察当前环境

[solutions.rkt](solutions.rkt) 保留 `p` 的定义，但不执行 `(test 0 (p))`。它用这个有限过程观察参数求值：

```scheme
(define (argument-probe)
  (display "argument evaluated")
  (newline)
  42)

(test 0 (argument-probe))
```

会先打印 `argument evaluated`，然后得到 0：证明确实算过那个最终没被使用的参数。对比 `(if #t 0 (p))` 则安全返回 0。显示输出是本节唯一为观察顺序而引入的副作用，状态模型稍后再讲。

## 5. 为什么这样设计这一单元

四道题不是四个孤立技巧，而是一条链：

```text
1.1：按规则求值
 → 1.3：用规则组织一个正确过程
 → 1.4：操作符也是可以计算出来的值
 → 1.5：求值规则本身决定程序能否产生结果
```

暂不讲宏、解释器实现或完整数值算法。先把“表达式”“过程值”“应用过程”“特殊形式”分开，后面才不会把语言机制当作魔法。
