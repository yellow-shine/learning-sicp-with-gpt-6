# 1. 这节课到底想解决什么问题？

先不谈 higher-order procedure。

假设上一节我们已经会写：

```scheme
(define (sum-integers a b)
  (if (> a b)
      0
      (+ a
         (sum-integers (+ a 1) b))))
```

也会写：

```scheme
(define (sum-squares a b)
  (if (> a b)
      0
      (+ (square a)
         (sum-squares (+ a 1) b))))
```

再来一个：

```scheme
(define (pi-sum a b)
  (if (> a b)
      0
      (+ (/ 1.0 (* a (+ a 2)))
         (pi-sum (+ a 4) b))))
```

仔细看。

它们表面上在做三件不同的事：

```text
整数求和
平方求和
某个 π 级数求和
```

但程序结构几乎一样：

```text
if index 超过终点
    返回 0
else
    当前项
    +
    剩下所有项
```

变化的只有两个东西：

```text
当前项怎么算？

a
(square a)
1 / (a(a+2))

下一项是谁？

a + 1
a + 1
a + 4
```

Sussman 在这里指出一个非常 SICP 的判断：

> 当你反复写几乎一样的程序时，真正的问题不是“重复代码不好看”，而是**有一个概念还没有被赋予名字**。([TAU Open Course Ware](https://ocw.tau.edu.ng/courses/electrical-engineering-and-computer-science/6-001-structure-and-interpretation-of-computer-programs-spring-2005/video-lectures/2a-higher-order-procedures/ "2A: Higher-order Procedures | Video Lectures | Structure and Interpretation of Computer Programs | Electrical Engineering and Computer Science | MIT OpenCourseWare"))

这句话非常值得记住。

## 1.1 上一节 procedural abstraction 还不够

Lecture 1A/1B 已经教了：

```scheme
(define (square x)
  (* x x))
```

这样我们可以把：

```text
x * x
```

抽象成：

```text
square
```

这是：

> 把一个**具体计算步骤**封装成 procedure。

但这里的问题更高一层。

我们真正想抽象的是：

```text
对一系列 index
    计算一个 term
    把结果相加
    再产生下一个 index
```

注意，这个 abstraction 本身含有两个“洞”：

```text
term 怎么算？
next 怎么算？
```

这两个洞不是数字。

它们本身是 **computation**。

所以如果语言只允许：

```text
number
string
boolean
```

作为参数，而不允许：

```text
procedure
```

作为参数，就很难直接表达这个抽象。

这就是 Lecture 2A 要跨过的门槛。

# 4. 第一层：procedure 作为参数

先解决刚才的 `sum`。

我们写：

```scheme
(define (sum term a next b)
  (if (> a b)
      0
      (+ (term a)
         (sum term
              (next a)
              next
              b))))
```

第一次看到通常会觉得这段代码比三个具体版本更抽象。

先不要急着看语法。

它表达的是：

```text
sum(
    如何产生当前值,
    当前 index,
    如何产生下一个 index,
    终点
)
```

所以：

```text
term : index → value

next : index → next-index
```

---

## 4.1 为什么 `term` 需要是 procedure？

因为我们不想规定：

```text
当前项一定是 a
```

而希望调用者决定：

```scheme
(lambda (x) x)

(lambda (x) (* x x))

(lambda (x)
  (/ 1.0 (* x (+ x 2))))
```

也就是说：

> `sum` 不知道“加什么”，它只知道“如何进行求和”。

这叫：

```text
separate mechanism from policy
```

在这里：

```text
mechanism = 遍历、终止、相加

policy =
    term
    next
```

这是今天大量软件设计的根源。

# 5. Evaluation：`sum` 到底怎么运行？

例如：

```scheme
(define (identity x) x)
(define (inc x) (+ x 1))

(sum identity 1 inc 3)
```

我们先按照 Lecture 1B 的 applicative-order substitution model。

原式：

```scheme
(sum identity 1 inc 3)
```

绑定：

```text
term → identity
a    → 1
next → inc
b    → 3
```

body：

```scheme
(if (> 1 3)
    0
    (+ (identity 1)
       (sum identity
            (inc 1)
            inc
            3)))
```

计算：

```text
(> 1 3)
→ #f
```

于是：

```scheme
(+ (identity 1)
   (sum identity
        (inc 1)
        inc
        3))
```

然后：

```text
(identity 1) → 1
(inc 1)      → 2
```

得到：

```scheme
(+ 1
   (sum identity 2 inc 3))
```

继续：

```text
→ (+ 1
     (+ 2
        (sum identity 3 inc 3)))

→ (+ 1
     (+ 2
        (+ 3
           (sum identity 4 inc 3))))

→ (+ 1
     (+ 2
        (+ 3 0)))

→ 6
```

注意这里最值得看的不是 `6`。

而是：

```scheme
(term a)
```

里面的：

```text
term
```

本来只是一个 formal parameter。

运行时：

```text
term → identity
```

因此：

```scheme
(term a)
```

变成：

```scheme
(identity 1)
```

**变量现在可以保存一个 procedure。**

这正是思维突破。

Sussman 在回答学生问题时特意强调：`next` 本身是 procedure，而 `(next a)` 是**应用这个 procedure 得到的值**；procedure 可以像其他值一样传来传去。([TAU Open Course Ware](https://ocw.tau.edu.ng/courses/electrical-engineering-and-computer-science/6-001-structure-and-interpretation-of-computer-programs-spring-2005/video-lectures/2a-higher-order-procedures/ "2A: Higher-order Procedures | Video Lectures | Structure and Interpretation of Computer Programs | Electrical Engineering and Computer Science | MIT OpenCourseWare"))

# 6. procedure 和 procedure application 千万不要混

这一节特别容易混淆：

```scheme
next
```

和：

```scheme
(next a)
```

完全不是一回事。

```text
next
↓
procedure 本身
```

而：

```text
(next a)
↓
apply procedure
↓
产生一个 value
```

比如：

```scheme
(define (inc x) (+ x 1))
```

那么：

```text
inc
```

表示：

```text
那个 procedure object
```

而：

```scheme
(inc 5)
```

表示：

```text
apply inc to 5
→ 6
```

现代语言一样：

```python
f = abs
```

与：

```python
f(-3)
```

不同。

# 7. Lambda 到底解决什么问题？

假设：

```scheme
(define (square x)
  (* x x))
```

只是为了传一次：

```scheme
(sum square 1 inc 10)
```

我们其实没必要给它一个永久名字。

于是：

```scheme
(sum
  (lambda (x) (* x x))
  1
  (lambda (x) (+ x 1))
  10)
```

`lambda` 的本质不是“高级 Lisp 语法”。

它表达：

> **构造一个 procedure value。**

你应该这样读：

```scheme
(lambda (x)
  (* x x))
```

不是：

> lambda 关键字……

而是：

```text
construct a procedure

parameter:
    x

body:
    (* x x)
```

就像：

```scheme
42
```

产生 number value，

```scheme
"hello"
```

产生 string value，

而：

```scheme
(lambda (x) (* x x))
```

产生：

```text
procedure value
```

# 8. Higher-order Procedure 第一层真正解决了什么？

三个程序：

```text
sum-integers
sum-squares
pi-sum
```

以前：

```text
每个程序
    自己处理 recursion
    自己处理 boundary
    自己处理 next
```

现在：

```text
                  sum
                   │
       ┌───────────┼────────────┐
       │           │            │
     term          next       bounds
       │           │
具体 computation  traversal
```

我们不是简单“减少重复代码”。

而是在建立：

> **abstraction over a computational pattern**

这就是 higher-order programming 的核心。

# 9. 一个非常重要的 SICP Pattern

以后看到：

```scheme

```

不要马上翻译：

> **为什么这里把一个 computation 参数化？**


```text

      │
```

# 11. 两层 lambda 为什么不能合并？

很多第一次学 SICP 的人都会问：

为什么：

```scheme
(lambda (f)
  (lambda (x)
    ...))
```

而不是：

```scheme
(lambda (f x)
  ...)
```

这也是视频现场学生直接问的问题。

答案非常重要。([TAU Open Course Ware](https://ocw.tau.edu.ng/courses/electrical-engineering-and-computer-science/6-001-structure-and-interpretation-of-computer-programs-spring-2005/video-lectures/2a-higher-order-procedures/ "2A: Higher-order Procedures | Video Lectures | Structure and Interpretation of Computer Programs | Electrical Engineering and Computer Science | MIT OpenCourseWare"))

第一种：

```scheme
(lambda (f)
  (lambda (x)
    ...))
```

类型直觉是：

```text
procedure → procedure
```

例如：

```text
average-damp
    ↓
input:  f
    ↓
output: another procedure
```

所以：

```scheme
(average-damp square)
```

的结果仍然是 procedure。

---

第二种：

```scheme
(lambda (f x)
  ...)
```

则是：

```text
procedure × number → number
```

调用时必须一次提供：

```scheme
(foo square 10)
```

它直接产生一个数字。

两者抽象层级完全不同。

# 12. `average-damp` 到底是什么？

先忽略 square root。

给定：

```text
f(x)
```

average damping 产生一个新函数：

$$
g(x)=\frac{x+f(x)}2
$$

Scheme：

```scheme
(define (average-damp f)
  (lambda (x)
    (average x (f x))))
```

所以：

```text
f
 │
 ▼
average-damp
 │
 ▼
g
```

注意：

> `average-damp` 不是在“计算一个数字”。

它是在：

> **transforming one computation into another computation**

这是比 `sum` 更高一层的 abstraction。

---

# 13. 手动展开 `average-damp`

比如：

```scheme
(define (square x)
  (* x x))

(define g
  (average-damp square))
```

代入：

```scheme
(average-damp square)
```

body 是：

```scheme
(lambda (x)
  (average (square x) x))
```

因此：

```text
g
↓
procedure(x)
    average(square(x), x)
```

然后：

```scheme
(g 4)
```

展开：

```scheme
(average (square 4) 4)
```

↓

```scheme
(average 16 4)
```

↓

```scheme
10
```

关键是：

```scheme
(average-damp square)
```

这一步并**没有运行 square**。

它只是构造：

```scheme
(lambda (x)
  (average (square x) x))
```

直到：

```scheme
(g 4)
```

才真正调用 `square`。

例如：

```scheme
(define (make-adder n)
  (lambda (x)
    (+ x n)))
```

执行：

```scheme
(define add5
  (make-adder 5))
```

概念上：

```text
Global Environment
│
├── make-adder → procedure
│
└── add5 ──────────────┐
                       │
                       ▼
              procedure (x)
              body: (+ x n)

```

```scheme
(add5 3)
```

```text
E2
x = 3
parent = E1
```

```text
x → E2 → 3

n → not in E2
   → E1
   → 5
```

于是：

```text
3 + 5
→ 8
```

> **closure**

# 15. Fixed Point：为什么突然开始讲平方根？

这不是数学跑题。

SICP 是要展示：

> higher-order procedure 能把“复杂算法”重新组织成非常清楚的计算组件。

上一节平方根可能长这样：

```text
guess
  ↓
good-enough?
  ↓ no
improve
  ↓
new guess
  ↓
repeat
```

能工作。

但 SICP 问：

> 这里真正的数学结构是什么？

Heron 方法：

$$
y_{n+1} = \frac{y_n+x/y_n}{2}
$$

定义：

$$
f(y)=\frac{y+x/y}{2}
$$

当找到正确平方根 $r$：

$$
f(r)=r
$$

因此 square root 可以重新描述为：

> **寻找函数 f 的 fixed point。**

这正是课堂从具体 square-root procedure 提升成 general fixed-point computation 的过程。([TAU Open Course Ware](https://ocw.tau.edu.ng/courses/electrical-engineering-and-computer-science/6-001-structure-and-interpretation-of-computer-programs-spring-2005/video-lectures/2a-higher-order-procedures/ "2A: Higher-order Procedures | Video Lectures | Structure and Interpretation of Computer Programs | Electrical Engineering and Computer Science | MIT OpenCourseWare"))

# 16. Fixed Point 是什么？

对于：

$$
f(x)
$$

如果：

$$
f(x)=x
$$

那么 `x` 就是 `f` 的 fixed point。

例如：

```text
cos(x)
```

反复：

```text
1
↓ cos
0.5403
↓ cos
0.8575
↓
0.6543
↓
...
↓
≈ 0.739...
```

最终：

```text
cos(x) ≈ x
```

这也是课堂实际使用的直觉例子。([TAU Open Course Ware](https://ocw.tau.edu.ng/courses/electrical-engineering-and-computer-science/6-001-structure-and-interpretation-of-computer-programs-spring-2005/video-lectures/2a-higher-order-procedures/ "2A: Higher-order Procedures | Video Lectures | Structure and Interpretation of Computer Programs | Electrical Engineering and Computer Science | MIT OpenCourseWare"))

# 17. `fixed-point` 是什么 abstraction？

大致：

```scheme
(define (fixed-point f first-guess)

  (define (close-enough? x y)
    (< (abs (- x y)) tolerance))

  (define (try guess)
    (let ((next (f guess)))
      (if (close-enough? guess next)
          next
          (try next))))

  (try first-guess))
```

先不要看细节。

它抽象的是：

```text
给我：

f
initial guess

我负责：

guess
 ↓
f
 ↓
new guess
 ↓
f
 ↓
new guess
 ↓
...
直到稳定
```

也就是：

```text
fixed-point
    =
generic iterative improvement engine
```

# 18. Process Shape

假设：

```scheme
(fixed-point f 1.0)
```

计算过程：

```text
guess0 = 1.0
   │
   ▼
guess1 = f(guess0)
   │
close?
   │ no
   ▼
guess2 = f(guess1)
   │
close?
   │
  ...
```

如果实现是尾递归：

```scheme
(try next)
```

那么在 Scheme proper tail recursion 下：

```text
space = O(1)
```

若经过 `k` 次迭代：

```text
time ≈ O(k × cost(f))
```

但注意：

> `k` 如何随误差变化，取决于 convergence rate。

所以这里不要粗暴说：

```text
fixed-point = O(n)
```

因为“n”是什么并没有定义。

# 19. 为什么直接用 `x / y` 不行？

因为平方根 $r$ 满足：

$$
r=\frac{x}{r}
$$

于是似乎可以找：

$$
f(y)=\frac{x}{y}
$$

的 fixed point。

例如 $x=2$，从 `1` 开始：

```text
1
↓ 2 / 1
2
↓ 2 / 2
1
↓
2
↓
1
↓
...
```

永远振荡：

```text
1 ↔ 2
```

Sussman 就是通过这个例子引出 average damping。([TAU Open Course Ware](https://ocw.tau.edu.ng/courses/electrical-engineering-and-computer-science/6-001-structure-and-interpretation-of-computer-programs-spring-2005/video-lectures/2a-higher-order-procedures/ "2A: Higher-order Procedures | Video Lectures | Structure and Interpretation of Computer Programs | Electrical Engineering and Computer Science | MIT OpenCourseWare"))

# 20. Average Damping = algorithm transformer

定义：

```text
f(y) = x/y
```

然后：

```text
average-damp(f)
```

得到：

$$
g(y) = \frac{y+f(y)}2 = \frac{y+x/y}{2}
$$

这恰好就是 Heron 的更新规则。

所以：

```scheme
(define (sqrt x)
  (fixed-point
    (average-damp
      (lambda (y)
        (/ x y)))
    1.0))
```

看看这段程序现在表达什么：

```text
sqrt(x)

= fixed point
       of

  average damping
       of

       y ↦ x/y
```

这已经非常接近数学语言。

SICP 的目标不是炫技，而是：

> **让 program structure mirror conceptual structure。**

# 21. 详细展开 `(sqrt 4)`

这是本节最值得真正跑一遍的地方。

调用：

```scheme

```

先构造：

```scheme
(lambda (y)
  (/ 4 y))
```

称它为：

```text
f(y) = 4/y
```

然后：

```scheme
(average-damp f)
```

产生：

```scheme
(lambda (y)
  (average y (/ 4 y)))
```

称为：

```text
g(y) = (y + 4/y) / 2
```

然后：

```scheme
(fixed-point g 1.0)
```

运行：

```text
y0 = 1.0

y1 =
(1 + 4/1) / 2
= 2.5

y2 =
(2.5 + 4/2.5) / 2
= (2.5 + 1.6)/2
= 2.05

y3 =
(2.05 + 4/2.05)/2
≈ 2.000609756

y4
≈ 2.000000093

...
→ 2
```

你应该看到三层东西：


# 23. Newton's Method：为什么还要再抽象一次？

SICP 接着说：

如果我们不是专门求 square root，而是想解决：

$$
f(x)=0
$$

Newton iteration 是：

$$
x_{n+1} = x_n - \frac{f(x_n)}{f'(x_n)}
$$

关键观察：

定义：

$$
g(x) = x-\frac{f(x)}{f'(x)}
$$

Newton method 就变成：

```text
找到 g 的 fixed point
```

于是刚才已经写好的：

```scheme
fixed-point
```

可以直接复用。

这就是 SICP 想让你体会的：

> 好的 abstraction 会成为下一层 abstraction 的 primitive。

# 24. `deriv` 更有意思

我们需要：

$$
f'
$$

SICP 写：

```scheme
(define (deriv f)
  (lambda (x)
    (/ (- (f (+ x dx))
          (f x))
       dx)))
```

注意类型：

```text
f
:
number → number
```

而：

```text
(deriv f)
:
number → number
```

因此：

```text
deriv
:
(number → number)
        →
(number → number)
```

换句话说：

> differentiation 被表达成 **procedure transformation**。

这在思想上非常漂亮。

数学里：

```text
f
↓ differentiation
f'
```

程序里：

```text
procedure f
↓ deriv
procedure df
```

两者结构一致。

# 25. Newton's method 最终如何组合？

大致：

```scheme
(define (newton f guess)
  (define df (deriv f))

  (fixed-point
    (lambda (x)
      (- x
         (/ (f x)
            (df x))))
    guess))
```

于是：

```scheme
(define (sqrt x)
  (newton
    (lambda (y)
      (- x (square y)))
    1.0))
```

逻辑结构：

```text
sqrt
 │
 │ create
 ▼
f(y) = x - y²
 │
 ▼
Newton
 │
 ├───────────┐
 │           │
 │        deriv
 │           │
 │           ▼
 │          df
 │           │
 └─────┬─────┘
       ▼
 g(y) = y - f(y)/df(y)
       │
       ▼
 fixed-point
       │
       ▼
   solution
```

这几乎就是 Lecture 2A 的知识结构核心。课堂就是这么把 Newton method 分解成 `deriv` 与 `fixed-point` 等可组合过程的。([TAU Open Course Ware](https://ocw.tau.edu.ng/courses/electrical-engineering-and-computer-science/6-001-structure-and-interpretation-of-computer-programs-spring-2005/video-lectures/2a-higher-order-procedures/ "2A: Higher-order Procedures | Video Lectures | Structure and Interpretation of Computer Programs | Electrical Engineering and Computer Science | MIT OpenCourseWare"))

# 26. SICP 在这里真正教的是“Wishful Thinking”

Sussman 在 Newton method 部分反复做一件事情：

存在。

存在。

# 27. Procedure vs Function

这一节课堂特意区分了这两个词。([TAU Open Course Ware](https://ocw.tau.edu.ng/courses/electrical-engineering-and-computer-science/6-001-structure-and-interpretation-of-computer-programs-spring-2005/video-lectures/2a-higher-order-procedures/ "2A: Higher-order Procedures | Video Lectures | Structure and Interpretation of Computer Programs | Electrical Engineering and Computer Science | MIT OpenCourseWare"))

数学里的：

```text
function
```

例如：

$$
f(x)=x^2
$$

是一个数学映射。

程序里的：

```scheme
(lambda (x)
  (* x x))
```

是：

```text
procedure
```

procedure 是：

> 一个 computational object / rule，用来计算那个数学 function。

因此严格说：

```text
procedure computes a function
```

而不是：

```text
procedure = mathematical function
```

实际编程交流里当然经常混用，但 SICP 在这里故意让你意识到两层概念。

这个区别后面会越来越重要，因为 procedure 可能：

```text
有 state
有 side effect
不终止
抛异常
依赖 environment
```

而纯数学 function 没这些 operational properties。

# 28. First-Class Procedure 是什么意思？

课程最后引用 Christopher Strachey 的观点，列出 first-class object 的“权利”。([TAU Open Course Ware](https://ocw.tau.edu.ng/courses/electrical-engineering-and-computer-science/6-001-structure-and-interpretation-of-computer-programs-spring-2005/video-lectures/2a-higher-order-procedures/ "2A: Higher-order Procedures | Video Lectures | Structure and Interpretation of Computer Programs | Electrical Engineering and Computer Science | MIT OpenCourseWare"))

procedure 能：

```text
① 被变量命名

(define f square)

② 作为参数传入

(sum square ...)

③ 作为返回值

(average-damp f)
→ procedure

④ 放入 data structure
   （2B 之后会越来越自然）
```

这不是 Scheme 的小功能。

它意味着：

> **computation itself is manipulable data.**

这是 Lecture 2A 最应该记住的一句话之一。

# 29. Higher-order procedure 到底是什么？

简单定义：

> 接收 procedure 作为参数，或返回 procedure 的 procedure。

例如：

```scheme
(sum term a next b)
```

因为接收：

```text
term
next
```

所以是 higher-order procedure。

而：

```scheme
average-damp
```

既接收：

```text
procedure
```

又返回：

```text
procedure
```

所以更直观。

# 30. Procedure vs Process 再区分一次

Lecture 1B 的重要结论仍然适用。

比如：

```scheme
(define (sum term a next b)
  (if (> a b)
      0
      (+ (term a)
         (sum term
              (next a)
              next
              b))))
```

这个：

```text
procedure
```

产生：

```text
recursive process
```

因为：

```text
(term a) + ...
```

必须等待递归结果。

展开：

```text
term(1) + sum(2...)
        ↓
1 + (term(2) + sum(3...))
        ↓
1 + (2 + (term(3) + ...))
```

需要保存 deferred additions：

```text
space O(n)
time  O(n)
```

---

如果写 iterative version：

```scheme
(define (sum term a next b)
  (define (iter a result)
    (if (> a b)
        result
        (iter (next a)
              (+ result (term a)))))
  (iter a 0))
```

仍然是 recursive procedure：

```scheme
(iter ...)
```

调用自己。

但 process：

```text
(a=1,result=0)
↓
(a=2,result=1)
↓
(a=3,result=3)
↓
(a=4,result=6)
```

是：

```text
iterative process

space O(1)
time O(n)
```

Higher-order procedure 和 recursion/iteration 是**两个正交维度**：

```text
Higher-order
= abstraction relationship

recursive / iterative process
= runtime process shape
```

不要混在一起。

# 31. Substitution Model 在本节怎么使用？

例如：

```scheme
((average-damp square) 4)
```

先 evaluation operator：

```scheme
(average-damp square)
```

↓

```scheme
(lambda (x)
  (average (square x) x))
```

所以整个 expression：

```scheme
((lambda (x)
   (average (square x) x))
 4)
```

apply：

```text
x → 4
```

↓

```scheme
(average (square 4) 4)
```

↓

```scheme
(average 16 4)
```

↓

```text
10
```

这里可以非常漂亮地看到上一节 evaluation rule：

```text
combination
   ↓
evaluate operator
   ↓
evaluate operands
   ↓
apply operator procedure
```

注意最外层 operator 本身居然不是名字：

```scheme
foo
```

而是：

```scheme
(average-damp square)
```

这个表达式经过 evaluation 后才产生 procedure。

课堂最后也专门再次指出这种“双左括号”完全合法：operator position 本身就是一个 expression，可以先 evaluate 成 procedure。([TAU Open Course Ware](https://ocw.tau.edu.ng/courses/electrical-engineering-and-computer-science/6-001-structure-and-interpretation-of-computer-programs-spring-2005/video-lectures/2a-higher-order-procedures/ "2A: Higher-order Procedures | Video Lectures | Structure and Interpretation of Computer Programs | Electrical Engineering and Computer Science | MIT OpenCourseWare"))

# 32. Applicative-order 在这里发生什么？

例如：

```scheme
(f (g x))
```

Scheme 默认：

```text
evaluate f
evaluate (g x)
    ↓
    evaluate g
    evaluate x
    apply g
    ↓
    result
apply f to result
```

如果：

```scheme
((average-damp f) 10)
```

则：

```text
evaluate operator:
    (average-damp f)

        evaluate average-damp
        evaluate f
        apply average-damp
        ↓
        returns procedure g

evaluate operand:
    10

apply g to 10
```

重点：

```text
operator position itself may be computation
```

这是 Lisp/Scheme 非常统一的地方。

```scheme
  (average (f x) x))
```

与：

```scheme
(define (foo f)
  (lambda (x)
    (average (f x) x)))
```

不是同一个 abstraction。

不要只回答：

> 第二个返回函数。

请从：

```text
输入
输出
evaluation timing
composition capability
```

四个角度解释。
