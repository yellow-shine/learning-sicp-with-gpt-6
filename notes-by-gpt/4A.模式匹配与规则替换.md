# 1. 这节课到底想解决什么问题？

## 1.1 回到 3B：我们已经能做 symbolic differentiation

上一节我们可能写出了类似：

```scheme
(define (deriv exp var)
  (cond ((number? exp) 0)

        ((variable? exp)
         (if (same-variable? exp var)
```

```scheme
(deriv '(+ x y) 'x)
```

```scheme
(+ 1 0)
```

看起来不错。

但 Sussman 在 4A 开头突然问：

## 1.2 真正的问题：知识和执行机制混在一起了

仔细观察刚才的 `deriv`：

```scheme
(cond
  ((number? exp) ...)
  ((variable? exp) ...)
  ((sum? exp) ...)
  ((product? exp) ...))
```

这里混合了两类完全不同的东西。

一类是 **微积分知识**：

```text
d(c)/dx = 0

d(x)/dx = 1

d(u + v)/dx
=
du/dx + dv/dx

d(uv)/dx
=
u dv/dx + v du/dx
```

另一类是 **程序执行机制**：

```text
检查 expression 是什么形状
↓
提取部分
↓
绑定变量
↓
构造新 expression
↓
继续递归
```

如果明天我们想实现：

```text
algebra simplifier
trigonometric simplifier
logical simplifier
compiler optimizer
```

按照 3B 的做法，我们又得重新写一套：

```scheme
(cond ...)
```

虽然算法骨架几乎一样。

Sussman 的目标因此是：

```text
Domain Knowledge
    derivative rules
    algebra rules
    trig rules
           │
           │ 数据
           ▼
┌──────────────────────┐
│ General Rule Engine  │
│                      │
│ matcher              │
│ instantiator         │
│ control strategy     │
└──────────────────────┘
           │
           ▼
     transformed AST
```

他说得非常明确：希望把 **matching、instantiation 和 control structure** 从具体规则中抽出来，从“解决一个问题”提升到“解决一类问题”。([MIT OpenCourseWare](https://opencw.aprende.org/courses/electrical-engineering-and-computer-science/6-001-structure-and-interpretation-of-computer-programs-spring-2005/video-lectures/4a-pattern-matching-and-rule-based-substitution/ "4A: Pattern Matching and Rule-based Substitution | Video Lectures | Structure and Interpretation of Computer Programs | Electrical Engineering and Computer Science | MIT OpenCourseWare"))

这就是本节最重要的 abstraction。

# 4. 第一核心思想：Rule 本身也是 Data

这是这节最值得记住的一步。

以前：

```scheme
(define (deriv ...)
  ...)
```

规则存在于程序控制结构里。

现在我们想写：

```scheme
(define deriv-rules
  '(
    ((dd (?c c) (? v))
     0)

    ((dd (?v v) (? v))
     1)

    ((dd (?v u) (? v))
     0)

    ((dd (+ (? x1) (? x2)) (? v))
     (+ (dd (: x1) (: v))
        (dd (: x2) (: v))))
    ))
```

注意最外层的：

```scheme
'
```

即 `quote`。

为什么？

因为：

```scheme
(dd ...)
```

现在不是要求 Scheme 调用一个叫 `dd` 的 procedure。

我们是在描述一个 **symbolic structure**。

也就是说：

```text
Scheme expression
       ↓ quote
ordinary Lisp data
       ↓
我们的程序读取它
       ↓
赋予它“rule”的意义
```

# 5. 这里其实有三层语言

这是很多人第一次学 4A 时没有意识到的地方。

非常重要。

我们现在同时生活在三个世界里：

```text
Level 1
Scheme
────────────────────
实现 matcher / simplifier


Level 2
Symbolic expression language
────────────────────
(+ (* 3 x) y)


Level 3
Rule language
────────────────────
(+ 0 (? e))  →  (: e)
```

例如：

```scheme
'(+ (* 3 x) 0)
```

在 Scheme 看来只是：

```text
list
```

但对我们的 symbolic algebra system 来说，它表示：

```text
3x + 0
```

而：

```scheme
'((+ 0 (? e))
  (: e))
```

对 Scheme 来说也只是：

```text
list
```

但我们的 **rule interpreter** 会给它这样的意义：

```text
如果找到 (+ 0 anything)
把结果替换成 anything
```

这就是：

> **Syntax 本身没有意义，是 interpreter 给 syntax 意义。**

把这句话记住。

到 Lecture 7 写 metacircular evaluator 时，它会回来。

# 6. Pattern 和 Skeleton

每条规则有两个部分：

```text
Pattern  ─────────→ Skeleton
 左边                 右边
```

Sussman 在讲座中直接用这两个词来描述 rule：pattern 与 source expression 匹配；skeleton 被实例化产生 target expression。([MIT OpenCourseWare](https://opencw.aprende.org/courses/electrical-engineering-and-computer-science/6-001-structure-and-interpretation-of-computer-programs-spring-2005/video-lectures/4a-pattern-matching-and-rule-based-substitution/ "4A: Pattern Matching and Rule-based Substitution | Video Lectures | Structure and Interpretation of Computer Programs | Electrical Engineering and Computer Science | MIT OpenCourseWare"))

例如：

```scheme
((+ 0 (? e))
 (: e))
```

意思：

```text
pattern
(+ 0 (? e))

skeleton
(: e)
```

假设输入：

```scheme
(+ 0 (* x y))
```

matching：

```text
(? e)
   ↓
(* x y)
```

于是 dictionary：

```text
e → (* x y)
```

然后 instantiate：

```scheme
(: e)
```

得到：

```scheme
(* x y)
```

所以：

```text
(+ 0 (* x y))
      │
      │ match
      ▼
e = (* x y)
      │
      │ instantiate
      ▼
(* x y)
```

# 7. Pattern Language 到底是什么？

大致是：


只匹配 `foo` 本身。

# 8. 一个非常重要的例子：重复 pattern variable

看：

```scheme
(+ (* (? x) (? y))
   (? y))
```

匹配：

```scheme
(+ (* 3 x)
   x)
```

这里第一个：

```scheme
(? x)
```

得到：

```text
pattern x → 3
```

注意：

> pattern variable `x` 和 expression 中的 symbol `x` 根本不是同一个东西。

然后：

```scheme
(? y)
```

匹配 expression 的：

```scheme
x
```

得到：

```text
pattern y → symbol x
```

dictionary：

```text
x → 3
y → x
```

最后又遇到：

```scheme
(? y)
```

它不能随便匹配。

因为 `y` 已经绑定：

```text
y = x
```

所以最后那个 expression 必须也是：

```text
x
```

因此：

```scheme
(+ (* 3 x) x)
```

成功。

但：

```scheme
(+ (* 3 x) 4)
```

失败。

Sussman 在讲座中就是用这个例子解释 simultaneous tree traversal 与 dictionary consistency。([MIT OpenCourseWare](https://opencw.aprende.org/courses/electrical-engineering-and-computer-science/6-001-structure-and-interpretation-of-computer-programs-spring-2005/video-lectures/4a-pattern-matching-and-rule-based-substitution/ "4A: Pattern Matching and Rule-based Substitution | Video Lectures | Structure and Interpretation of Computer Programs | Electrical Engineering and Computer Science | MIT OpenCourseWare"))

# 9. Matcher 到底在干什么？

先不要看代码。

它本质上做的是：

```text
match(pattern, expression, dictionary)
             ↓
    dictionary' or failed
```

也就是说 matcher 并不是直接产生新 expression。

它只是回答：

> “这个 pattern 能不能解释这个 expression？如果可以，各 pattern variable 分别是什么？”

例如：

```text
pattern:
(+ (? x) (? y))

expression:
(+ a (* b c))

initial dictionary:
{}

        ↓ MATCH

result:
{x → a,
 y → (* b c)}
```

---

# 10. 为什么需要 Dictionary？

你可能会自然产生一个问题：

> 为什么匹配到 `(? x)` 时不直接替换？

因为现在我们还不知道：

```text
替换到哪里？
```

Matcher 只负责：

```text
理解 source
```

Instantiator 才负责：

```text
construct target
```

所以：

```text
Matcher
pattern + expression
      ↓
dictionary


Instantiator
skeleton + dictionary
      ↓
new expression
```

这是一个漂亮的 separation of concerns。

讲座里有人正好问了这个问题，Sussman 的回答就是：matcher 根本不知道 skeleton，所以此时没东西可 substitution；matcher 是独立组件。([MIT OpenCourseWare](https://opencw.aprende.org/courses/electrical-engineering-and-computer-science/6-001-structure-and-interpretation-of-computer-programs-spring-2005/video-lectures/4a-pattern-matching-and-rule-based-substitution/ "4A: Pattern Matching and Rule-based Substitution | Video Lectures | Structure and Interpretation of Computer Programs | Electrical Engineering and Computer Science | MIT OpenCourseWare"))

# 11. Matcher 的核心算法：同时遍历两棵树

假设：

```scheme
pattern
(+ (* (? x) (? y))
   (? y))
```

expression：

```scheme
(+ (* 3 x)
   x)
```

把它们想象成两棵树：

```text
Pattern                  Expression

       +                         +
      / \                       / \
     *  (? y)                  *   x
    / \                       / \
 (? x)(? y)                  3   x
```

Matcher 的核心动作不是神秘 AI。

就是：

```text
同时遍历两棵树
```

## 11.1 原子 vs 原子

例如：

```text
pattern:    +
expression: +
```

相同：

```text
dictionary 不变
```

如果：

```text
pattern:    +
expression: *
```

则：

```text
failed
```

## 11.2 Pattern Variable

```text
pattern:
(? x)

expression:
3
```

扩展 dictionary：

```text

```

## 11.3 Compound Structure

核心代码思想大致是：

```scheme
(match (cdr pattern)
       (cdr expression)
       (match (car pattern)
              (car expression)
              dictionary))
```

这一行非常值得理解。

不是：

```text
match car
match cdr
```

这么简单。

而是：

```text
旧 dictionary
      │
      ▼
match car
      │
      ▼
dictionary1
      │
      ▼
match cdr
      │
      ▼
dictionary2
```

即：

```text
dictionary 被“穿过”整棵树
```

Sussman 用的就是这种描述：dictionary 被 threaded through the structure。([MIT OpenCourseWare](https://opencw.aprende.org/courses/electrical-engineering-and-computer-science/6-001-structure-and-interpretation-of-computer-programs-spring-2005/video-lectures/4a-pattern-matching-and-rule-based-substitution/ "4A: Pattern Matching and Rule-based Substitution | Video Lectures | Structure and Interpretation of Computer Programs | Electrical Engineering and Computer Science | MIT OpenCourseWare"))

# 12. 把 Matcher 的 Evaluation 真正展开

考虑：

```scheme
(match '(+ (? x) (? y))
       '(+ 3 4)
       empty-dict)
```

概念上：

```text
match
│
├── compare structure
│
├── match car
│     pattern: +
│     exp:     +
│
│     → success
│     → dict = {}
│
└── match cdr
      pattern: ((? x) (? y))
      exp:     (3 4)
```

继续：

```text
match (? x) against 3
      ↓
extend dictionary
      ↓
{x → 3}
```

然后：

```text
match (? y) against 4
with dictionary {x → 3}
      ↓
{x → 3, y → 4}
```

最终：

```text
{x → 3,
 y → 4}
```



```text
  ↓
```


# 16. Instantiation 本质又是一遍 Tree Walk

伪代码：

```scheme
(define (instantiate skeleton dict)
  (cond ((atom? skeleton)
         skeleton)

        ((skeleton-evaluation? skeleton)
         (evaluate
           (evaluation-expression skeleton)
           dict))

        (else
         (cons
           (instantiate (car skeleton) dict)
           (instantiate (cdr skeleton) dict)))))
```

观察结构：

```text
atomic?
 ├─ yes → itself
 └─ no
     ├─ special : form → evaluate
     └─ ordinary pair
           ├─ instantiate car
           └─ instantiate cdr
```

又是 SICP 不断出现的：

```text
recursive tree walk
```

MIT 讲座也明确把 instantiation 描述成 recursive tree walk。([MIT OpenCourseWare](https://opencw.aprende.org/courses/electrical-engineering-and-computer-science/6-001-structure-and-interpretation-of-computer-programs-spring-2005/video-lectures/4a-pattern-matching-and-rule-based-substitution/ "4A: Pattern Matching and Rule-based Substitution | Video Lectures | Structure and Interpretation of Computer Programs | Electrical Engineering and Computer Science | MIT OpenCourseWare"))

# 17. `(: x)` 到底是什么？

这是特别容易误会的地方。

```scheme
(: x)
```

**不是 Scheme 语法。**

Scheme 并不知道冒号是什么意思。

它只是：

```scheme
(list ': 'x)
```

我们的 instantiator 自己约定：

```text
如果某个 skeleton node 长成：

(: something)

就把 something
按 dictionary 求值/展开
```

所以：

```scheme
(: x)
```

真正含义是我们的 interpreter 赋予的。

再次看到核心思想：

```text
syntax
  +
interpreter
  =
meaning
```

# 18. 更厉害一点：Skeleton 里还可以 computation

考虑 constant folding rule：

```scheme
(((? op) (?c c1) (?c c2))
 (: (op c1 c2)))
```

假设输入：

```scheme
(+ 3 4)
```

匹配：

```text
op → +
c1 → 3
c2 → 4
```

然后右侧：

```scheme
(: (op c1 c2))
```

不是简单替换成：

```scheme
(+ 3 4)
```

而是：

```text
lookup op → +
lookup c1 → 3
lookup c2 → 4

apply + to 3,4
       ↓
       7
```

所以一条 rule 不仅能模板替换，还可以：

```text
compute part of target
```

这就已经开始像一个真正的小 programming language 了。

# 22. General Simplifier

讲座中的结构大致可以写成：

```scheme
(define (simplifier the-rules)

  (define (simplify-exp exp)
    (try-rules
      (if (compound? exp)
          (map simplify-exp exp)
          exp)))

  (define (try-rules exp)
    (define (scan rules)
      (if (null? rules)
          exp
          (let ((dict
                 (match (pattern (car rules))
                        exp
                        (empty-dictionary))))
            (if (eq? dict 'failed)
                (scan (cdr rules))
                (simplify-exp
                  (instantiate
                    (skeleton (car rules))
                    dict))))))
    (scan the-rules))

  simplify-exp)
```

这段程序值得认真读。

# 23. 第一眼很可怕，但它其实只有三个循环

把所有代码隐藏，只看 computation shape：

```text
simplify expression
      │
      ├── recursively simplify children
      │
      ▼
   try rules
      │
      ├── rule 1
      ├── rule 2
      ├── rule 3
      └── ...
             │
          match?
             │
        ┌────┴────┐
        │         │
       no        yes
        │         │
   next rule   instantiate
                  │
                  ▼
           new expression
                  │
                  ▼
             simplify again
```

所以三个 recursion：

```text
1. expression-tree recursion
2. rule-list recursion
3. rewrite-result recursion
```

Sussman 就提醒学生：这里 recursion 交织得很复杂，不应该试图一次在脑中模拟全部控制流；更重要的是依赖 procedure specification。([MIT OpenCourseWare](https://opencw.aprende.org/courses/electrical-engineering-and-computer-science/6-001-structure-and-interpretation-of-computer-programs-spring-2005/video-lectures/4a-pattern-matching-and-rule-based-substitution/ "4A: Pattern Matching and Rule-based Substitution | Video Lectures | Structure and Interpretation of Computer Programs | Electrical Engineering and Computer Science | MIT OpenCourseWare"))

这句话其实非常 SICP。

# 43. 复杂度怎么看？

这一课的重点并不是 Big-O，但可以分析。

假设 expression 有：

```text
N nodes
```

有：

```text
R rules
```

一次 tree traversal 每个节点尝试最多 `R` 条规则。

粗略：

```text
O(N × R × match-cost)
```

一个 structural match 最坏还可能检查整个 subtree/pattern。

所以真实复杂度可能明显更高。

更麻烦的是：

```text
rewrite
```

可能：

```text
缩小 tree
保持 tree
放大 tree
```

例如 distribution：

```text
a * (b + c)
↓
a*b + a*c
```

tree 反而变大。

因此 general term rewriting 很难给一个漂亮统一的 Big-O。


Dictionary 的 bindings：

```text

```

Simplifier 还需要构造新的 expression tree。

它不是原地 mutation：

```text

  ↓

```

所以还涉及新结构的空间分配。

```text
       matcher / instantiate
             │
             ▼
       CONTROL STRATEGY
 traverse / try / repeat
             │
             ▼
        NEW EXPRESSION
```

真正的架构是：

```text
Representation
      +
Semantics
      +
Control
```

# 52. 容易混淆的几个概念

### `(? x)` vs `(: x)`

```text
(? x)
```

出现在 pattern：

> 捕获一个 expression，叫它 x。

```text
(: x)
```

出现在 skeleton：

> 取出之前捕获的 x。

可以记：

```text
? = ask / capture

: = use / substitute
```

---

### Matcher vs Simplifier

Matcher：

```text
只判断一个 pattern
能否匹配一个 expression
```

Simplifier：

```text
遍历整棵 expression tree
尝试许多 rules
反复 rewrite
```

Matcher 只是 simplifier 的组件。

---

### Dictionary vs Expression

Dictionary 是：

```text
metadata / bindings
```

例如：

```text
x → (* a b)
```

不是最终 symbolic expression。

---

### Rule vs Procedure

Rule：

```text
data
```

Procedure：

```text
computation
```

但是：

```text
interpreter(rule)
```

让 rule 表现得像 computation。

这正是最关键的 abstraction leap。

# 53. 常见误区

### 误区 1：`?` 和 `:` 是 Scheme 特殊语法

不是。

它们只是我们的 DSL convention。

正确 mental model：

```text
Scheme sees lists.

Our interpreter assigns meaning.
```

---

### 误区 2：Matcher 会直接修改 expression

不会。

Matcher：

```text
pattern + expression
→ dictionary
```

Instantiator：

```text
skeleton + dictionary
→ new expression
```

这是两个阶段。

---

### 误区 3：Pattern variable 每次出现都能重新绑定

不行。

如果：

```scheme
(? x)
```

第一次绑定：

```text
x → foo
```

第二次 `(? x)` 必须仍匹配 `foo`。

否则：

```text
failed
```

---

### 误区 4：Simplifier 只是跑一遍 rules

不是。

它：

```text
simplify children
↓
try rules
↓
rewrite
↓
simplify rewritten result
↓
...
```

---

### 误区 5：有 rules 就一定 terminate

完全错误。

```text
a → b
b → a
```

永远循环。

---

### 误区 6：simplified 是一个客观属性

不是。

正确说法：

```text
simplified
relative to:
    rule set
    rule ordering
    traversal/control strategy
```

---

### 误区 7：这节主要是在学 symbolic algebra

Symbolic algebra 只是 example。

真正主题：

```text
build a language for symbolic transformation
```

# 55. 这节课真正应该记住什么？

如果一个月之后只保留几个东西，我希望是下面这些。

## 5 个核心思想

**① Programs can manipulate programs/data structures symbolically.**

```text
expression itself can be data
```

**② Rules can also become data.**

```text
behavior specification itself
can be represented
```

**③ Separate knowledge from mechanism.**

```text
rules
≠
rule engine
```

**④ Inventing a language is an abstraction technique.**

```text
problem domain
↓
domain language
↓
interpreter
```

**⑤ Complex control flow becomes manageable through contracts.**

不要试图 mentally inline 全部 recursion。

---

## 5 个关键机制

```text
Pattern matching
Dictionary / bindings
Instantiation
Tree traversal
Repeated rewriting
```

---

## 3 个最重要的不变量

### Invariant 1

同一个 pattern variable：

```text
必须始终表示相同 expression
```

---

### Invariant 2

Matcher：

```text
不产生 replacement

只产生：
bindings or failure
```

---

### Invariant 3

`simplify-exp` 的 contract：

```text
输入 expression
↓
返回相对于当前 rule set
已经 simplified 的 expression
```

内部 recursion 多复杂都不应该破坏这个 abstraction。

## 题 1：手动 Pattern Match

Pattern：

```scheme
(+ (* (? x) (? y))
   (? y))
```

分别判断下面两个 expression 是否匹配：

```scheme
(+ (* 3 z) z)
```

```scheme
(+ (* 3 z) x)
```

如果成功，请写出完整 dictionary。

重点不是答案，而是手动模拟：

```text
car match
↓
dictionary
↓
cdr match
↓
dictionary
```

---

## 题 2：为什么 Dictionary 必须 Thread Through Recursion？

假设你错误地写成：

```scheme
(match (car pattern)
       (car expression)
       dict)

(match (cdr pattern)
       (cdr expression)
       dict)
```

两个 recursive call 都使用原始 `dict`。

解释为什么：

```scheme
(+ (? x) (? x))
```

可能错误地匹配：

```scheme
(+ 3 4)
```

思考：

> 前半棵树学到的信息为什么必须传给后半棵树？

---

## 题 3：推演完整 Simplification

有规则：

```scheme
((* 1 (? x))
 (: x))

((* 0 (? x))
 0)

((+ (? x) 0)
 (: x))
```

手动推演：

```scheme
(+ (* 1 a)
   (* 0 b))
```

要求你明确写：

```text
simplify child 1
simplify child 2
rebuild parent
try rules
final expression
```

## 题 4：找出 Non-termination

加入：

会发生什么？
