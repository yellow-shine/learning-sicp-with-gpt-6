# SICP 系统学习路线

面向：能用 Go 独立编写递归、高阶函数和树结构的学习者。教材采用 **SICP 第二版（Scheme）**，训练环境采用 **Racket + `#lang sicp`**。

**目标不是刷完习题，而是能解释：一个抽象解决什么问题、程序如何执行，以及改变设计会付出什么代价。** 我提供代表题实现、推导与运行验证；你可以按顺序直接阅读，不需要答题、提交作业或等待检查。不设完成期限。

## 如何使用这套课程

每单元遵循：**问题 → 核心概念 → 代表题完整解答 → 执行追踪 → 设计取舍与小结**。

1. 先看阅读范围和前置依赖，知道这一节在解决什么。
2. 跟着题解中的具体输入读推导，再运行附带代码。
3. 对照运行结果，留意抽象的作用和适用边界，然后直接进入下一单元。

不设理解检查关卡。第一单元已写好的三个辨析例子保留为可选补充，可以直接看答案。代码中的自动自检用于验证题解，不是对学习者的考试。

## 运行环境

当前编写时已检测到 Racket 9.3 和 `sicp` 包。换机器时先安装 [Racket][racket]，然后：

```sh
racket --version
raco pkg show sicp
# 仅在尚未安装 sicp 时执行：
raco pkg install --auto sicp

# 在本目录运行一个单元：
racket units/01-02-numerical-processes/solutions.rkt

# 可选：验证全部 35 个单元（Python 3 标准库，无需额外包）：
python3 check.py
```

全课脚本逐单元输出 `PASS`，成功时汇总 `35/35 units passed`。它也检查单元是否齐全；缺文件、程序报错或单个进程超过 60 秒都会使验证失败。数值基准的实测时间会波动，不把特定速度比作为通过条件。共享的解释器/机器模块使用相对路径导入，复制课程时请保留整个 `units/` 目录。

也可以用 DrRacket 打开 `.rkt` 文件，选择从源码确定语言，然后点击 Run。每个教学文件以 `#lang sicp` 开头；它基于 R5RS 并做了适配，**不是 Common Lisp，也不是默认的 `#lang racket`**。普通 Racket 的 pair 默认不可变，不能未经调整就用于第三章的可变 pair 示例。详见 [SICP 语言文档][sicp-lang]。

初期不引入项目框架、包管理配置或双语言实现。Go 只用于澄清熟悉概念与 Scheme 的差异。

## 顺序与依赖

第一次学习建议按编号顺序走，减少来回切换。表中的前置是主要概念依赖（传递依赖不重复列），**不是要求写完前面所有习题**。同章相邻单元不一定互为依赖。

例如，04.03 惰性求值器需要 **04.01 的求值器结构 + 03.07 的延迟机制**，不是只读完相邻的 04.02 就能跳过前置知识。每个单元的依赖详见下表。

五条贯穿全书的思想线索（箭头表示联系，不是完整的直接依赖清单）：

- **过程与抽象**：01.02 → 01.05 → 01.06 → 04.01。
- **表示独立性**：02.01 → 02.08 → 02.09 → 04.01 → 05.03。
- **求值模型**：01.01 → 03.02 → 04.01 → 05.04 → 05.05。
- **时间与延迟**：03.01 → 03.06；03.07 → 03.08 → 04.03。
- **语言是工具**：02.05 → 03.05 → 04.01 → 04.04 / 04.05（思想联系，不全是硬前置）。

本章小结：同一个 Scheme 过程可以贯穿“环境模型 → 元循环解释 → 显式控制 → 编译指令”，逐步显式化控制和存储机制。教材使用指定寄存器与保存策略，不等同于现代编译器完整的通用寄存器分配算法；这里的机器也不是一颗真实 CPU 的全部实现。

补齐原稿未展开的图形语言、区间算术、电路模拟、约束传播、`amb`、存储分配/垃圾回收、词法地址等内容。全书主线覆盖不等于每道习题都要做。

几个贯穿课程的纠偏：

- “递归过程”看执行时待完成工作的形状，不只看源码是否自调用。
- 组合的封闭性质（closure property）与词法闭包（lexical closure）不是同一个概念。
- 普通调用会先求参数，但这不保证所有 Scheme 实现都按同一参数顺序求值。
- 正则序、按名调用、按需调用要区分；记忆化不是“延迟”的同义词。
- Lisp 的源表达式可读成列表/符号等数据；运行中的过程值并不就是源码列表。
- Go、数据库和分布式系统类比只是理解辅助，不能代替教材机制或推出完全等价。
