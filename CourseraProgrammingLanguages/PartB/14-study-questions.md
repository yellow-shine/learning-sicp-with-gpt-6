# Answers

1. `*` 真能接受任意个参数。那是一次调用、三个参数。
2. 调用前三个参数都求值，递归在进入 `if` 之前已经发生。
3. `(e)` 是零参数调用。`*` 允许三个参数，所以语法合法；运行时才发现第二个参数是过程。
4. 值有标签。变量只是当前绑定到某个值。表达式没有检查器赋予的类型。
5. Racket 的 `let` 里所有右边都用进入之前的环境，所以两边都看见旧值。ML 的 `let` 是顺序的。
6. 创建 `lambda` 不求值体，调用发生在 `w` 已求值之后。初始化表达式当时就要读 `w`，得到 undefined。
7. 闭包按词法找同一个 binding，`set!` 改了它的当前内容。`c` 里放的是早先算完的值。
8. 不以 `null` 结尾，`list?` 为假，`pair?` 为真。`set!` 只改变量指向什么，不改 cell。改字段要用 `mcons`。
9. 闭包已经能把表达式放进体，并且创建时不跑体。零参数是因为推迟的是这个表达式，不是等一个新参数。
10. 立刻求值；得到函数且不算体；把求值结果当零参数函数调用。
11. 0 次和 7 次。事先算在乘 0 时做了用不到的工作。
12. 结果在纯计算下相同。第一次有副作用和耗时，第二次只读格子，thunk 已经不在。
13. Promise 记住一个零参数计算。有参数必须按参数留表。
14. 没有。Racket 函数参数在调用处求值。Haskell 才是课程点名的 lazy language。
15. List 的每个 `cons` 都要先算出尾巴。Stream 每次只造一个 pair，尾巴是未调用的 thunk。
16. car 是下一个值，cdr 是下一个 stream。把 cdr 传下去，下次消费需要 pair 时才调用。
17. 前者定义时就要查找尚未绑定完的自己。后者定义成功，调用时把调用结果放进 cdr，于是要建无限 list。
18. 不是。它的构造器不先求值尾巴，请求下一个才算。
19. 体内每次调用都新建空表。顶层把实现细节暴露给所有人。
20. 不能。重复发生在递归内部。外层表只记住完整调用。
21. 函数先求值所有参数。Macro 在求值前把使用处重写成 `if` 的语法。
22. 展开结果是 `#f`，`(car null)` 不在后来的程序里。
23. 模式变量被复制到多个求值位置。`let` 能收成一次，但那时函数同样好，所以不该用 macro。
24. Racket 里它是一个标识符。C 里减号是运算符，三个 token，`head` 会被换掉。
25. 不展开。局部变量遮蔽 macro。
26. 使用处的 `y` 被填进 macro 的 `(let ([y 1]) ...)`，两个运算数都是 1。Hygiene 改名，结果是 14。
27. `lo` 和 `hi` 各一次，且按书写顺序；`body` 每次迭代一次；起点不小于终点则 body 零次。
28. 没匹配上规则时，错误还能用 macro 的名字说。匹配了但展开非法，检查发生在展开之后，消息说的是 `let`。
29. 数和字符串已经带着语言的标签，`number?` 能看。ML 的 list 元素必须同一类型，所以要自己的构造器。
30. 更大的语言不只有整数结果。返回“语言里的值”，值也用构造器表示，以后不用改约定。
31. 两者都是取第二个元素，不检查种类符号。值仍是 list。
32. `(add (const 3) (const 4))` 的 `pair?` 和 `list?` 都是假，`add?` 是真。
33. 客户端造不出能通过谓词的值，只能走你的函数。List 谁都能伪造 car 里的符号。
34. Macro 可以生成函数，但造不出一种让 `number?` 和 `pair?` 都为假的新数据。那要内置的 `struct`。
35. Parser：字符串进，语法错误或 AST 出。Interpreter：AST 进，值或对象语言错误出。
36. 语言由语义定义。同一种语义可以解释，也可以编译。速度不是“编译型语言”这个词能解释的。
37. 作为 Racket 表达式求值时只调用构造器。加法在 `eval-exp`。
38. 前者不是合法 AST，可以崩溃。后者是合法树，值种类不对，必须给出对象语言层面的错误。
39. 求值到自身的表达式。返回 `add` 说明计算没做完。
40. 调用者应只看见对象语言的值。宿主语言的 `if` 可以出现在解释器内部，只要最终返回的是 `eval` 的结果。
41. 名字的值在表里，不同子表达式可能要不同的表。全局表无法表达局部绑定。
42. 自由变量要按定义时的环境解释。只保存体会在调用时找错表，或找不到。
43. 词法 13，动态 23。
44. 函数 AST 没有环境，还不是值。闭包把当时的环境冻进可传递的值。
45. 参数求值仍用调用者环境。取出闭包环境、准备求值体的那一步起，不再用它。
46. 函数 AST 不是可调用的值，也不带环境。整个闭包使递归仍用原来的定义环境。
47. “调用必须基于闭包环境，而不是 caller environment。”观察到动态作用域，或定义处有的名字在调用处未绑定。
48. 那是运行时反复扫描语法。预遍在求值前算一次，存在函数上或侧表里。
49. `eval` 之前树已经是 `if-then-else`。它不会给生成的变量改名，也不按对象语言的定义处解析自由变量。
50. 好处：必错的程序，例如把一个值同时送给 `+` 和 `car`，不必运行就排除。代价：能跑的异构返回值和混合 list 也被排除。
51. 每个值都是同一个 datatype 的构造，标签总在。`pair?` 是看不见的模式匹配。
52. 解析已成功，运行尚未开始，程序被拒绝。这是语言定义的一部分。外挂警告不算。
53. `hd` 空列表、数组越界、除以零。也不保证你没把分支写反。
54. Sound 禁止接受会做 X 的程序。Complete 禁止拒绝不会做 X 的程序。假阴性是检查器说不会，其实会。
55. 对非平凡性质，这是不可判定性的后果。要终止又不要假阴性，就必须留下假阳性。
56. X 发生时程序可以做任何事。前三条是收紧类型、保留动态检查、给默认值。
57. 定义仍要求：若检查会失败，必须表现为错误。只在证明不会失败时才能删。
58. 规则变了。这个程序是合法的，不是晚发现的类型错误。
59. `pow1` 支持静态：错误调用形式在运行前被拒绝。`pow2` 支持“反正要测”：`+` 写成 `*`，类型通过，结果是 13。
60. 旧的数字调用行为不变，仍合法。静态这边类型变了，旧调用不再通过；好处是检查器列出每一处，改完你知道没有遗漏。
61. 每件要防的事都可以单独选择何时查，原型和维护阶段答案还可能不同。Typed Racket 把选择留给文件，不取消选择。
62. 它只要求运行时还有能力执行新程序。那个能力可以是编译器。`quote` 给的是树，字符串 `eval` 还要解析。
