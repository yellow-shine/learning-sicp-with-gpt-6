# Part B Problem Chain

每一环都是前一环留下的具体做不到。不是视频目录。

```text
Part A 的函数、环境、闭包、datatype、类型推导，
换一种语法还在吗？课程是不是只是重放？
        │
        │  还在。但 Racket 不靠静态类型系统，语法几乎就是树。
        │  重放只占 Section 5 开头。后面是新问题。
        ▼
没有类型检查器，程序如何组织？
        │
        │  值有标签，变量没有静态类型。
        │  异构 list 直接放。谓词在运行时问。
        │  走不到的表达式里的错误不会被发现。
        ▼
括号这么多，程序还是文本吗？
        │
        │  括号是 term 序列。第一项是特殊形式，否则是调用。
        │  多一个括号就是零参数调用。
        │  解析没有优先级歧义。这是后面能直接写 AST 的原因。
        ▼
绑定的初始化，应该看见哪些名字？
        │
        │  let 看过去，let* 看左边，letrec 看全部，值仍按顺序填。
        │  文件是一个 letrec。跨文件不是。
        ▼
函数式语言为什么还有赋值？
        │
        │  后面的惯用法要记住一个格子。
        │  set! 改绑定的当前内容。已算完的值不跟着变。
        │  闭包仍按词法找那个绑定，但读到的是当前内容。
        │  cons 不能改字段。要改字段用另一类型 mcons。
        ▼
计算是否一定要立即执行？
        │
        │  函数参数是。if 的未选中分支不是。
        │  把 if 包成函数，两支都先算，递归不停。
        ▼
怎样把“现在算”变成“以后算”？
        │
        │  Thunk：零参数函数。创建不算，调用才算，每次调用都重算。
        ▼
不需要就不算，需要多次却只算一次，怎么办？
        │
        │  Promise：mcons(#f, thunk)。
        │  第一次 force 算并覆盖，以后只读。
        │  这是讲师所说的 lazy evaluation 的手写版。
        │  Haskell 把类似规则放进函数调用。Racket 没有。
        ▼
如何表示无限数据？
        │
        │  不能建成无限 list。Eager 的 cons 会在定义时要尾巴。
        │  Stream = thunk，调用得 (值, 下一个 thunk)。
        │  生产者不知道要几个，消费者不知道怎么产生。
        ▼
同一个纯函数、不同参数，重复算怎么办？
        │
        │  一个格子不够。Memoization 是一张表。
        │  表要跨调用存活，又不能放顶层。
        │  递归必须走带表的入口，否则指数还在。
        ▼
函数无法控制参数求值，怎么办？
        │
        │  Macro：求值前把语法变成语法。
        │  可以规定一段语法求值零次、一次或多次。
        │  拿不准就用函数。Macro 经常被用在函数够用的地方。
        ▼
Macro 引入的变量会不会污染调用者？
        │
        │  天真替换会捕捉，也会在使用处查找自由变量。
        │  Hygiene：改名，并且自由变量在定义处解析。
        │  这就是词法作用域用在语法变换上。
        ▼
动态语言如何表示 datatype？
        │
        │  内置值已有标签。自己的表达式树可以先用带符号的 list。
        │  那仍是 list，访问器可以混用。
        ▼
怎样得到一种真正的新数据？
        │
        │  struct。构造器、谓词、访问器一次生成。
        │  pair? 为假。用错访问器就失败。
        │  Macro 造得出语法，造不出这种新种类。
        │  不导出构造器，动态语言也能隐藏表示。
        ▼
Programming language 本身如何执行？
        │
        │  字符串 → parser → AST → 可选类型检查 → 解释或编译。
        │  作业跳过前两步：人用构造器写树，eval 消费树。
        │  没有“解释型语言”这回事。语言由语义定义。
        ▼
解释器要诊断哪些错？
        │
        │  非法 AST 可以崩溃。
        │  合法树上算出来的值种类不对，必须说清楚。
        │  eval 必须返回 value，不能返回还没算完的 add。
        │  宿主语言的 7 不是对象语言的 const 7。
        ▼
变量在哪里寻找值？
        │
        │  在环境里。eval(expr, env) → value。
        │  变量节点不是值。查找失败是对象语言错误。
        │  let 的体用扩展后的环境。程序从空环境开始。
        ▼
函数为什么需要记住定义环境？
        │
        │  体里有自由变量。调用时的环境不是定义时的环境。
        │  只保存代码，就会变成动态作用域，或找不到名字。
        ▼
Closure 怎样实现词法作用域？
        │
        │  eval(fun, env) = closure(fun, env)
        │  调用时在闭包环境上绑定参数，再求值体。
        │  不用调用者环境。
        │  递归：函数名映射到整个闭包，不是函数 AST。
        ▼
闭包保存整个环境，是语义还是粗实现？
        │
        │  语义只要自由变量的绑定。
        │  整个环境是正确但费空间的做法。
        │  预遍算出自由变量；编译时可以把环境变成额外参数。
        ▼
怎样给对象语言加形式，而不改解释器？
        │
        │  Racket 函数把 B 的树变成 B 的树，在 eval 之前跑完。
        │  这是 macro，但是不卫生。有变量时名字要自己避开。
        ▼
Static 与 Dynamic typing 到底各自保证什么？
        │
        │  静态检查：解析后、运行前拒绝。目的是某类行为不会发生。
        │  Sound：通过则不会做 X。Complete：不会做 X 的都不拒绝。
        │  终止 + sound ⇒ 一般不能 complete。于是有假阳性。
        │  动态：值有标签，碰到原语才查。不是没有类型。
        ▼
Weak 是动态吗？
        │
        │  不是。Weak 是既不静态拦也不动态拦，失败了可以做任何事。
        │  Racket 动态，但失败必须表现为错误。
        │  原语接受更多值，是求值规则变了，是第三条轴。
        ▼
所以该选哪边？
        │
        │  没有总冠军。七组权衡都成立。
        │  问的是：这件事要在运行前证明，还是留到测试和运行。
        │  两边都支持的语言仍要人做这个选择。
        ▼
Part C 还剩什么？
        对象和方法查找。课程说那比闭包规则更复杂。
        函数式和面向对象是相反的分解，因此比表面更像。
        Generics 和子类型会回到静态类型。本笔记停在 Part B。
```
