# Programming Languages Part B — Complete Mental Model

不再按视频顺序。读完应能看着一门陌生语言的函数、作用域、闭包、求值策略、datatype、macro 和类型纪律，说出它把哪几件事放在了哪里。

Part A 把这些词教成使用者的语义。Part B 的升级是：闭包要造出来，datatype 不再由类型系统赠送，求值时机可以被推迟或提前重写，类型检查被说成相对某个 X 的近似证明。

---

## 1. Dynamic Languages

Racket 不是“没有类型的 ML”。值有运行时标签。变量没有 `x : int` 这种承诺，它是环境里的一个绑定，当前指向某个值。表达式没有检查器赋予的类型；走不到的表达式里的标签错误不会出现。

原语不相信调用者。`+` 看见字符串就失败，只是失败发生在求值走到它的时候，而不是拒绝整个程序。`number?` 之所以存在，是因为静态语言里检查器已经知道的事，这里要当场问。

一个有用的翻译：每个 Racket 值都是同一个 datatype 的构造，运算前拆标签，运算后把结果再包上标签。`struct` 是这幅图的例外：程序运行中可以增加一种新构造器。ML 不愿这么做，因为穷尽性会失守。

因此组织程序的方式变了，算法不必变。列表递归还是空则基底、否则处理头和对尾递归。变的是契约：没有类型声明，文档和测试变成更弱的替代；你可以让非法值跳过，也可以让它炸。两种都写得出来，语言不再替你选。

括号是这门动态语言的另一半，不是装饰。一个 term 是原子，或括号里的 term 序列。第一项是特殊形式就按那个形式的规则，否则是函数调用。`(f x)` 不是 `f(x)` 的换皮：括号表示树，被调用者在序列里面，多一个括号就是零参数调用。解析没有“乘法比加法紧”这种补丁。所以后面可以直接把树写出来，`eval` 也可以吃 list 而不是字符串。

## 2. Evaluation Strategy

每种构造都必须说明子表达式是否求值、何时求值、求值几次。

Racket 和 ML 的函数调用：参数在进体之前各算一次。`if`：只算测试，再只算一支。`lambda`：创建时不算体。这三句解释了后面几乎所有惯用法。

Eager 不是道德，是默认。它让递归的停机依赖于 `if` 不是函数。把 `if` 包成函数，第三支在进 `if` 之前就递归，任何参数都不终止。

特殊形式是语言里少数不被当成调用的名字。Macro 的作用就是让程序员往这张表里加名字，而且加的动作发生在求值之前。

## 3. Delayed Computation

不想现在算，就把表达式放进零参数函数，先不要调用。Thunk 是闭包的一种用法：代码加上定义时环境，参数列表为空。每次调用都重算。不调用就永远不算。

这在“可能根本不用”时是赚。在“可能用很多次”时是亏，比重先算一次更差。最好的两边是：没有副作用、何时算不影响结果；不需要就不算；需要了就记住。

Promise 用一个可变 pair 做这个记忆。`#f` 加 thunk 表示还没算。第一次 `force` 把 car 改成 `#t`，调用 thunk，用结果覆盖 cdr。以后只读。副作用只发生一次。这就是讲师所说的 lazy evaluation 的手写版。Haskell 把类似规则放进函数参数；Racket 没有，标准库的 `delay` 也只是库，课程选择自己写，以便看见 `mcons`。

Call-by-name 和 call-by-need 这两个名字课程没用。裸 thunk 的形状接近前者，promise 接近后者。不要把它们写进“讲师的术语表”，除非题目自己用了。

## 4. Streams

无限序列做不成一条 list。Eager 的 `cons` 在定义时就要尾巴，环会立刻失败。能做的是：stream 本身是 thunk；调用得到一个有限的 pair；car 是下一个值；cdr 是另一个 thunk。

未请求的尾巴不存在。所以 `1, 2, 3, ...` 只在你不断调用时才多出一个 pair。消费者不知道生产者的公式，生产者不知道要几个。递归函数把 cdr 传下去，不要在传之前调用。

这和 list、iterator、generator、Java Stream 都不是一回事。本课的 stream 不缓存走过的元素，也没有“结束”。Haskell 的惰性 list 更接近，因为构造器默认不算尾巴；那是语言规则，不是你手写的约定。

## 5. Macros

函数变换值。Macro 变换语法。展开在类型检查和求值之前，死分支里也展开。因此它可以删掉一段语法，或把它放进 `lambda`，调用者写起来像特殊形式。

没有任何 Racket 函数能接受 `e` 而不求值它。所以 `my-delay` 若要让调用者不必自己写 thunk，必须是 macro。`my-force` 不需要这个能力，做成 macro 只会把参数语法复制多次。默认用函数。

次数用语法出现的位置控制：`let` 右边是一次，函数体里是每次调用一次，展开结果里不出现就是零次。顺序也一样，因为展开后的函数参数从左到右求值。

Hygiene 是词法作用域用于语法变换。Macro 自己的局部变量改名，以免捕捉使用处的变量。Macro 体里的自由变量在定义处解析，使用处遮蔽 `*` 不会把乘法变成加法。C 预处理器两件都不做，还要和优先级打架。Racket 的使用处本身是一棵子树，所以没有那个优先级洞。

给被解释语言写的 Racket 函数是另一种 macro：树变成树，发生在 `eval` 之前，解释器看不见那个名字。它不卫生。有变量时要自己起不会撞的名字。

## 6. Data Representation

没有 ML datatype 时，one-of 不再是一个类型，而是一组你约定一起处理的值。

语言自带的值已经有标签，`number?` 够用，所以 int 和 string 可以放进同一个 list。自己的表达式树可以先用 list，car 放符号。那能把 `eval` 写出来，但结果仍是 list：两种访问器只要 `car` / `cdr` 的深度相同就可以互换，任何人都能伪造一个看起来像 Add 的 list。

`struct` 不是这套函数的简写。它增加一种新数据。`pair?` 为假，用错访问器就失败。一行声明给出构造器、谓词和访问器。它不给出“这些就是全部变体”，也不给出字段类型。那是动态类型留下的洞。模块里不导出构造器，可以补上“谁有权构造”。Macro 补不上“这是一种新种类”。

求值函数返回表达式，不返回裸整数。基线返回整个 `const`。递归之后取出整数、运算、再包回去。这样以后结果可以是数、布尔、闭包或 pair，返回约定不用改。

## 7. Interpreter Architecture

```text
具体语法 → parser → AST → 可选类型检查 → 解释器或编译器 → 行为
```

解释器是用 A 写的程序，吃 B 的树，给出 B 的答案。编译器把 B 翻译成已有实现的 C。名字都不好：一个是求值器，一个是翻译器。现实实现把两者接成管道。Java 的字节码和 JIT、芯片内部的再翻译，都是这个混合。

语言由语义定义。不存在编译型语言或解释型语言。`eval` 只说明运行时还要有一份实现，那份实现可以是编译器。

作业跳过 parser 和类型检查器。人用 struct 构造器写树。构造器调用建树，不做加法。`eval` 才做加法，并且必须把宿主语言的结果包回对象语言的值。

可以假设树合法。不能假设递归结果是你希望的种类。`(negate -7)` 可以崩溃。`(add (const 1) (bool #f))` 必须给出对象语言的错误，不能暴露 `const-int`。每次 `eval` 都返回 value。返回 `add` 是解释器的 bug。

## 8. Environments

变量不是值。`eval(x, env)` 在环境里查找 `x`。环境是名字到 value 的表，不是调用栈。找不到是对象语言错误。

大多数子表达式把收到的环境原样传下去。`let` 的初始化用旧环境，体用多了一行的环境。程序从空环境开始。`eval-under-env` 留在顶层，是为了评分脚本，不是为了语义。

作用域就是“哪一次递归把哪张表传下去”。三种 `let` 在 Racket 自己里已经演示过：初始化表达式看见过去、看见左边、或看见全部。解释器里你要为对象语言选择一种，并在递归调用里实现它。

## 9. Closures

函数值不能只保存体，因为体有自由变量。定义时的环境和调用时的环境可以不同。只保存代码，要么禁止自由变量，要么使用动态作用域。

```text
Closure = 函数代码 + 定义时的环境
```

求值函数定义，返回的是闭包，不是函数 AST。闭包是 value。源程序不写这个构造器，解释器造它。

调用：在调用者环境里求值函数和参数；确认得到闭包；然后丢掉调用者环境，在闭包环境上绑定参数，再求值体。递归再把函数名绑定到整个闭包，不是绑定到 AST，否则递归调用丢了定义环境。

`x → 10` 时定义的 `λy. x+y`，在 `x → 20` 里用 3 调用，词法结果是 13。用了调用者环境就是 23，那是 bug。

三条不变量：查找用传入的环境；函数值携带定义环境；调用基于闭包环境。

保存整个环境是正确的粗实现。语义只要求自由变量的绑定在。预遍算一次自由变量，换更快的表，是空间和查找的优化，不改变谁看见哪个 `x`。编译到没有闭包的语言时，环境变成额外参数，函数值仍是一对。

Part A 的闭包是使用者心里的一对。Part B 的闭包是解释器构造的 struct。同一句话，从理解变成了必须写对的代码。

## 10. Lexical Scope

词法作用域：自由变量按定义处解释。动态作用域：按调用处解释。同一段程序可以差出 13 和 23。

闭包是词法作用域的自然实现，因为定义时能看见的表，被放进了以后唯一用来求值体的那个值里。动态作用域不需要这个值，调用时用当前表即可。它更简单，也不是这门课的语言。

Hygiene 是同一规则的另一处出现。Macro 的自由变量在定义处解析，局部变量不捕捉使用处。函数早就这样。文本替换退回了动态查找。

`set!` 不推翻词法作用域。闭包仍找定义时的那个 binding。变的是 binding 的当前内容。已经算完、放进别的格子的值不跟着变。

## 11. Static vs Dynamic Typing

静态检查：程序已经解析，尚未运行，仍被拒绝。这是语言定义的一部分，不是外挂警告。类型系统的做法是给表达式定类型。目的是某类运行时行为不会发生。两件事要分开。没有检查器能读心，所以写反的分支、`+` 写成 `*`，都不是它的 X。

相对这个 X：sound 是通过则不会做 X，没有假阴性。Complete 是不会做 X 的都不被拒绝，没有假阳性。实际系统追求 sound。Generics 这类特性常常是为了少一点假阳性。非平凡性质上，终止、sound、complete 不能兼得。选择前两个，于是死代码里的坏运算仍会让整个程序被拒绝。

检查时机是一条轴，不是两个点。编译时和运行时最常见。浮点除以零返回无穷，比异常更晚，而且是有用的设计。

Weak 是第三条事：通过了静态检查，运行时仍可做任何事，因为该做的动态检查可以不做。C 和 C++ 是这个。数组越界是主要例子，而人们通常不把它叫类型错误。Racket 不是 weak：定义要求失败表现为错误；实现只有在证明检查不会失败时才能删掉它。

原语若把 `"foo"+3` 定义成 `"foo3"`，那是求值规则变宽，不是动态检查。合法程序变多，bug 可能永远不宣布。

七组权衡都成立：方便、被拒绝的有用程序、早发现 bug、性能、重用、原型、维护。没有总冠军。更好的问题是，对这个软件的这件事，要在运行前证明并接受假阳性，还是留到测试和运行。语言两边都支持，人不因此免于选择。

## 依赖，压成三张图

```text
高阶函数
    → 闭包（代码 + 环境）
        → 环境必须是解释器的数据
            → eval(expr, env) → value
```

```text
Eager
    → 不用的参数也付费，包出来的 if 停不下来
        → Thunk
            → 用多次会重算
                → Promise / 讲师所说的 lazy evaluation
                    → Stream（推迟的是尾巴，不是同一个结果）
                        → Memoization（推迟的是重复的带参计算）
```

```text
括号语法
    → 没有优先级歧义的树
        → Macro 按树展开，或人直接写 AST
            → 解释器只消费树
```

三条线在“宿主函数生成对象语言的树”处相接：那是 macro 的时间点，加上解释器的输入格式。它不卫生，因为卫生需要对象语言的作用域信息，普通 Racket 函数在填 struct 时没有那套信息。

## 典型误区

| 说法 | 纠正 |
| --- | --- |
| `()` 只是 Lisp 的怪语法 | 括号是树。多一个就是零参数调用。少一个就把调用拆成多个参数，或把特殊形式的元数弄错 |
| Dynamic typing = no typing | 值有标签。可以看成只有一个大类型。缺的是运行前的证明 |
| Closure = function pointer | 指针没有自由变量的绑定。没有环境就没有词法作用域 |
| Stream = list | Stream 是 thunk。List 在构造时就把尾巴算完。调用 stream 才得到 pair |
| Thunk = thread | 没有并发。零参数闭包。Future / async Promise 是别的语义 |
| Macro = function | 函数看见已求值的参数。Macro 在求值前替换语法。复制语法就是复制求值 |
| Interpreter = parser | Parser 产树或语法错误。Interpreter 消费树，产对象语言的值 |
| Environment = call stack | 环境是名字到值的表。对象语言的一次调用是一次带着新表的递归 `eval`。栈是宿主语言自己的调用 |
| Static typing = strong typing | 静/动是何时查。Weak 是查失败了也不必表现为错误。Racket 动态但不是 weak。C 有静态检查但是 weak |
| 有 `eval` 所以是解释型语言 | 只说明运行时要有实现。实现可以是编译器。课程否认“解释型语言”这个说法 |
| Racket 的 `let` 等于 ML 的 `let` | ML 的是 `let*`。Racket 的 `let` 所有右边都看过去 |
| `set!` 改数据 | 它改变量指向什么。改 pair 字段是 `set-mcar!`，而且只对 `mcons` |
| Lazy = 用了 thunk | Thunk 每次调用都重算。Lazy 在本课还要记住。Racket 的函数参数仍是 eager |
| Struct = 少写的 list | `pair?` 为假。用错访问器失败。Macro 造不出这个 |
| Sound = 没有 bug | 只相对于声明的 X。`+` 写成 `*`、分支写反，都不是那个 X |
| 闭包必然慢 | 简单实现费的是空间，因为留了用不到的绑定。自由变量的小环境保持同一语义 |

## 看一门陌生语言时的问题单

1. 函数调用的参数，是进体前算一次，还是用到才算，还是用到才算并记住？
2. 条件是特殊形式还是函数？自己写一个 `if` 会不会把两支都算掉？
3. 自由变量按定义处还是调用处解析？函数值里有没有环境？
4. 赋值改的是绑定，还是一块共享数据的字段？默认的数据结构可不可变？
5. 新的变体是真正的新种类，还是约定在某个字段里放标签？用错时失败还是静默？
6. 有没有在求值前重写语法的机制？它卫生吗？它按树还是按字符工作？
7. 哪些错误在运行前拒绝，哪些在碰到值时拒绝，哪些发生了也不必表现为错误？
8. 静态检查若存在，它声称的 X 是什么？它是否接受假阳性以换取 sound 和终止？

这八问能定位。它们不代替那门语言的手册。Part B 的目标就是让这八问问得出来。
