# Section 5.1 从 ML 到 Racket：没有类型检查器时，程序还是什么

标注见 `00-course-map.md`。本章覆盖 Section 5 前 12 讲：语言骨架、括号、动态类型、绑定、mutation、pair。延迟求值从 `02` 开始。

---

## 这一章真正要换的眼镜

**【课程】** Racket 仍是 mostly functional：匿名函数、一等闭包、一切皆表达式。`[字幕可能有误]` 导论句 “we need return statements” 与后文矛盾，应按 “everything is an expression, so we don't need return statements” 理解。递归、列表、高阶函数都还在。

所以换语言不是为了重学 `map`。讲师点名两个必须换语言才能看见的差别：

1. Racket 不靠静态类型系统。数字加字符串可以写进文件；错误推迟到那个表达式真的被求值。
2. 语法极简。分组几乎全靠括号，而不是每种构造一套特殊规则。

**【讲解】** 更换语言之后，对“程序”的理解变在三处，而不是变在关键字表：

| | ML（Part A） | Racket（这里） |
| --- | --- | --- |
| 程序在跑之前被证明了什么 | 类型推导拒绝一大类程序 | 几乎只检查语法和少数静态问题（后文 Section 7：未绑定变量在点 Run 时会被查） |
| 一个变量“是”什么 | 有类型的绑定，如 `x : int` | 一个 identifier 当前绑定到某个 **value**。值有运行时标签，变量没有静态类型 |
| 一段文本如何变成结构 | 解析器要处理优先级、中缀、语法糖 | 括号把文本几乎直接写成树。`(+ 3 4)` 就是一棵以函数调用为根的树 |

后面所有惯用法——异构列表、`set!`、thunk、macro、用手写 datatype——都依赖这三处变化。若只记住 “Racket 括号多、没类型”，后面的解释器会对不上。

**【课程】** 历史定位，避免和旧经验打架：Racket 从 Scheme 演进而来，约 2010 年设计者停止使用 Scheme 这个名字，以便做不兼容改动。你最可能踩到的不兼容是：**列表元素不可变**，和 ML 一样，和传统 Scheme 不一样。空列表写成 `null`，不是 `'()`。讲师偶尔说漏嘴叫 Scheme，指的是这一族语言。

**【课程】** 文件的两行仪式：

```racket
#lang racket
(provide (all-defined-out))
```

`#lang racket` 是因为 DrRacket 能跑多种语言，必须声明这一文件是 Racket。第二行是课程的简化：Racket 默认每个文件是一个模块，内容私有；作业把测试放在第二个文件，所以这行把本文件全部公开。这不是语言核心，是课程工程约定。注释以分号开头，直到行尾。

DrRacket 的 definitions 窗口对 Part A 的 Emacs buffer，interactions 窗口对 REPL。点 Run 执行定义。成功时 REPL 不像 ML 那样打印类型，只给提示符；失败才报错。

## 编程模型：定义、调用、特殊形式

### 问题

怎样用最少的语法规则，表达 Part A 已经会的 val、函数、递归和条件？

### 机制

**【课程】** 定义就是：

```racket
(define x 3)          ; 像 ML 的 val x = 3
(define y (+ x 2))    ; + 是函数。调用写成 (函数 参数 ...)
```

函数调用的形状永远是：

```text
(e0 e1 e2 ... en)
```

先求值 `e0` 得到要调用的函数，再求值各参数，然后进入函数体。`+`、`*`、`=`、`-` 都是普通函数，只是名字碰巧是符号。这和 `f(x)` 不是同一棵树：传统语法把括号留给“调用”，把 `+` 放在参数中间；Racket 的括号表示“一个序列”，序列的第一项决定它是调用还是特殊形式。下一节展开。

匿名函数用 `lambda`，对应 ML 的 `fn`：

```racket
(define cube1
  (lambda (x)
    (* x (* x x))))

(define cube2
  (lambda (x)
    (* x x x)))          ; * 本身可以吃任意个参数
```

**【课程】** `(* x x x)` **不是** ML 那种元组或柯里化的语法糖。Racket 的函数真的可以有 0、1、2、3……个参数。课程不教你如何自己定义可变参数函数；作业也不需要。

定义函数的简写是语法糖，展开后就是上面的 `define` + `lambda`：

```racket
(define (cube3 x)
  (* x x x))
; 等价于 (define cube3 (lambda (x) (* x x x)))
```

多个参数就放在函数名后面、右括号之前：`(define (pow1 x y) ...)`。

**【课程】** 递归不需要 ML 的 `fun` / `val rec` 那种额外构造。顶层 `define` 的语义是 letrec 式的（见后面“顶层绑定”），所以函数体里可以直接叫自己。

```racket
(define (pow1 x y)          ; 只考虑 y >= 0
  (if (= y 0)
      1
      (* x (pow1 x (- y 1)))))
```

`if` 是特殊形式，不是函数：

```text
(if e1 e2 e3)
```

没有 `then` / `else` 关键字。三个表达式依次排开。语义上只求值 `e1`，再求值 `e2` 或 `e3` 之一。这和函数调用“参数全求值”的差别，是下一章 thunk 的全部动机。现在先记住：`if`、`define`、`lambda`、后来的 `cond`、`let` 都不是函数调用。

**【课程】** 柯里化仍然只是闭包惯用法，不是语言特殊支持。Racket 有多参数函数，所以柯里化不常见，本课后面也少用。定义柯里化函数有语法糖，讲师说配套代码里有，视频没展开，这里不编造那种糖。**调用**没有糖。要算 \(4^2\)：

```racket
(define pow2
  (lambda (x)
    (lambda (y)
      (pow1 x y))))

(define three-to-the (pow2 3))
(three-to-the 2)     ; 9
((pow2 4) 2)         ; 16。少一层括号就是另一种程序
```

括号永远有意义。这是下一节调试练习的预告。

### PL Insight

特殊形式是语法里的例外：第一项是关键字时，其余项不按“参数全求值”处理。一门语言的表达力，很大一部分就在这些例外的求值规则上。Racket 把例外收得很小，所以你能在一页纸上写下全部语法。这是后面 macro 能“增加特殊形式”的原因：macro 扩展的就是这张关键字表。

## 列表：和 ML 同一抽象，换一套名字

**【课程】** 这一段对应 Part A Section 1 用函数拆列表的那种用法，不是模式匹配。

| 想法 | ML | Racket |
| --- | --- | --- |
| 空列表 | `[]` | `null`。不是 `'()` |
| 构造 | `::` 中缀 | `(cons x xs)`，函数在前 |
| 头 / 尾 | `hd` / `tl` | `car` / `cdr`（读作 “could-er”） |
| 是否为空 | `null` 函数 | `null?`。空列表的值叫 `null`，谓词叫 `null?`，名字容易混 |
| 一次构造很多元素 | 语法糖 | `(list e1 e2 ... en)`：先求值 n 个表达式，再做成长度为 n 的列表 |

`car` / `cdr` 是几十年前机器指令名的历史事故，不要从英语里找意义。

```racket
(define (sum xs)
  (if (null? xs)
      0
      (+ (car xs) (sum (cdr xs)))))

(define (my-append xs ys)
  (if (null? xs)
      ys
      (cons (car xs) (my-append (cdr xs) ys))))

(define (my-map f xs)
  (if (null? xs)
      null
      (cons (f (car xs))
            (my-map f (cdr xs)))))
```

名字里的连字符是 Racket 惯例：`my-append`，不是 `my_append` 或 `myAppend`。三种写法语法都合法，惯例不同。`append` 和 `map` 是内置的，所以课程用 `my-` 避免遮蔽。遮蔽在 Racket 里比你想的更容易把自己绕晕。

REPL 把列表印成 `'(4 5 6)`。那就是 `(cons 4 (cons 5 (cons 6 null)))`。函数值印成 “procedure”，和 ML 印 “fn” 同类：实现拒绝把代码倒出来。

**【课程】** 没有类型检查器时，这段代码“能通过 Run”：

```racket
(sum (list 3 "hi"))
; + 期望 number，得到字符串 "hi"。错误在运行时，并且 DrRacket 会指向出错表达式
```

这是动态类型的第一口味道：程序结构合法，值的标签不匹配，直到 `+` 真的看到那个字符串。

### 执行 trace：`(sum (list 3 4))`

```text
sum (cons 3 (cons 4 null))
  null? → #f
  (+ (car → 3) (sum (cdr → (cons 4 null))))
      sum (cons 4 null)
        null? → #f
        (+ 4 (sum null))
            sum null → 0
        → 4
  → 7
```

和 ML 的递归列表函数是同一棵递归树。变的不是算法，是“类型错误不再在这棵树开始长出来之前被剪掉”。

## 括号：语法即树

### 问题

为什么满屏括号反而是优点？`(f x)` 和 `f(x)` 概念上差在哪里？

### 语法规则，几乎全部

**【课程】** 忽略少数边角，一个 term 要么是原子（atom，不可再分），要么是括号里的 term 序列。

原子包括：`#t`、`#f`、数、字符串、变量名，以及少数特殊形式的名字：`define`、`lambda`、`if`，后来还有 `cond`、`let`、`let*`、`letrec`、`begin`、`set!`、`quote`、`define-syntax`。Macro 的意义就是让程序员增加新的特殊形式。

```text
term ::= atom | ( term term ... )

若序列第一项 t1 是特殊形式：按该形式自己的规则解释其余项
否则：这是函数调用
```

因此：

```racket
(+ 3 (car xs))     ; + 不是特殊形式 → 三元序列，函数调用
(lambda (x)        ; lambda 是特殊形式 → 下一项是参数列表，再下一项是函数体
  (if ...))        ; 函数体本身又是一个 term
```

方括号和圆括号完全同义，只是风格。DrRacket 会在你键入圆闭括号时，若匹配的是方开括号，就自动改成方闭括号。课程不挑剔，但 `cond` 的分支、`let` 的绑定惯例用方括号。

### 从字符到树：为什么这对语言实现重要

**【课程】** 编译、运行、按 Tab 缩进，真正要的都不是“几行字符”，而是树。以 cube 为例：

```text
源码字符                     树
(define cube                 define
  (lambda (x)               /      \
    (* x x x)))          cube      lambda
                                 /        \
                               (x)         *
                                          / | \
                                         x  x  x
```

有了括号和前缀，这个转换（parsing）没有歧义。不存在 “`x + y * z` 是加在上还是乘在上” 这种必须另学优先级的问题。学校里学过的“乘法比加法紧”是中缀语法的补丁。Racket 的补丁是：多写括号，运算符放在前面。

**【讲解】** 这就是 Part B 后半解释器能跳过 parser 的伏笔。若具体语法几乎就是树，程序员可以直接把树写出来。`eval` 接受 list 而不是字符串，也是同一事实（Section 7 可选讲）。

### `(f x)` 不是 `f(x)` 的换皮

| | 传统 `f(x)` | Racket `(f x)` |
| --- | --- | --- |
| 括号的意义 | 标记“这里发生调用”，常可省略或乱加 | 标记“这是一个 term 序列” |
| 被调用者的位置 | 括号外面 | 序列第一项，本身可以是任意表达式 |
| 额外括号 | 往往只影响阅读或优先级 | **永远改变含义** |

**【课程】** 在大多数位置，`(e)` 的意思是：求值 `e`，把结果当函数，用 **0 个参数** 调用它。`((e))` 是：调用 `e` 的结果，再把那个结果用 0 个参数调用。这完全合法——你可能真的有返回 thunk 的函数——但若不是你的本意，运行时才会炸，而且炸在函数体被执行的那一次，不是点 Run 的那一次。

没有静态类型把“整数”和“函数”分开，所以 `(1)` 能写进文件。

### 括号不是审美问题

**【课程】** 讲师的辩护不是“你应该喜欢括号”。HTML 用更长的 `<foo>...</foo>` 做同样的树，很少有人因此否定 Web。语法偏好可以是非理性的；因为不喜欢括号就拒绝 Racket 的语义，像历史学家因为不喜欢某国口音就不研究该国历史。课程不教哪种语法好。它要求你穿过括号去看构造、作用域和求值。

**【扩展】** tokenization、parenthesization、abstract syntax 这三个词，讲师在 macro 可选讲里才正式用来讨论 macro 系统如何切词。括号讲本身已经把 parsing = 从字符串到树讲完了。细节见 `04`。

## 括号调试：每一种错法都是另一种程序

**【课程】** 习惯于“多加括号帮自己看”的人，在 Racket 里会越加越错。正确策略：放慢，想每个括号在构造哪一次调用；搞不清就删掉重写；缩进必须反映树。

下面都是阶乘。正确版本：

```racket
(define (fact n)
  (if (= n 0)
      1
      (* n (fact (- n 1)))))
```

`(fact 5)` → 120，`(fact 10)` → 3628800。Racket 的数可以很大，这不是本讲重点，但说明运行时没有悄悄溢出截断这个例子。

| 版本 | 错在哪 | 何时发现 | 错误在说什么 |
| --- | --- | --- | --- |
| `fact1`：基线写成 `(1)` | `(1)` = 用 0 个参数调用 1 | 点 Run 成功。调用到 `n = 0` 才炸。此前已递归约 5 次 | application: expected procedure, given 1; no arguments |
| `fact1b`：同样把 1 加上括号，但递归写成 `fact` 而不是 `fact1b` | 几乎总是跳进上面那个正确的 `fact` | 只有原参数就是 0 才炸 | 看起来“能工作”是因为根本没测到坏分支 |
| `fact2`：`(= n 0)` 少了括号 | `if` 后面有 5 段：`=`、`n`、`0`、`1`、乘法 | **语法错误**，还没运行 | `if` 必须恰好 3 段 |
| `fact3`：`(define fact3 (n) ...)` | 左括号放在参数前，而不是函数名前 | 语法错误 | define 一个变量后跟了两个表达式。函数定义的括号在名字前 |
| `fact4`：`(* n fact4 (- n 1))` | `*` 吃任意个参数，这里吃了 3 个：`n`、函数 `fact4`、`n-1` | 运行到乘法 | `*` 的第二个参数是 procedure，不是 number。ML 的类型检查器会在运行前抓住 |
| `fact5`：`(fact5)` | 递归调用给了 0 个参数 | 运行时 | procedure expects 1 argument, given 0 |
| `fact6`：把 `*` 放在第二位，写成用 `n` 去调用 | `(n * ...)` 把数当函数 | 基线 `n = 0` 正常。错误在递归**返回的路上**才第一次被发现：试着把 `1` 当函数调用 | 你以为错在最初的 `n = 5`，其实最外层调用还没执行到那次错误应用 |

**【讲解】** `fact6` 的精确报错文本在字幕里有两处互相打架（“given 5” 与 “given 1”）。可靠的课程结论是：求值先把递归做完，再在最小的那个 `n` 上尝试把数当函数，所以栈已经展开到基线附近。自己读树，有时比系统的报错更接近你原本想写的程序。

这张表就是动态类型把错误从 compile-time 挪到 run-time 的实验记录。语法错误仍然很早（`if` 的元数、`define` 的形状）。“把数当函数”“参数个数不对”“把函数传给 `*`”都要有测试走到那条路径。

### 一句话

括号是结构，不是语气。多一个括号 = 多一次零参数调用。少一个括号 = 把本该是调用的东西拆成几个独立参数，或把特殊形式的元数弄错。

## 动态类型：值有标签，检查器不在场

### 问题

没有 datatype 绑定和构造器，怎样写一个能对“数和列表任意嵌套”求和的函数？

**【课程】** ML 做不到把数和 `int list` 放进同一个 list，除非先声明 datatype 和构造器。那不是数据本身做不到，是类型检查器不允许。Racket 没有这个检查器，所以可以直接做。代价是：测试必须真的执行到错误表达式，否则 `n * x` 这种笔误（把 `*` 写在中间）会安静地留在文件里。

### 概念区分（本章最需要记牢的一张表）

| 东西 | 在 Racket 里有没有“类型” | 课程里的说法 |
| --- | --- | --- |
| 值（value） | 有运行时标签。数就是数，pair 就是 pair，函数就是函数 | 后面 Section 7 的精确说法：不是“没有类型”，而是实现给每个值加上构造器标签 |
| 变量（variable） | 没有静态类型。它是环境里的一个绑定，当前指向某个值 | `x` 绑定到某值；`set!` 可以改这个绑定指向别的值 |
| 表达式（expression） | 没有类型检查器赋予的类型。它求值成一个值 | 走不到的表达式里的标签错误不会被发现 |
| 谓词（predicate） | `number?`、`string?`、`list?`、`pair?`、`null?` 在运行时看标签 | 静态语言里往往不需要问“这是不是数”，因为检查器已经知道 |
| 错误检测 | 从“拒绝程序”变成“在用错标签的原语上抛错” | `car` 作用在字符串上，是运行时错误 |

**【讲解】** “Dynamic typing = 没有类型”是错的。动态类型语言仍然区分数、函数、pair。它缺少的是：在运行前，根据程序结构证明某些标签错误不会发生。变量不携带 `int` 这种承诺；值携带标签。这就是为什么动态类型几乎总要运行时检查：`+` 不能相信调用者，必须看参数的标签。

Section 7 会把这说成“万物都是同一个 ML datatype 的值，标签是构造器”。这里先用这张表够用。

### 代码：嵌套求和

```racket
(define xs (list 4 5 6))
(define ys (list (list 4 5) 6 7 (list 8) 9 2 3 (list 0 1)))
; 还可以更深：(list (list 4 5) ... (list 5 0) ...) 仍然是合法数据

(define (sum1 xs)                 ; 参数遮蔽上面的 xs，这是正常的
  (if (null? xs)
      0
      (if (number? (car xs))
          (+ (car xs) (sum1 (cdr xs)))
          (+ (sum1 (car xs))      ; 假定不是数就是列表
             (sum1 (cdr xs))))))
```

`(sum1 xs)` → 15，`(sum1 ys)` → 45（讲师希望你自己加对）。更深的 `(list (list (list 4)) 5 (list 7 2))` → 18。

若深处有字符串：`sum1` 假定“不是数就是列表”，于是对字符串做 `car`，运行时错误。这是动态语言里误用函数的典型结局：错误发生在库函数的内部假设被打破的那一层，不一定在调用者写错的那一行附近。

第二个版本选择另一种契约：非数非列表就跳过，当作对总和贡献 0。

```racket
(define (sum2 xs)
  (if (null? xs)
      0
      (if (number? (car xs))
          (+ (car xs) (sum2 (cdr xs)))
          (if (list? (car xs))
              (+ (sum2 (car xs)) (sum2 (cdr xs)))
              (sum2 (cdr xs))))))
```

于是曾经失败的输入现在得到 14（跳过那个非数）。把某个 5 换成 `#f`，得到 13。`sum2` 仍假设**最初的参数**是列表：直接 `(sum2 "hi")` 会在还没确认它是列表时就取 `car`。若还要让任意值都返回 0，讲师留作练习。

**【课程】** 风格选择是：强制调用者传对，否则报错；还是对奇怪的值采取默认行为。两种都写得出来，因为没有类型声明能替你记录意图。文档和测试变成类型声明的替代品，而且更弱：测试没覆盖到的路径等于没有声明。

异构列表本身无碍：

```racket
(define zs (list #f "hi" 14))
(car zs)    ; #f
(cdr zs)    ; '("hi" 14)
```

### PL Insight

类型检查器是一个在运行前根据程序结构拒绝程序的定理证明器（Section 7 会把这个说法收紧）。拿掉它，数据构造变自由，错误检测变晚，函数的契约从“类型即文档”变成“注释 + 测试 + 运行时谓词”。这不是更简单，是把证明义务从编译器挪到了测试和谓词上。

## `cond`：嵌套 `if` 的形状，以及“真”的定义

**【课程】** 当 else 分支本身又是 `if` 时，用 `cond`。可以把它看成嵌套 `if` 的语法糖，也可以把二元 `if` 看成只有两个分支的 `cond`。课程不在乎你用哪种方向记忆。

```racket
(cond
  [test1 expr1]
  [test2 expr2]
  ...
  [#t    expr-default])
```

从左到右找第一个求值为真的测试，求值对应表达式，那就是结果。后面的测试和表达式不算。方括号只是惯例。

**【课程】** 最后一支的测试应该是 `#t`。若所有测试都是假，`cond` **不报错**，返回一个奇怪的 void 对象。调用者通常不会想要它，于是错误被推迟成更难读的下游错误。

`sum1` / `sum2` 改写成 `sum3` / `sum4` 后，三个测试 `null?`、`number?`、`#t`（或再加 `list?`）并排，比嵌套 `if` 更容易核对与 ML 的三个 case 是否对应。`sum3` 的 `#t` 分支仍假定第一个元素是列表；`sum4` 在跳过之前显式问 `list?`。

### 什么算真

**【课程】** `if` 和 `cond` 的测试不必是布尔。只有 `#f` 走假分支。其他一切——`34`、空列表、字符串——都算真。空列表、空字符串在某些动态语言里算假，**在 Racket 里不算**。

```racket
(if 34 14 15)     ; 14
(if null 14 15)   ; 14
(if #f 14 15)     ; 15
```

静态类型语言要求测试是 `bool`，因为每个表达式恰好一个类型，放一个 `int` 在那里没有额外信息。Racket 可以这么做，是因为它本来就允许任何值流到任何位置。

讲师自己不是这个特性的爱好者，但它强化了动态类型。有人认为是坏风格，有人觉得方便，有人看场合。课程要求你知道语义，不要求你爱用它。

一个它确实短的例子：统计列表里有多少个 `#f`。非假就递归，不需要 `(not (eq? (car xs) #f))` 这种绕法：

```racket
(define (count-falses xs)
  (cond [(null? xs) 0]
        [(car xs) (count-falses (cdr xs))]   ; 不是 #f，就不计数
        [#t (+ 1 (count-falses (cdr xs)))]))
```

`(count-falses (list 34 #t "hi"))` → 0。加进四个 `#f` → 4。

## 局部绑定：三种 let，三种环境

### 问题

ML 只有一种 `let`。为什么 Racket 要 `let`、`let*`、`letrec`，再加函数体里的局部 `define`？

**【课程】** 因为这三种语义都合理，而且各有最方便的场合。看见一门语言把三种定义都留下来，是在逼你把“绑定表达式在哪个环境里求值”说清楚。这比多记一个关键字重要。

语法（`let*`、`letrec` 同形，只是关键字不同）：

```racket
(let ([x1 e1]
      [x2 e2])
  body)
```

只有一个绑定时，里面那层括号也不能省。`let` 的右括号在 body 之后。

`max-of-list` 用它避免对同一个尾部做两次递归（Part A 见过的指数爆炸）：

```racket
(define (max-of-list xs)
  (cond [(null? xs) (error "empty list")]
        [(null? (cdr xs)) (car xs)]
        [#t (let ([tlans (max-of-list (cdr xs))])
              (if (> tlans (car xs))
                  tlans
                  (car xs)))]))
```

`error` 是内置的，求值到它就停。假定列表非空且只含数。

### 三种环境，用同一个“傻的加倍”看清

设参数是 `x`。

**`let`：所有 `ei` 都在 let 之前的环境里求值。** 不是 ML。

```racket
(define (silly-double x)
  (let ([x (+ x 3)]
        [y (+ x 2)])
    (- (+ x y) 5)))
```

右边两个 `x` 都是参数。`x` 局部绑定 = 参数 + 3，`y` = 参数 + 2，相加再减 5 = `2 * 参数`。

没有遮蔽时，这和 `let*` 结果相同，所以不遮蔽时课程推荐用 `let`，它在告诉读者“这些初始化互不依赖”。它还有 ML 做不到的方便：交换。

```racket
(let ([x y]
      [y x])
  ...)
```

Racket 的 `let` 下，body 里 `x` 是旧的 `y`，`y` 是旧的 `x`。ML 的 `let` 会让第二个绑定看见第一个，于是两个都变成旧的 `y`。

**`let*`：每个 `ei` 在前面的绑定已经加入后的环境里求值。** 这就是 ML 的 `let`。没有它，你得嵌套写 `let`。

```racket
(define (silly-double* x)
  (let* ([x (+ x 3)]
         [y (+ x 2)])      ; 这个 x 是刚绑定的那个
    (- (+ x y) 8)))        ; (x+3) + (x+5) - 8 = 2x
```

**`letrec`：所有绑定，包括后面的，都在环境里。** 表达式仍然按书写顺序求值。这是互递归需要的，类似 ML 的 `and`（讲师的说法是 “more like ML's and for mutually recursive things”）。

```racket
(define (silly-triple x)
  (letrec ([y (+ x 2)]
           [f (lambda (z) (+ z y w x))]
           [w (+ x 7)])
    (f -9)))
```

调用时 `z = -9`，`y = 参数+2`，`w = 参数+7`，`x = 参数`，加起来是 `3 * 参数`。`w` 出现在 `f` 的定义之后，`let` 和 `let*` 都做不到这个前向引用。

为什么函数体里引用还没求值的 `w` 却是安全的？因为求值 `lambda` **不**求值函数体。顺序是：先算 `y`，再创建 `f` 的闭包（体还没跑），再算 `w`，然后才调用闭包。那时 `w` 已经有值。

若把 `y` 改成 `(+ w 2)`，`w` 虽然“在环境里”，但还没被求值。Racket 不因此立刻报错，而是给出一个奇怪的 undefined，随后 `+` 作用在 undefined 上才报错。这是 bug，不是技巧。

**【课程】** 建议：`letrec` 只用于互递归函数。其他场合前向引用几乎总是错误。

偶数 / 奇数的互递归（只对非负整数；偶数返回 0，奇数返回 1）是 `letrec` 的正当用例。幻灯片用希腊字母 λ，DrRacket 允许，但作业不要交 Unicode，写成 `lambda`。逻辑留给你自己顺着调用走；要点只是 `even` 的体调用 `odd`，`odd` 的体调用 `even`，所以两个绑定必须同时在环境里。

另一个反例：在绑定还没求值时就在表达式（不是函数体）里使用后面的名字，会撞上 undefined。不要写。

### 局部 `define`

**【课程】** 在函数体的特定位置可以直接写 `define`。语义与 `letrec` 相同：全部在环境里，仍按顺序求值，前向引用只应出现在尚未调用的函数体里。

Racket 的主要使用者和设计者现在更推荐：需要 `let` / `let*` 的特殊语义时用它们；若三种结果相同，或你其实需要 `letrec`，用局部 `define`。课程相反，更想让你看见三种语义，所以讲解用 `let` / `let*` / `letrec`。作业两种都接受。

### 环境图

```text
调用 silly-double* 时，参数 x = 10

let* 之前的环境:  { x ↦ 10 }

求值 (+ x 3) 用这个环境 → 13
加入绑定后:           { x ↦ 13 }     ; 遮蔽

求值 (+ x 2) 用新环境 → 15
body 的环境:          { x ↦ 13, y ↦ 15 }
```

`let` 的图不同：两个右边都只看见 `{ x ↦ 10 }`。`letrec` 的图是：一开始三个名字都在环境里，但值按顺序填入；填入之前去用，得到 undefined。

### PL Insight

“let 的意义”不是一个自然事实。它是语言设计者对“初始化表达式看见哪些绑定”的选择。三种选择都自洽。好的语言让你把选择写在关键字里，读者就不用猜。

## 顶层绑定：一个文件就是一个 letrec

**【课程】** 文件里的一串 `define` 像 `letrec`，也像局部 `define`：可以引用更早的绑定，也可以引用更晚的绑定。求值仍按顺序。引用更晚的名字，应当只出现在函数体里，并且那个函数在被引用的表达式求值完成之前不被调用。

和函数内部的 `letrec` 有一个细节差：顶层过早引用不是 undefined，而是错误 `reference to an identifier before its definition`。课程说这个差别不必深究。

```racket
(define (f x) (+ x b))   ; b 在后面。安全，因为体还没跑
(define b 3)
(define c (+ b 4))       ; 7。用更早的绑定，像 ML
; (define d (+ e 1))     ; 若 e 在后面：错误，不是 undefined
; (define f 17)          ; 同一文件两个 f：duplicate definition
```

不能在同一文件里遮蔽。两个同名绑定是往同一个环境里放两次，没有意义。

这不是免费的午餐。优点是前向引用方便；缺点是过早引用会错，以及失去文件内遮蔽。

**【课程】** REPL 既不完全像 `letrec`，也不完全像 `let*`。正常用没问题。已知坑：在 REPL 里遮蔽标准库的名字，又定义递归函数，会出很怪的事。绕开方法：不要在 REPL 里定义自己的递归函数。放进文件再 Run。调用文件里已经定义好的递归函数是安全的。

**【课程】** 技术上，说“文件顶层”并不准确。每个文件隐式是一个模块。模块内部仍是 letrec 语义，所以上面的例子成立。跨文件不是一个大 letrec：每个文件自己的 letrec，可以 include / 使用另一个文件的东西，也可以遮蔽另一个模块的绑定。`+` 只是标准库模块里的函数，你甚至可以在自己的文件里遮蔽它——每个文件只能定义一次。这种遮蔽是坏风格，但它解释了模块边界：遮蔽发生在模块之间，不发生在模块内部。

讲师说过若有时间会可选地讲模块系统。本批字幕没有单独的模块讲。上面这些就是课程在 Part B 里关于模块实际说过的话。Section 6 还会用“不导出构造器”来做抽象，那是另一处，见 `05`。

## Mutation：`set!` 改的是绑定，不是值

### 问题

函数式语言为什么还要赋值？一个 identifier 的 binding 被改变，到底意味着什么？

**【课程】** 后面的惯用法（promise、memoization）需要 mutation，所以必须现在讲清，并讲清滥用的代价。Racket 程序员通常很少用赋值。构造叫 `set!`，读作 “set bang”。

```racket
(set! x e)
```

`x` 必须已经在环境里。求值 `e`，然后**改变这个 `x` 绑定到的内容**。之后任何使用这同一个 `x` 的查找，都看到新值。已经完成的查找不受影响：它们拿到的是当时的值。

这就是 Java、C、Python 里的赋值，只是套了括号。

有副作用之后，需要按顺序做几件事：

```racket
(begin e1 e2 ... en)   ; 依次求值，整个 begin 的结果是 en 的结果
```

前面的表达式若没有 `set!`、打印或其他副作用，就是浪费。本章示例还用不到 `begin`，下一章的 `my-force` 会用。

### 例子：闭包仍然是词法的，但查到的是“当前内容”

```racket
(define b 3)
(define f (lambda (x) (* 1 (+ x b))))
(define c (+ b 4))     ; 现在查找 b，得到 3，所以 c 绑定到 7
(set! b 5)             ; 此后这个环境里的 b 是 5
(define z (f 4))       ; 调用时查找 b，得到 5；z = 9
(define w c)           ; w = 7。c 里放的是已经算完的 7，不是“b+4”这个表达式
```

**【讲解】** Part A 会说：闭包使 `f` 永远加 3。那在没有赋值时成立，因为 `b` 的内容永远是初始内容。有 `set!` 之后，词法作用域仍然成立——`f` 找的还是定义时所在的那个 `b`，不是调用处的某个别的 `b`——但查找拿到的是那个绑定的**当前内容**。

```text
环境（同一个 binding，内容在变）
  b  ●──────────► 3
  f  ●──────────► 闭包 { 代码: λx. (* 1 (+ x b)) , 环境: 指向这个 b }
  c  ●──────────► 7          查找发生在 set! 之前，7 是值，不再跟踪 b

set! b 5 之后
  b  ●──────────► 5          f 的闭包仍指向这个 binding，所以下次调用看到 5
```

这就是 “binding 被改变” 的意思：环境条目还是那一条，条目里的值换了。不是新建了一个 `b`，也不是改了数字 3 这个值（数仍然不可变）。

### 若你害怕别人改顶层绑定

**【课程】** 没有人该在作业里这么写。原则是：担心某物会变，就在它能变之前复制一份。

```racket
(define f
  (let ([b b])                    ; 局部 b 初始化为当时的外层 b，外界够不着
    (lambda (x) (* 1 (+ x b)))))
```

局部名字不必也叫 `b`。叫 `c` 一样，只要函数体查找的是这份副本。

还不够。`+` 和 `*` 也是变量，绑定到函数。若语言允许 `set!` 它们，这份“永远加 3”的承诺仍会被破坏。语义上你还得复制 `+` 和 `*`。Scheme 里这是真问题：有人 `set!` 了 `+`，大量假定它仍是加法的代码会坏。Racket 的妥协是：

> 若定义某个绑定的那个文件自己没有 `set!` 它，其他人也不得 `set!` 它。

加法所在的文件没有对 `+` 做 `set!`，所以别人也不能赋值给它。你不必、也不应该在作业里复制这些绑定。Racket 程序员的实际假设是：没有人会对顶层绑定做 `set!`。

### 对推理的破坏

| 被破坏的东西 | 没有 mutation 时 | 有 `set!` 之后 |
| --- | --- | --- |
| 推理 | 绑定的值就是定义时算出来的那个，永远 | 必须谈“当前内容”；同一段代码两次查找可能不同 |
| 别名（aliasing） | 对不可变数据，别名看不出来 | 两个变量若指向同一绑定，一个 `set!` 另一个也变。下一节会看到：`set!` **不**让两个变量共享的 cons cell 一起变 |
| 相等 | 算过一次就能重用结果 | 若计算读了可能变的绑定，重用结果是错的。memoization 因此要求函数不读可变状态 |
| 抽象 | 函数的意义由参数和自由变量的定义决定 | 自由变量的绑定若可写，函数的意义还依赖“谁会在调用前写它” |
| 调试 | 错误是纯的，重跑得到同样结果 | 结果依赖赋值历史 |

**【课程】** 讲师的立场：不要对顶层绑定使用 `set!`，任何语言都一样。大量代码可能依赖的顶层名字不该被赋值。不用 mutation，语义简单得多。一门语言是否应该允许顶层绑定被改，本身就可疑。Racket 允许，但用“定义文件没改过，别人也不能改”限制了爆炸半径。

后面 promise 和 memoization 用的 mutation 是受控的：改的是一块外界看不到的局部状态，用来记住已经算过的答案。那是惯用法，不是许可证。

## `cons` 的真相：列表是一种 pair，不是另一种数据

### 问题

动态类型语言里，类型检查器不会区分 list 和 pair。为什么还要两套构造器？

**【课程】** 答案是：不要。`cons` 就是做 pair。列表是以 `null` 结尾的嵌套 pair。这在动态类型语言里很常见。

```racket
(define pr (cons 1 (cons #t "hi")))          ; 不是列表
(define lst (cons 1 (cons #t (cons "hi" null)))) ; 是列表
```

REPL 把 `pr` 印成带点的形式，点在最后一个元素前，表示“这不是列表”。`lst` 印成普通列表。

```text
pr:  pair                lst: pair
    /    \                    /    \
   1     pair                1     pair
        /    \                   /    \
      #t     "hi"              #t     pair
                                   /    \
                                 "hi"   null
```

`car` 像 ML 的 `#1`，`cdr` 像 `#2`。`(cdr (cdr pr))` 是字符串 `"hi"`。`(cdr (cdr lst))` 是单元素列表 `(cons "hi" null)`，要再 `car` 才得到字符串。

**【课程】** `caddr` 是库函数，等于 `(car (cdr (cdr x)))`。读作 “cadder”。历史同上，能自己定义，但标准库已经有。

| 谓词 | 对 `pr`（improper） | 对 `lst`（proper） | 对 `null` |
| --- | --- | --- | --- |
| `list?` | `#f` | `#t` | `#t` |
| `pair?` | `#t` | `#t` | `#f` |

`list?` 只对 proper list 为真：空列表，或 `cdr` 方向最终走到 `null` 的 cons。`pair?` 对任何 `cons` 的结果为真，因此包括除空列表外的所有 proper list，也包括 improper list。

`length` 对三元素列表返回 3。对不是列表的 cons 报错。报错术语：像 `lst` 这样的叫 proper list；`cons` 出来但不以 `null` 结尾的叫 improper list。

`(and e1 e2 ...)` 是原语，全部为真才真。可用来同时问 `list?` 和 `pair?`。

### 风格

**【课程】** 元素个数事先不知道：用 proper list，末尾放 `null`。只是要一个临时的二元组或三元组：pair 套 pair 可以。Racket 没有内置 triple。下面两种都像“三个东西”，但是不同的树，印出来不同：

```racket
(cons 1 (cons #t "hi"))          ; 1 在 car，(pair #t "hi") 在 cdr
(cons (cons 1 #t) "hi")          ; (pair 1 #t) 在 car，"hi" 在 cdr
```

第二种要取出 `#t`：`(cdr (car x))`。

讲师认为这很难追踪，下一节的 struct 是更好的风格。`cons` 适合“我就是要一个 pair”，不适合“我有四种表达式，每种字段含义不同”。

### 和 ML 的对照

ML 用逗号做 pair、用 `::` 做 list，类型检查器保证你不会把一个当另一个传给 `length`。Racket 用同一个 `cons`，程序员自己记住哪些是 proper list。自由的代价是这个记忆。

## `mcons`：另一种 pair，字段可以改

### 问题

不可变 cons 让别名无关，这是 Part A 强调过的好处。若某个惯用法真的要改 pair 的字段呢？

**【课程】** Racket 与 Scheme / Lisp 最大的变化：普通 cons cell 的 car / cdr **不能**改。因此可以用 cons 做不可变 pair 和 list，别名无关这一优点回来了。

次要好处，动态类型特有：`list?` 可以更快。cons cell 诞生的那一刻，它是不是 proper list 就定了，而且永远不会变（没有人能改掉与“是否以 null 结尾”有关的字段）。实现可以记下这个事实，不必每次 `list?` 都走到尽头。

`set!` 改不了 cons cell：

```racket
(define x (cons 14 null))
(define y x)                 ; y 和 x 此刻指向同一个 cons cell
(set! x (cons 42 null))      ; 只把 x 这个变量改指向新 cell
; x → (42 ...)
; y → (14 ...)               ; 旧 cell 还在，14 还在
(car y)  ; 14
(car x)  ; 42
```

```text
set! 之前
  x ●──► [14 | null]
  y ●──► 同一个 cell

set! x 之后
  x ●──► [42 | null]     新 cell
  y ●──► [14 | null]     旧 cell 未改
```

想写 `(set! (car x) 45)` 是不对的。`set!` 只接受 identifier，只改变量指向什么。Scheme 有 `set-car!`，会找到 `x` 指向的 cell 并改 car 字段。Racket 故意没有它。

要可变字段，用另一套类型，不要混：

| | 不可变 | 可变 |
| --- | --- | --- |
| 构造 | `cons` | `mcons` |
| 第一字段 | `car` | `mcar` |
| 第二字段 | `cdr` | `mcdr` |
| 谓词 | `pair?` | `mpair?` |
| 改字段 | 不存在 | `set-mcar!`、`set-mcdr!` |

```racket
(define mpr (mcons 1 (mcons #t "hi")))
(mcar (mcdr mpr))          ; #t
(set-mcdr! mpr 47)         ; 外层 cdr 变成 47
(set-mcdr! mpr (mcons #t "hi"))
(set-mcar! (mcdr mpr) 14)  ; 内层 car 变成 14
```

不能混用。`car` / `cdr` 不接受 mcons。`length` 要求 proper list：improper list 报错，即使用 `mcons` 拼出一个“看起来像列表”的东西也报错。`set-mcar!` 不接受普通 cons。`mcons` 不能用来做 proper list。

**【课程】** 需要多块内容、且内容会变：用 mcons。不想要可变性：用 cons。后面的 promise 就是一个两字段的可变 pair：一个字段是“算过了吗”，另一个字段从 thunk 变成结果。

## 逐讲笔记

上面是连续论证。下面按视频把课程要求的十段补齐。已在正文展开的机制这里只指向，不重复贴代码。

### 01 Introduction to Racket

1. **问题：** 怎样进入一门新语言，而不把课程变成语法迁移周？
2. **动机：** 作业第一题是熟悉 Racket，其后马上是新概念。新概念在 Racket 里比在 ML 里更干净，但也可以在 ML 里做。
3. **概念：** mostly functional；无静态类型系统；极简括号语法；Scheme 血统；列表不可变；`#lang racket`；`(provide (all-defined-out))`；`define` 像 `val`。
4. **机制：** DrRacket = definitions + interactions。Run 成功不打印类型。未绑定标识符：`reference to an unbound identifier`。
5. **代码：** `(define s "hello")`，REPL 里 `(+ 2 2)` → 4，`s` → `"hello"`。
6. **执行：** Run 先执行文件中的定义，再接受 REPL 表达式。
7. **PL：** 语言是载体。选 Racket 是为了动态类型和括号树，不是为了再写一遍 `map`。
8. **误区：** 把 Racket 当 Scheme 用，写出 `'()` 或可变列表。把 “everything is an expression” 理解成需要 `return`。`[字幕可能有误]`
9. **联系：** Part A 的匿名函数、闭包、表达式语言全部保留。不用 case 来拆 one-of；Racket 有相关支持，课程故意换一种访问方式。
10. **一句：** Racket 让你在没有类型检查器的函数式语言里，用括号直接看见程序的树。

### 02 Definitions, Functions, Conditionals

1. **问题：** 函数、变量、条件的最小写法是什么？
2. **动机：** 这些是 Part A 已会的，必须快速变成肌肉记忆，否则括号讲无法开始。
3. **概念：** 调用 `(f e1 ...)`；`lambda` = `fn`；`define` 的函数简写是糖；`*` 真可变参数；`if` 三表达式、无 then/else；柯里化是闭包惯用法。
4. **机制：** 特殊形式（`if`、`define`、`lambda`）不是调用。递归不需要新关键字。
5. **代码：** `cube1` / `cube2` / `cube3`，`pow1`，`pow2`，`((pow2 4) 2)`。
6. **执行：** `(pow1 3 2)` → 9，`(pow1 3 0)` → 1。`(pow2 3)` 返回函数，再给 2 得到 9。
7. **PL：** 调用的一般形式是 `(e0 e1 ... en)`，`e0` 可以是表达式。这是一等函数在语法上的直接体现。
8. **误区：** 以为 `(* x x x)` 是柯里化糖。以为调用柯里化函数可以写成 `(pow2 4 2)`。
9. **联系：** Part A 的 `fn`、闭包、递归。差别是多参数函数是真的，顶层递归不需要 `rec`。
10. **一句：** 除了少数特殊形式，Racket 程序就是函数调用的树。

### 03 Racket Lists

1. **问题：** 列表抽象如何在新语法里原样出现？
2. **动机：** 作业和后面的环境、memo 表都会用列表。名字必须先对齐。
3. **概念：** `null`、`cons`、`car`、`cdr`、`null?`、`list`；连字符惯例；REPL 的 quote 打印。
4. **机制：** 递归结构与 ML 相同。`car` / `cdr` 是历史名字。
5. **代码：** `sum`、`my-append`、`my-map`。
6. **执行：** `(sum (list 3 4 5 6))` → 18。`my-map` 加 1 得到 `'(4 5 6)`，与手写 `cons` 链打印相同。少给一个参数：运行时参数个数错误。
7. **PL：** 同一递归抽象可以独立于类型系统和具体语法存在。
8. **误区：** 用 `'()` 写空列表。把 `null` 和 `null?` 当成同一个东西。以为 REPL 的 `'` 是列表值的一部分，而不是打印方式。
9. **联系：** Part A Section 1 的 `hd` / `tl` / `null`，不是模式匹配。
10. **一句：** 列表还是“空，或头加尾”；变的是名字，以及类型错误要到 `+` 看见字符串才出现。

### 04 Syntax and Parentheses

1. **问题：** 括号多是缺陷还是语言实现上的简化？
2. **动机：** 不处理这个厌恶，后面 macro 和解释器的“程序即树”站不住。
3. **概念：** atom、special form、sequence；解析；方括号同义。
4. **机制：** 第一项是特殊形式则按该形式，否则是调用。括号使字符串到树没有优先级歧义。
5. **代码：** `(+ 3 (car xs))` vs `(lambda (x) (if ...))`。cube 的树。
6. **执行：** 无运行时新规则。这是语法到树的规则。
7. **PL：** 语法越接近抽象语法，语言实现越容易讨论。Racket 的括号是为了让 parsing 平凡。
8. **误区：** 括号是 Lisp 的怪癖，因此这门语言不值得学。把方括号当成另一种语义。
9. **联系：** 导论说的 minimalist syntax。后面 macro 增加特殊形式，解释器用 struct 表示同一棵树。
10. **一句：** 括号的工作是消除“这段文本对应哪棵树”的疑问。

### 05 Parentheses Matter: Debugging

1. **问题：** 括号放错时，程序实际在做什么？
2. **动机：** 动态类型加“括号即调用”，使笔误变成延迟很久的运行时错误。
3. **概念：** `(e)` = 零参数调用；语法错误 vs 运行时错误；错误可能在递归返回路上才出现。
4. **机制：** 见上面的 fact 表。
5. **代码：** `fact` 及 `fact1`–`fact6`。
6. **执行：** 正确的 `(fact 5)` → 120。每种错法的发现时机不同。
7. **PL：** 没有类型检查器时，元数错误和“数被当作函数”都是值的标签错误，不是语法错误。语法只保证括号配平、特殊形式的片段数量对。
8. **误区：** 加括号总是更安全。测试只测了非零参数，就认为基线括号是对的（`fact1b`）。
9. **联系：** 上一讲的“否则就是函数调用”。下一讲用 `number?` 在运行时区分值。
10. **一句：** 每一个括号都是一次结构决定；调试就是重新读树。

### 06 Dynamic Typing

1. **问题：** 没有 datatype，如何表示“数或列表，任意深”？
2. **动机：** 这是动态类型带来的方便，也是测试负担的来源。后面要和静态类型认真比较，现在先体会。
3. **概念：** 无类型检查器；`number?` 等运行时谓词；异构列表；契约靠测试和文档。
4. **机制：** `sum1` 用谓词分情况。误用则在 `car` 字符串时炸。`sum2` 选择跳过。
5. **代码：** `xs`、`ys`、`sum1`、`sum2`、`zs`。
6. **执行：** `sum1` 对纯嵌套数得到 15 / 45 / 18。对字符串得到 `car` 错误。`sum2` 跳过后得到 14 或 13。
7. **PL：** 动态类型不是没有类型。值有标签，变量没有静态类型，表达式没有检查器赋予的类型。标签错误从编译期挪到求值期。
8. **误区：** “没有类型所以什么都能加”。`+` 仍然拒绝字符串，只是拒绝得晚。以为 `sum2` 对任意初始参数都安全。
9. **联系：** Part A 的 datatype 是类型检查器强迫你写的标签。Racket 的内置值已经自带标签。Section 6 会把手写标签和 struct 讲透。Section 7 会把“一个大 datatype”说成 ML 程序员眼中的 Racket。
10. **一句：** 动态类型把“证明标签匹配”从运行前挪到每次原语调用。

### 07 cond

1. **问题：** 多分支条件怎样写才不像一棵斜着的 `if` 树？
2. **动机：** 作业会大量分支。`sum` 已经有三路，是合适的例子。
3. **概念：** `cond`；最后一支 `#t`；只有 `#f` 为假。
4. **机制：** 按序测试，取第一支为真的表达式。无支为真则 void，不报错。
5. **代码：** `sum3`、`sum4`、`count-falses`。
6. **执行：** `(if 34 14 15)` → 14；`(if #f 14 15)` → 15。`count-falses` 只数 `#f`。
7. **PL：** “真”的定义是语言设计选择。Racket 选择唯一的假是 `#f`，与另一些动态语言不同。这在静态类型里没有意义。
8. **误区：** 空列表是假。`cond` 没有 `#t` 分支时会报错（它返回 void）。`cond` 的方括号有语义（没有）。
9. **联系：** `if` 的求值规则不变：未选中的分支不求值。这是下一章的前提。
10. **一句：** `cond` 是嵌套 `if` 的可读形状；假只有 `#f`。

### 08 Local Bindings

1. **问题：** 局部变量的初始化表达式，应该看见哪些绑定？
2. **动机：** 一种 `let` 不够表达“同时交换”“顺序依赖”“互递归”这三种合理需求。
3. **概念：** `let`、`let*`、`letrec`、局部 `define`；undefined；函数体推迟求值使前向引用安全。
4. **机制：** 见三种环境图。求值顺序始终是书写顺序。
5. **代码：** `max-of-list`、`silly-double`、`silly-double*`、`silly-triple`。
6. **执行：** 参数 10 时，`let` 版得到 20；`let*` 版也得到 20，但中间绑定不同。`silly-triple` 返回三倍参数。`(f -9)` 里 `-9 + (x+2) + (x+7) + x = 3x`。
7. **PL：** 作用域规则是设计选择。把三种选择做成三个关键字，是在让语义可见。
8. **误区：** Racket 的 `let` 等于 ML 的 `let`（那是 `let*`）。在 `letrec` 里于函数体外使用后面的绑定。作业里为了“更 Racket”而看不懂自己用的是哪种语义。
9. **联系：** Part A 的环境和遮蔽。函数体不立即求值，是下一章 thunk 的同一事实。
10. **一句：** `let` 看过去，`let*` 看左边，`letrec` 看全部，但值仍按顺序填。

### 09 Top-level Bindings

1. **问题：** 文件里的定义是哪种 let？
2. **动机：** 不讲这个，递归和前向引用会变成迷信。
3. **概念：** 文件内部 letrec 语义；过早引用是错误；同文件不能遮蔽；REPL 不要定义递归函数；文件是模块，跨文件可以遮蔽。
4. **机制：** 函数体里的后向引用安全；表达式位置的后向引用不安全。
5. **代码：** `f` 使用后面的 `b`；`c` 使用前面的 `b`；重复定义 `f` 报错。
6. **执行：** 点 Run 时按顺序填绑定。取消注释 `d` 得到 before-definition 错误。
7. **PL：** “顶层”往往其实是模块作用域。模块边界决定遮蔽是否可能。
8. **误区：** 顶层像 ML，不能引用后面的函数。在 REPL 里复制文件中的递归定义来试验。
9. **联系：** 上一讲的 `letrec`。Section 6 的模块抽象依赖“每个文件是模块、导出是显式的”。
10. **一句：** 一个文件是一个 letrec；两个文件是两个 letrec，中间有导出边界。

### 10 Mutation with set

1. **问题：** 改变一个 identifier 的绑定，世界的哪一部分会看见？
2. **动机：** 后面要用 mutation 记住计算，但必须先知道它如何摧毁推理。
3. **概念：** `set!`；`begin`；词法作用域仍在，内容会变；局部复制；Racket 对库绑定的赋值限制。
4. **机制：** 见绑定图。已求值的 `c` 不跟踪 `b`。闭包查找的是同一个 binding 的当前内容。
5. **代码：** `b`、`f`、`c`、`set!`、`z`、`w`，以及带局部副本的 `f`。
6. **执行：** `c = 7`，`set!` 之后 `(f 4) = 9`，`w = 7`。
7. **PL：** 赋值改变的是环境条目的内容，不是值本身。别名、相等、抽象边界都要重新谈。顶层赋值尤其危险，因为共享那个绑定的代码你可能没全看见。
8. **误区：** `set!` 会把所有曾经从 `b` 算出来的值一起改掉。作业里对顶层 `set!`，或复制 `+` 来“防御”。以为 Racket 没有赋值所以是纯的。
9. **联系：** Part A 闭包“永远看见定义时的值”，在无赋值时成立。有赋值后，看见的是定义时那个绑定的当前值。不可变数据上的别名无关，要到下一讲才和 cons 对齐。
10. **一句：** `set!` 重写绑定的当前内容；已经算完的值不会跟着变，尚未查找的闭包会看见新内容。

### 11 The Truth about cons

1. **问题：** `cons` 到底构造什么？
2. **动机：** 动态类型不再区分 pair 类型和 list 类型，两套构造器就没有类型上的理由。
3. **概念：** cons cell；proper / improper list；点打印；`list?` vs `pair?`；`caddr`。
4. **机制：** 列表 = 嵌套 pair + 最终 `null`。`car` / `cdr` 就是取 pair 的两半。
5. **代码：** `pr` 与 `lst`。`(cdr (cdr pr))` vs `(cdr (cdr lst))`。
6. **执行：** `list?` 对 `pr` 为假、对 `lst` 为真。两者都是 `pair?`。`length` 拒绝 improper list。
7. **PL：** 一种构造器服务两种习惯用法，是动态类型里的常见简化。习惯用法（proper list vs 临时 tuple）变成程序员的纪律，而不是类型。
8. **误区：** 凡是 `cons` 出来的都是 `list?`。用深层 `car` / `cdr` 表示有结构的数据，并以为这和有名字的字段一样可维护。
9. **联系：** ML 的 `#1` / `#2` 与 `hd` / `tl` 在这里塌成同一对函数。Section 6 会论证 struct 比这种塌缩更好。
10. **一句：** `cons` 做 pair；列表只是以 `null` 结尾的那种 pair。

### 12 mcons

1. **问题：** 既要不可变列表的推理好处，又要一块能改的二元数据，如何不互相污染？
2. **动机：** promise 需要改字段。若因此把所有 cons 都变成可变的，Part A 关于别名的论证就毁了。
3. **概念：** 不可变 cons vs `mcons`；`set!` 不改 cell；`set-mcar!` / `set-mcdr!`；禁止混用。
4. **机制：** 两套函数、两种运行时标签。`list?` 能记下一个不可变 cell 是否为列表。
5. **代码：** `x` / `y` 的 `set!` 实验；`mpr` 的 `set-mcdr!`、`set-mcar!`。
6. **执行：** `set! x` 之后 `y` 仍是 `(14)`。`set-mcar!` 之后，所有指向那个 mcons 的名字都看见新 car。
7. **PL：** 可变性应该是类型上分开的，而不是所有 pair 的默认。这样别名只在你明确选择的数据上变得可观察。
8. **误区：** `set!` 能改 cons 的字段。用 `mcons` 做列表再交给 `length`。`set-car!` 在 Racket 里存在（不存在；那是 Scheme）。
9. **联系：** Part A：不可变使别名无关。下一章：mcons 加 thunk 实现“最多算一次”。
10. **一句：** 要改的是变量，用 `set!`；要改的是 pair 的字段，用另一套 `mcons`。

## 本章范围小结

### 核心问题

如果静态类型系统不再替你拒绝程序，函数式程序的骨架还在，但错误、数据构造和绑定的含义都要重谈。

### 知识地图

```text
Racket 程序 = 特殊形式 或 函数调用，括号即树
      │
      ├── 列表 = 以 null 结尾的不可变 pair（cons / car / cdr）
      │
      ├── 动态类型：值有标签，变量无静态类型，谓词在运行时问
      │
      ├── 绑定
      │     ├── let / let* / letrec / 顶层 letrec
      │     └── set! 改变绑定的当前内容
      │
      └── 可变 pair 是另一类型：mcons
```

### 最重要的代码模式

- `(define (f x) ...)` = `(define f (lambda (x) ...))`
- `(if e1 e2 e3)` 与 `(cond [t e] ... [#t e])`
- 列表递归：空则基底，否则 `car` 加对 `cdr` 递归
- 需要局部且互不依赖：`let`；需要左边：`let*`；需要互递归：`letrec`
- 需要改字段：`mcons`，不要 `set!` 一个 cons

### 容易混淆

| 混淆 | 分辨 |
| --- | --- |
| `(e)` 与 `e` | 前者是零参数调用 |
| `let` 与 ML 的 `let` | ML 的是 `let*` |
| `set!` 与改 cons | `set!` 只改变量指向什么 |
| `cons` 与列表 | 列表是一种 cons 用法 |
| `list?` 与 `pair?` | 空列表是 list 不是 pair；improper 是 pair 不是 list |
| 动态类型与无类型 | 值有标签；缺的是运行前的证明 |

### 和上一节（Part A）的关系

函数、递归、环境、闭包、列表都还在。拿掉的是：运行前的类型证明、模式匹配（课程暂时不用）、ML 那种单一 `let`、中缀和优先级。加上的是：运行时谓词、三种 let、受控的赋值、pair 与 list 的塌缩、另一套可变 pair。

### 为下一章准备了什么

函数体在调用前不求值。`if` 不算未选中的分支。`set!` 和 `mcons` 能记住一个格里的内容。这三件合在一起，才能把“现在算”变成“以后算，并且最多算一次”。

## Engineering Connection

**【课程已有的联系】** 顶层赋值会破坏所有依赖那个绑定的代码，所以语言用模块边界限制谁可以 `set!`。不可变 cons 让别名无关，这是大程序里能局部推理的前提。

**【扩展，类比，不是课程结论】**

- JavaScript / Python 的变量赋值像 `set!`：改的是绑定。若两个名字指向同一可变对象，改对象字段两边都看见，那是 `mcons` / 对象字段这一层，不是赋值本身。
- 现代语言把“可变格子”做成显式类型（Rust `Cell` / `RefCell`，OCaml `ref`），和 Racket 把 `mcons` 从 `cons` 分开是同一设计冲动。不要把这个类比当成 Racket 有所有权类型。
- “只有 `#f` 为假”在 Python 里不成立（空容器、0、`None` 都为假）。迁移时这是语义坑，不是风格坑。

## 检查题

1. 为什么 `(define (cube x) (* x x x))` 里的 `*` 不是柯里化语法糖？
2. `(if (= y 0) 1 (pow1 x (- y 1)))` 若改写成函数 `(my-if (= y 0) 1 (pow1 x (- y 1)))`，在你还没学 thunk 时，为什么递归会不停？先只根据“函数调用如何求值参数”回答。
3. `fact4` 写成 `(* n fact4 (- n 1))` 为什么点 Run 能成功，调用才失败？ML 会在哪一步拒绝？
4. 说“Racket 没有类型”错在哪里？变量、值、表达式各是什么情况？
5. `sum1` 和 `sum2` 在契约上有什么不同？哪一个更接近“调用者必须传对”？
6. 为什么 `cond` 的最后一支应该是 `#t`？缺了它，是语法错误还是更晚的混乱？
7. 用 Racket 的 `let` 交换 `x` 和 `y`，为什么 ML 的 `let` 做不到？
8. `letrec` 里，为什么函数体可以引用后面的 `w`，而 `(define y (+ w 2))` 这种写法会坏？
9. 顶层过早引用，和 `letrec` 里过早使用未初始化绑定，课程说的失败方式有何不同？
10. `set! b 5` 之后，为什么 `(f 4)` 变成 9，而 `c` 仍是 7？闭包找的是哪个 `b`？
11. 为什么复制一份局部 `b` 能让 `f` 不受后来的顶层 `set!` 影响？为什么课程仍不让你在作业里这么写？
12. `(cons 1 (cons 2 3))` 是 `list?` 吗？是 `pair?` 吗？`(cons 1 (cons 2 null))` 呢？
13. `set!` 为什么不能实现 `set-car!` 的效果？`mcons` 解决的是哪个问题，又故意不解决哪个问题？

## Answers

1. 因为 Racket 的函数真能接受任意个数的参数。`(* x x x)` 是一次调用、三个参数，不是“元组”或“返回函数再调用”的糖。
2. 调用函数前，三个参数都求值。第三个参数是递归调用，它又要先求值自己的三个参数，递归永不结束。`if` 之所以能停，是因为它不是函数，未选中的分支不求值。
3. 括号是配平的，`*` 也允许三个参数，所以语法合法。运行到乘法才发现第二个参数是过程不是数。ML 在类型检查阶段就拒绝把函数传给 `*`，程序不会开始跑。
4. 值有运行时标签，原语会检查标签。变量没有像 `x : int` 这样的静态类型，只是当前绑定到某个值。表达式没有类型检查器赋予的类型；走不到的表达式里的标签错误不会被发现。
5. `sum1` 假定非数就是列表，否则在 `car` 上炸，更接近“传错就失败”。`sum2` 对非数非列表跳过，改变了函数的意义，而且仍假定初始参数是列表。
6. 否则所有测试为假时返回 void，不报错。调用者稍后误用这个 void，错误远离真正的分支遗漏。
7. Racket 的 `let` 里所有右边都在进入 `let` 之前的环境求值，所以两边都看见旧值，交换成立。ML 的 `let` 是顺序的，第二个绑定看见第一个新值，两个都会变成旧的 `y`。
8. 创建 `lambda` 不求值函数体，调用发生在 `w` 已求值之后。`(+ w 2)` 在求值 `y` 时就要读 `w`，那时 `w` 还是 undefined，`+` 随后报错。
9. 顶层是明确错误：reference before definition。`letrec` 内部先给 undefined，真正的错发生在你把 undefined 传给 `+` 之类的原语时。
10. `f` 的闭包按词法找到定义时所在的那个 `b` 绑定。`set!` 改的是这个绑定的当前内容，所以调用时读到 5，`4+5=9`。`c` 的绑定里放的是早先算完的值 7，不是一个还连着 `b` 的表达式。
11. 局部 `b` 是另一个绑定，初始化为当时的外层值，外界的 `set!` 改不到它。课程不让这么写，是因为没人该依赖“防御顶层赋值”；正确纪律是不对顶层绑定 `set!`。Racket 还额外禁止赋值给定义文件自己没赋值过的库绑定。
12. `(cons 1 (cons 2 3))` 不以 `null` 结尾，是 improper list：`pair?` 为真，`list?` 为假。`(cons 1 (cons 2 null))` 两者都为真。`null` 本身 `list?` 为真、`pair?` 为假。
13. `set!` 只接受变量，把变量改指向别的值；原来的 cons cell 若还有别的名字指向它，内容不变。`mcons` 提供可改的字段，使共享同一个 cell 的名字能看见更新。它故意不让你改普通 cons，从而保住不可变列表上“别名无关”的推理。
