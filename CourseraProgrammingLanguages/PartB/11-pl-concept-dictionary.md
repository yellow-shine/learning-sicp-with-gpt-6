# PL Concept Dictionary

每个词：一句课程能对上的定义，一句程序员直觉，一个最小例子。没在视频里当术语讲的，标了扩展。

### Binding（绑定）

定义：环境里一个变量和它当前内容的对应。`set!` 改的是这个内容，不新建变量，也不改数本身。

直觉：名字是格子的标签，值是格子里现在放的东西。

```racket
(define b 3)
(set! b 5)    ; 同一个 binding，内容从 3 换成 5
```

### Environment（环境）

定义：变量到值的映射。解释器把它当成参数传递。空环境表示程序开始时没有绑定。

直觉：一张表。查找是读表，`let` 是拿一张多了一行的表去求值体。

```text
{ x → const 10, y → const 20 }
eval(Var "x", 这张表) → const 10
```

### Closure（闭包）

定义：函数代码，加上函数定义时的环境。

直觉：函数值若只用到参数，代码就够了。用到外面的名字，就必须把当时的表一起带走。

```text
Closure
├── code: λy. x + y
└── env: x → 10
```

### Free Variable（自由变量）

定义：出现在函数体里，又不是参数、也不是函数内部局部变量的变量。

直觉：这个函数自己不定义、却会去查找的名字。闭包至少要记住这些名字的绑定。

```text
λx. let y = 1 in x + y + z     自由变量只有 z
```

### Lexical Scope（词法作用域）

定义：自由变量按定义处的环境解释，不按调用处。

直觉：看代码写在哪里，就知道名字找谁。闭包是这件事的实现。

```text
x = 10; f = λy. x+y; x = 20; f(3)  → 13
```

### Dynamic Scope（动态作用域）

定义：自由变量按调用时的当前环境解释。

直觉：谁调用，就用谁身边的表。实现更简单，课程不采用。解释器若用调用者环境求值体，就会意外做出它。

```text
同上  → 23
```

### Thunk

定义：零参数函数，用途是推迟求值。创建时不算体，每次调用都算。

直觉：把“现在算”换成“以后算，或不算”。

```racket
(lambda () (+ 3 4))    ; 过程，不是 7
((lambda () (+ 3 4)))  ; 7
```

### Delayed Evaluation（延迟求值）

定义：表达式不在它被写到的位置求值，而在以后某个明确的时刻求值，或者永不求值。

直觉：求值时机是语义的一部分，不是优化注释。

```racket
(if #f (infinite-loop) 1)    ; 第二支永不求值
```

### Stream

定义：一个 thunk。调用它得到 pair：car 是下一个值，cdr 是其余元素的 stream。

直觉：无限序列的有限表示。未请求的尾巴不存在。

```racket
(define ones (lambda () (cons 1 ones)))
(car (ones))    ; 1
```

### Memoization

定义：纯函数把参数到结果的对应记在表里；再次用同一参数就查表。拼写没有第二个 r。

直觉：promise 是零参数的一格；有参数就要一张表。递归要快，内部调用必须走这张表。

```text
未命中 → 算 → 登记 → 返回
命中   → 返回 cdr
```

### Macro

定义：把一种新语法在求值前变换成已有语法。在 Racket 里，定义之后它成为特殊形式。

直觉：函数看见值，进门太晚。Macro 看见树，来得及不让某段语法被求值。

```racket
(my-delay (+ 3 4))    ; 展开成带 lambda 的 mcons，不立刻做加法
```

### Macro Expansion（宏展开）

定义：按 macro 定义，把使用处的语法换成脱糖后的语法。发生在类型检查和求值之前，包括死分支。

直觉：预遍。展开结果才是后来真正运行的程序。

```text
(comment-out (car null) #f)  展开成  #f
```

### Hygiene（卫生）

定义：macro 引入的局部变量不捕捉使用处的同名变量；macro 体里的自由变量在定义处解析，不在使用处解析。

直觉：macro 应该像函数一样遵守词法作用域。天真的粘贴做不到。

```text
(let ([y 7]) (double y))  → 14，不是被 macro 内部的 y 捕捉成 2
```

### AST（抽象语法树）

定义：表示程序结构的树：哪种构造，子树是什么。不是程序员写下的字符串。

直觉：解释器吃的是树。作业里树由 struct 构造器直接写成。

```text
        Add
       /   \
  Const 3  Const 4
```

### Interpreter（解释器）

定义：用语言 A 写成的程序，接收语言 B 的语法树，算出 B 的答案。

直觉：`eval(树, 环境) → 值`。它不是 parser，也不是“这门语言的本质”。

```text
eval-exp(add (const 3) (const 4)) → const 7
```

### Host Language（宿主语言）

定义：用来实现另一门语言的语言。课程叫 metalanguage，语言 A。这里是 Racket。

直觉：你的解释器、struct、`+` 都是宿主语言的。它们不是对象语言的构造。

```racket
(+ (const-n v1) (const-n v2))    ; 这行是 Racket
```

### Object Language（对象语言）

定义：被实现的语言 B。课程多说 language B，不总用这个英文词。算术语言和 MUPL 都是。

直觉：`add`、`fun`、`call` 的意义由你的 `eval` 规定，不由 Racket 规定。

```racket
(add (const 3) (const 4))    ; 建树，不做 3+4
```

### Static Typing（静态类型）

定义：在运行前拒绝一些已经能解析的程序，目的是某类运行时行为不会发生。做法通常是给表达式定类型。

直觉：合法程序的集合在开跑之前就缩小了。

```text
ML 拒绝把字符串传给 +，程序不会开始跑
```

### Dynamic Typing（动态类型）

定义：不做那种静态拒绝。值仍有标签，原语在运行时检查。Racket 仍会在点 Run 时拒绝未定义变量，静态检查很少，所以仍叫动态类型。

直觉：程序更容易被接受。标签不配，要等到那次原语调用。

```racket
(+ 1 "hi")    ; 能写下。求值到这一行才错
```

### Soundness（可靠性）

定义：相对某个要阻止的 X。从不接受一个存在输入就会做 X 的程序。没有假阴性。

直觉：通过了，就不会得它声称要防的那种病。不意味程序没有别的 bug。

```text
ML 对“数除以字符串”是 sound 的
```

### Completeness（完备性）

定义：相对同一个 X。从不拒绝一个不会做 X 的程序。没有假阳性。

直觉：所有安全程序都被接受。和非平凡 X、检查器终止、sound 不能兼得。实际类型系统选择不 complete。

```text
if true then 0 else 4/"hi"  被拒绝，但是不会做 X
```

### Weak Typing（弱类型）

定义：有些程序必须通过静态检查，运行后却可以做任何事：崩溃、破坏数据、删文件。动态检查可选，实际不做。

直觉：不是“动态”，也不是“类型少”。是失败了不必表现为错误。C/C++ 是例子。Racket 不是。

```text
数组越界之后，语言不保证你会得到一个错误
```
