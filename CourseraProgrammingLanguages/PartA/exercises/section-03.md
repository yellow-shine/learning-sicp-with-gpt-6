# Section 3 — 练习

## Concept Questions

1. 为什么 first-class function 和 closure 不是同一个概念？举一个是前者但不必是后者的函数。
2. 高阶函数在什么意义上是抽象，而不只是“把函数传来传去”？
3. 用同一段程序说明词法作用域和动态作用域可以得到不同结果。现代语言为什么几乎都选前者？至少给两个独立理由。
4. `fun f y = x + y` 在 `val x = 1` 之后定义，然后 `val x = 2`。调用 `f` 时，闭包的环境里 `x` 是多少？后来的绑定是赋值吗？
5. 删掉一个函数内部从未被自己的代码提到的局部变量，在哪种作用域下可能改变行为？为什么？
6. `String.size s` 放进传给 `filter` 的匿名函数，和先 `let val i = String.size s` 再在闭包里用 `i`，语义结果一样吗？哪个量不一样？
7. `int -> int -> int` 和 `int * int -> int` 的值各是什么形状？部分应用适用于哪一个？
8. Currying 和 partial application 谁是类型的形状，谁是调用的用法？
9. 闭包捕获 `ref` 时捕获的是什么？再 `val r = ref 0` 遮蔽原来的 `r`，闭包看见哪个盒子？
10. 用闭包做成的 `set` 和以后的对象，在“客户看不见表示”上相似。查找时间有什么不同？

## Code Reasoning

### A

```sml
val x = 1
fun f y = x + y
val x = 2
val y = 3
val z = f (x + y)
```

词法作用域下 `z` 是多少？动态作用域下呢？写出调用时闭包的环境。

### B

```sml
fun f y =
    let val x = y + 1
    in fn z => x + y + z end

val g = f 4
val y = 0
val n = g 6
```

画出 `g`。`n` 是多少？若在 `f` 返回之后、调用 `g` 之前能把 `f` 的局部 `x` 赋值改成 `100`，ML 允许吗？若 `x` 是 `ref`，答案怎么变？

### C

```sml
fun sorted3 x y z = z >= y andalso y >= x
val p = sorted3 1
val q = p 2
val a = q 2
val b = sorted3 3 2 1
```

`p` 和 `q` 的类型是什么？`a` 和 `b` 的值是什么？

### D

```sml
val x = ref 42
val y = ref 42
val z = x
val _ = x := 43
val n = !y + !z
val f = fn () => !z
val z = ref 0
val m = f ()
```

`n` 和 `m` 各是多少？第二个 `val z` 影响 `f` 吗？

---

## Answer Key

### Concepts

1. First-class 说函数能否当值传递。Closure 说函数值是否打包了定义处的环境。`fn x => x + 1` 是一等函数值。它没有自由变量，不必捕获外部绑定。
2. 不变的控制结构留在一个函数里，变化的步骤变成参数。加一种新步骤不必改骨架，骨架也不必知道各种步骤的名字。这是依赖边界，不是语法技巧。
3. 本章代码题 A 就是例子：词法得 6，动态得 7。理由：函数含义在定义处可确定，局部改名不影响行为；类型可以在定义处检查，后来的同名绑定即使类型不同也不破坏已创建的函数；私有数据不必出现在函数类型里，库才能写 `filter`。
4. 闭包里 `x` 是 `1`。后来的 `val x = 2` 是遮蔽，不是赋值。
5. 动态作用域。调用发生在那个局部变量的作用域内时，被调用函数的自由变量会查到它，即使函数自己的代码没写这个名字。词法作用域下，未在函数体出现的绑定不在它的自由变量里，删除不影响该函数。
6. 过滤结果一样，只要 `s` 不变。不一样的是 `String.size s` 的计算次数：每个元素一次，或每个 list 一次。闭包捕获的 `i` 是已经求出的整数。
7. 前者的值是一个函数，吃一个 `int` 返回另一个函数。后者的值是一个函数，吃一个 pair。部分应用适用于前者。
8. Currying 是把 tuple 参数变成一串返回函数，是定义和类型的形状。Partial application 是少传参数、留下返回的函数，是用法。没有 currying 的类型形状，就没有这种用法，除非手写转换器。
9. 捕获盒子，不是当时的内容。遮蔽产生另一个绑定，指向另一个盒子。闭包仍持有原来的盒子。对原盒子 `:=` 会改变闭包以后读到的内容。
10. 闭包在构造 `set` 时已经抓住具体函数和 list。以后没有“按接收者的类重选方法”这一步。对象的动态派发在调用时把 `self` 绑到接收者，继承的方法可以因此跑到子类覆盖的版本。隐藏表示是相似的。查找时间不是。

### Code

A. 词法：`6`。闭包环境 `x → 1`，参数 `y → 5`，因为 `x + y` 在调用前用当时的 `x → 2`、`y → 3` 算成 `5`。动态：函数体里的自由 `x` 查调用时的 `x → 2`，结果 `7`。

B.

```text
g = closure
  code: fn z => x + y + z
  env:  x → 5, y → 4
n = 5 + 4 + 6 = 15
```

ML 不能把那个局部 `x` 赋值改掉。它不是盒子。若 `x` 是 `ref`，闭包捕获盒子，返回之后仍可 `:=`，`g` 会看见新内容。

C. `p : int -> int -> bool`。`q : int -> bool`。`a` 是 `2 >= 2 andalso 2 >= 1`，即 `true`。`b` 是 `1 >= 2 andalso 2 >= 3`，即 `false`。

D. `n` 是 `85`。`f` 捕获的是 `z` 在遮蔽之前指向的盒子 A，内容已被写成 `43`。第二个 `val z` 是新盒子，不影响 `f`。`m` 是 `43`。
