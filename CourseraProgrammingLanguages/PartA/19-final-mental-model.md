# 19 — Programming Languages：最终心智模型

十个 Section 之后，剩下的不该是三门语法。应该是一张可以带去任何语言的图。

```text
Program
│
├── Syntax          怎么写。必要，通常无趣。
├── Semantics
│     ├── Evaluation    在什么环境里，何时，变成什么值
│     └── Typing        运行前拒绝什么。可以没有
├── Idioms          这些构造通常怎么组合
│
├── Names
│     ├── Binding       名字如何进入环境
│     ├── Scope         自由变量在定义处还是调用处查找
│     └── Lifetime      绑定比哪次调用活得更久
│
├── Values
│     ├── Each-of       同时有的几块
│     ├── One-of        若干互斥形状之一
│     └── Functions     代码。若有词法作用域且会逃走，则是闭包
│
├── State             默认可变，默认不可变，或显式的盒子
├── Abstraction       客户被允许观察什么
├── Dispatch          调用时选哪段代码：闭包已选好，或按接收者再找
└── Extension         加操作容易，还是加变体容易
```

语言不大。ML、Racket、Ruby 各自只有一小撮构造。软件的多样性来自组合，不来自构造的数量。Grossman 在结束时把这称为这门学科里真正令人敬畏的事实：很少的规则，加上人的安排，变成世界上在跑的软件。

## 用大约二十个概念覆盖整门课

| 概念 | 它在课里的位置 | 没有它你会怎样 |
|---|---|---|
| Expression / Value | S1 | 分不清计算和结果 |
| Environment | S1，S6 实现 | 名字的含义无法局部写下 |
| Binding vs Assignment | S1，S3 的 `ref` | 把所有语言都读成盒子 |
| Evaluation rules | 每个构造 | 只能试，不能推理 |
| Function is a value | S1 正式规则，S3 才拿来用 | 递归和“传递计算”同时说不清 |
| Eager arguments | S1 | 解释不了短路为什么必须是特殊形式 |
| Each-of / One-of / Self-reference | S2 | 用整数和魔数编码数据 |
| Pattern matching | S2 | 测试和提取分开，漏情况要到运行才炸 |
| Immutability | S1，贯穿到 S10 | 在别名上看不见的地方引入观察差异 |
| First-class function | S3 | 复制骨架，或用不可扩展的 flag |
| Lexical scope | S3 | 函数含义依赖谁调用了它 |
| Closure | S3 使用，S6 实现 | 返回的函数丢失自由变量；回调无法携带私有数据 |
| Parametric polymorphism | S2–S4 | 为每种元素类型复制 `map` |
| Type inference | S4 | 把“没写类型”误认为“没有类型系统” |
| Abstraction boundary | S4 的 signature；S3 的闭包类型 | 客户依赖表示，实现不能换 |
| Delayed evaluation | S5 的 thunk；不是 Haskell 的默认惰性 | 无限结构和“先不要算”只能靠复制代码 |
| Program as tree | S5–S6 | 把语言实现理解成处理字符串 |
| Soundness / Completeness | S7 | 用阵营口号代替设计权衡 |
| Object / Dynamic dispatch | S8 | 把方法调用当成取出闭包再按词法环境调用 |
| Decomposition axis | S9 | 不知道“这种改动为什么烦”烦在哪一根轴 |
| Subtyping vs Generics | S10 | 在 Java/C# 里用错一种可替换 |

二十个太多就压成五句：

1. 求值在环境里进行。绑定扩展环境，赋值修改盒子。两者都叫“变了”时，后面全部混乱。
2. 函数值若遵守词法作用域并比调用活得久，它就是闭包。
3. 数据是 each-of、one-of，或自己包含自己。模式匹配是 one-of 的使用方式。
4. 类型系统是运行前的近似。Sound 则放弃 complete。推断是静态检查的界面，不是动态类型。
5. 组织程序时，你要么按操作切开 one-of，要么按变体把操作放进对象。扩展方向决定哪一刀更便宜。子类型是另一套可替换，不是泛型的别名。

## 三门语言在这张图上的让步

| | SML | Racket | Ruby |
|---|---|---|---|
| 这一格 | 静态、函数式 | 动态、函数式 | 动态、面向对象 |
| 求值 | eager。延迟要自己用 thunk | eager。延迟是这一部分的主题 | eager。block 延迟到 `yield` |
| 绑定 | `val` 不可变。`ref` 显式 | `define` 不可变。`set!` 和 `mcons` 显式 | 对象字段默认可变 |
| 函数 | 一等闭包。一个参数 | 一等闭包。括号即调用 | 方法不是一等的。Proc 才是 |
| one-of | datatype + match | struct 或带 tag 的 list。没有穷尽检查 | 类层次。没有穷尽检查 |
| 拒绝程序 | 运行前，sound 且不 complete | 求值到那一步才拒绝 | 消息发送时才拒绝 |
| 隐藏 | signature 可隐藏类型 | 闭包、词法、模块 | 私有方法、不公开类 |
| 派发 | 闭包在创建时已选定代码 | 同左 | 调用时按接收者的类查找 |

第四格，静态的面向对象，课上不作为主语言。Java 和 C# 坐在那里。学完这三格再看它们，问题会变成：它们的子类型规则是否尊重可变性？泛型是真的参数多态，还是擦除之后的折中？lambda 捕获的是值还是可变绑定？接口是子类型、是抽象边界，还是两者的混合？

## How to Learn a New Programming Language

不要从语法表开始。按这个顺序问。每一问都对应课程里已经见过的一次设计选择。

```text
1. 值有哪些？
   数、函数、对象、null、带 tag 的并集，分别是不是一等的？

2. 表达式如何变成值？
   哪个构造求所有子表达式，哪个只求一部分？
   参数是 eager 还是惰性？延迟是默认的，还是要写成 thunk / block / lazy？

3. 名字如何绑定？
   绑定是扩展环境，还是给已有盒子赋值？
   同名再绑定是遮蔽，还是错误，还是修改？

4. 作用域规则是什么？
   自由变量在定义处还是调用处查找？
   函数值因此是不是必须是闭包？
   闭包捕获的是值、绑定，还是可变盒子？

5. 什么是可变的？
   默认不可变，默认可变，还是显式盒子？
   别名能否观察到写操作？
   字段、集合元素、闭包捕获的变量，是否同一答案？

6. 函数如何表示？
   一等吗？一个参数还是多个？
   currying 是语言默认还是库？
   方法是函数吗？block / lambda / 函数指针差在哪？

7. 类型系统做什么？
   运行前拒绝什么？sound 吗？故意不 complete 吗？
   不写类型时，是推断，还是根本不检查？
   可替换靠子类型、类型参数、还是 duck typing？
   可变位置是否协变？函数参数是否逆变？

8. 抽象边界是什么？
   客户能看见表示吗？
   signature、interface、私有字段、闭包环境，各藏了什么？
   两种实现在什么观察下等价？时间算不算？

9. 派发如何发生？
   调用时还查不查接收者？
   继承的方法看见的是定义时的函数，还是接收者上的覆盖？
   多参数都参与派发吗？不参与的话，binary method 怎么写？

10. 扩展哪一个方向更便宜？
    加一种操作，还是加一种数据变体？
    语言把便宜的那个方向做成了默认分解吗？

11. 程序在语言内部是文本还是树？
    有宏吗？卫生吗？
    有 eval 吗？eval 的输入是字符串还是语法对象？

12. 哪些是糖？
    展开之后，是否只剩下已经理解的构造？
    若是，就不要为糖单建一套心智模型。
```

十二问都答完，语法表才有用。语法表回答第 0 问：这些规则在这门语言里怎么拼写。

## 看一段陌生代码时的最短流程

```text
这段名字是绑定，还是赋值？
  赋值 → 谁还 alias 着这块数据？
  绑定 → 谁的闭包已经捕获了旧绑定？

这段调用选中的代码是哪一份？
  闭包 → 定义处已定
  方法 → 接收者运行时的类
  重载 → 编译期的参数类型，不是运行时

这个失败会在何时出现？
  类型规则看得见 → 运行前
  值的 tag 不对 → 求值到那一步
  逻辑错但类型对 → 没有任何机制会帮你

这个改动在哪根轴上？
  新操作 → 函数式分解便宜
  新变体 → 对象分解便宜
  新的可替换类型 → 先分清 subtype 和 type parameter
```

## 课程没有覆盖、但模型留了位置的东西

Wrap-up 里他明确放下的：

- Haskell 的默认惰性，以及用类型把副作用隔离出去的方式（type classes、monads）。Section 5 的 thunk 是显式版本。默认惰性会打乱本课的求值规则，所以没选它当教学语言。
- Prolog 和逻辑编程。搜索是语义的一部分，不是库。那是表上的另一行，不是函数式/对象那一行里的一格。
- 并发的具体机制。他只论证了不可变使共享更容易推理。他没有讲内存模型。
- Racket 和 Ruby 的模块系统细节。他在结束时说，若要再强调一件事，就是模块化。ML 的 signature 是课上真正讲透的边界。另外两种语言的边界值得以后自己补。

这些空位不是漏洞。模型的问法仍然适用：延迟是默认的吗？搜索是语义还是库？可变共享跨线程吗？边界藏的是类型还是仅仅是名字？

## 读完之后不应该留下的句子

- “函数式语言没有状态。”
- “动态类型就是运行时才知道类型，所以和类型推断一样。”
- “闭包就是 lambda。”
- “对象和闭包是一回事。”
- “子类就是子类型。”
- “这门课的结论是不要用 OOP。”
- “这门课的结论是 ML 比 Java 好。”

应该留下的句子：

> 不同编程语言表面上语法不同，是因为它们在一组很小的机制上做了不同的让步：何时求值，名字绑定到值还是盒子，自由变量何时查找，运行前拒绝多少程序，客户能观察什么，调用时再选一次代码还是定义时已经选好，以及你期待将来加的是操作还是变体。

车可以换。引擎的问题不会换。
